# ACG可视化面板功能测试样例集

> 日期： 2026-7-15
> **本文档用于说明如何使用acg界面中的高级功能完成整体的测试，提供了测试方法来验证引擎的功能。**
> 入口页面：`/agentos/acg`（ACG 动态群体智能引擎）
> 运维页面：`/agentos-console?runId={runId}`（定向查看运行、审核、检查点和 Trace）
> 基准节点数和边数来自当前合同样例；动态规划会根据任务意图生成差异化图，验收应同时核对结构与合同状态，不应只比较固定数量。
> 用法：把「合同文本」粘进输入框，按各样例的「操作」勾选开关，点「启动 ACG 引擎」，对照「预期观察」核对。

---

## 样例 1 · 标准合同审查（展示动态拓扑 + 低熵通信）

**操作**：选择「强制动态」，不勾选故障注入，启动。

**合同文本**：

```
甲方应在货物验收合格后30日内支付全部款项，逾期每日按合同总额万分之五支付违约金；乙方对交付成果享有知识产权，甲方仅获得使用授权；本合同任何争议提交北京仲裁委员会仲裁。
```

**预期观察**：

- **ACG 拓扑图**：当前可见图基准为 **22 节点 / 54 边**，呈现多层认知协作网络，而不是一条直线：
  - 动态规划的 7 个**步骤节点**（`contract_parse` → `clause_classify` → `risk_detect` → `legal_evidence_match` → `revision_suggest` → `human_review` → `report_generate`）构成执行主干；
  - 每个步骤挂一个**智能体节点**（执行该步的 Agent，execution 边）；
  - Memory、Evidence 只绑定真实生产与消费关系；主干步骤节点完成后显示绿色状态边框。
- **拓扑降噪**：切换「主执行链」后只显示 Step/Control 与 dependency/control_flow；返回「全图」后可逐类开关依赖、通信、执行、读写和证据边；点击节点应出现节点详情与入/出关系。
- **就绪集调度轨迹**：基准流程显示 7 个调度轮次；同一步骤重试时按 batchId 保留独立批次。
- **低熵通信指标**：节省率必须大于 0，审计账本必须显示「校验通过」；具体 Token 数随合同内容和模型输出变化，不作为固定断言。
- **数据血缘与运行交互**：基准流程显示 6 条消费/交互记录，如 `contract_parse → clause_classify`；每条只列字段名、引用、Token 和合同状态，不展示合同正文或中间输出正文。

**验证点**：这一组证明「引擎按需精准投递、不全盘倾倒」——下游只拿到它声明需要的字段。

## 样例 2 · 风险检测超时 → 自愈恢复

**操作**：粘贴文本，勾选「注入故障演示自愈」，节点选 `risk_detect`，故障类型选「模型超时」，启动。

**合同文本**：同样例 1，或：

```
本服务协议自签署之日起生效，有效期两年；甲方未按约定付款的，乙方有权暂停服务并要求赔偿损失；不可抗力导致无法履约的，双方互不担责。
```

**预期观察**：

- **任务最终状态仍为「已完成」**——故障被自动恢复，无需人工干预。
- **恢复次数**指标显示 **1**。
- **恢复轨迹 tab**：出现两条记录——「故障注入」（risk_detect，故障类型 timeout）→「检查点恢复」（策略 local_replan）。
- 拓扑图中 risk_detect 节点最终仍为完成态（重跑成功）。

**验证点**：这一组证明「接受动态注入的异常，无人工干预下自主完成闭环」——赛题鲁棒性评分项。

## 样例 3 · 启用认知规划器（展示静态优选）

**操作**：选择「模板升格」，不勾选故障注入，启动。

**合同文本**：

```
甲方应按月支付服务费，逾期承担违约责任；服务范围包括系统维护与技术支持。
```

**预期观察**：

- 任务完成；图元数据包含 `promotedFromLinear: true` 和来源工作流版本。
- 当前可见图基准为 **18 节点 / 46 边**。节点数小于强制动态路径是正常现象，但风险、证据、建议、审核要点和最终报告必须完整。
- 模板步骤 ID 为 `parse_contract`、`classify_clauses`、`risk_detect`、`legal_evidence_match`、`suggestion_generate`、`human_review`、`report_generate`；它们与动态路径的角色语义一致，但公共 ID 不混用。

**验证点**：这一组证明「静态优选」——已知任务复用高质量模板，而非每次都动态生成。

## 样例 4 · 证据检索为空 → 自愈

**操作**：勾选「注入故障演示自愈」，节点选 `legal_evidence_match`，故障类型选「证据为空」，启动。

**合同文本**：

```
保密条款：乙方应对在合作过程中知悉的甲方商业秘密承担保密义务，保密期限为合同终止后五年；违反保密义务的，应支付违约金人民币五十万元。
```

**预期观察**：

- 任务最终「已完成」，恢复次数 1。
- 恢复轨迹显示 legal_evidence_match 节点的故障注入与检查点恢复。
- 数据血缘和运行交互保留重试前后的事件，账本完整性校验仍为通过。

**验证点**：不同故障类型（证据为空，区别于样例 2 的超时）同样能自愈。

## 样例 5 · 故障节点对比（可选，展示自愈普适性）

故障节点下拉框会随规划模式切换公共 Step ID。逐一切换不同步骤，观察都能自愈：

| 规划模式          | 节点                 | 故障类型   | 预期            |
| ----------------- | -------------------- | ---------- | --------------- |
| 模板升格/智能规划 | `parse_contract`   | Agent 崩溃 | 完成，恢复 1 次 |
| 模板升格/智能规划 | `classify_clauses` | 模型超时   | 完成，恢复 1 次 |
| 强制动态          | `contract_parse`   | Agent 崩溃 | 完成，恢复 1 次 |
| 强制动态          | `clause_classify`  | 模型超时   | 完成，恢复 1 次 |
| 任意              | `report_generate`  | Agent 崩溃 | 完成，恢复 1 次 |

**验证点**：自愈机制对任意节点、任意故障类型普适。

## 样例 6 · 运行上下文、运维跳转与审计导出

**操作**：完成任一 ACG 运行后执行以下检查。

**预期观察**：

1. 页面标题区显示完整 `runId`，复制按钮可写入剪贴板。
2. 浏览器 URL 包含 `?runId=run_xxx`；刷新页面后恢复同一拓扑、指标、交互和报告。
3. 点击「运维查看」进入 `/agentos-console?runId=run_xxx`，运维页直接选中对应运行，即使该运行不在列表第一页也能读取详情。
4. 血缘面板可导出 `acg-audit-{runId}.json` 与 `.csv`。
5. 导出文件只包含运行身份、字段名、证据引用、Token、合同状态、校验值、前序哈希、事件哈希和时间戳；不得包含合同正文、Agent 输出正文或最终报告正文。
6. CSV 按实际事件包含 production、consumption、interaction 和 contract_violation 记录；无违规运行不虚构 contract_violation 行，并能由 Excel 以 UTF-8 正确打开。

**验证点**：运行结果可刷新、可定向运维、可形成脱敏审计证据包。

## 样例 7 · 复杂任务深度思考闭环

**操作**：选择「强制动态」，确认界面显示「深度思考」。首次运行不注入故障并在人工审核节点暂停；审核通过后完成报告。第二次运行可对 `risk_detect` 注入一次「模型超时」，观察重试、自愈和人审闭环。

**任务提示词**：

```text
请对一份跨境 AI 软件研发、云服务和数据处理综合合同执行完整审查。合同同时涉及里程碑付款、分阶段验收、源代码与模型成果归属、开源组件许可、第三方分包、训练数据来源、个人信息跨境传输、数据留存与删除、SLA、网络安全事件通知、违约责任上限、单方解约和跨境争议解决。

请强制生成动态 ACG，完成合同文本解析、条款分类、风险识别、证据依据匹配、修改建议、人工审核要点和最终 Markdown 报告。风险识别需要综合比较付款与验收条件、知识产权与开源义务、数据合规与安全义务、SLA 与责任限制之间的冲突；请在不违反字段依赖的前提下并行调度可就绪节点，并在分析完成后汇聚为统一结论。

上下文必须按字段契约传递：解析结果只向下游提供已声明的合同类型、主体、范围、付款、验收、知识产权和争议解决字段；风险节点只输出 risks、risk_level、risk_score；证据节点只输出 evidences、citations；建议节点只输出 revision_suggestions、manual_review_focus。不得把完整合同正文直接透传给风险、证据、建议或报告节点。

最终报告必须区分高、中、低风险，列明条款位置、冲突关系、风险原因、可能后果、可核验证据、替换条款建议、需要业务负责人确认的决策和签署前置条件。高风险结论必须进入人工审核，审核通过后才能生成最终报告。
```

**预期观察**：

- 规划 Trace 记录 `dynamic_generation`，请求的思考模式为 `deep`。
- `contract_parse`、`risk_detect`、`report_generate` 的 `_llm.thinking_mode` 为 `deep`；条款分类、证据检索、建议生成和人审门禁仍按各自确定性逻辑或检索逻辑执行。
- 拓扑出现任务起点、并行分析、汇聚、人工审核和任务终点；运行先进入 `waiting_review`，审核通过后进入 `completed`。
- 开启一次故障注入时，调度轨迹保留不同 attempt 和 batchId，恢复轨迹显示故障与检查点恢复，成功兄弟节点不被回滚。
- 当前规划粒度是“能力级”：复杂文本会增加推理内容和交互信息，但不会仅因篇幅更长就无限增加节点。当前全部法律能力命中时，可见图基准仍为 22 节点；若要按付款、知识产权、数据安全分别生成独立执行节点，需要另行实现风险子任务拆分能力。

**验证点**：这一组同时验证真实深度思考、动态规划、并行汇聚、低熵通信、人审暂停和自愈恢复，而不是只观察静态节点数量。

## 排查提示

- 若页面访问被重定向到登录页：先在浏览器登录，或确认路由守卫已放行。
- 若启动后无数据：确认后端 `/ai/core/workflows/runs/{id}/acg` 端点可达（生产经 Java 网关转发到 Python 服务）。
- 若刷新后未恢复：检查 URL 中的 `runId` 是否仍存在，以及该运行是否仍可通过状态 API 读取。
- 若运维页未定向选中：确认使用 `/agentos-console?runId={runId}`，不要只打开无查询参数的运维入口。
- 故障注入的 `max_triggers` 默认 1，即触发一次后自愈；若想看连续故障导致失败，可在 API 层把 max_triggers 调大（超过单节点自愈上限 3 次会判定失败）。

# 字段级修复与前缀复用验证（2026-10-05）

## 修改后的行为

对可定位到显式对象字段的简单合同错误，运行时从 JSON Schema 的结构化错误收集全部失败字段，生成仅允许这些字段的 `patch` 合同。模型不再重写有效正文；程序深复制并合并指定字段，再执行原有完整合同校验、证据边界归一化和产物渲染。

- 新模块：`apps/agentOS/src/adapters/model/contract_repair.py`。
- 支持缺少必填字段、字段类型、枚举及简单长度/数量/数值约束；拒绝补丁中的额外字段、缺失字段和无效替换值。
- 引用/组合 Schema、数组索引、对象整体约束、未声明属性、超过 16 个失败字段及运行时拥有的产物字段，保持既有一次完整修复路径。
- 字段补丁无效时直接报告合同违例，不追加无界重试；JSON 解析修复与合同修复仍各限一次。
- 不自动填造事实、来源或证据。模型补丁与原模型输出同属待验证数据，来源真实性不由 JSON 校验保证。

支持续接的模型运行时保留原 `system` 和原 `user` 请求，追加上一份语义结果及修复操作。最终产物归一化生成的 `artifact` / `artifacts` / `final_answer` 重复正文不再发送给修复模型。

DeepSeek / GLM 的 Schema 原先附在首条 system 消息中。字段补丁通过类型化 `prefixResponseSchema` 保留首条消息原有 Schema，在追加消息中提供当前补丁 Schema，最后一条仍为 user。原材料前缀不被新的输出 Schema 打断；原有证据及权限规则不被替换。该内部字段不作为供应商请求参数发送。

通用严格 Structured Outputs 提供商继续使用实际补丁 Schema；其供应商隐式 Schema 前缀可能变化，不能据此承诺与 DeepSeek 相同的缓存收益。不支持续接的旧运行时保持原修复方式。

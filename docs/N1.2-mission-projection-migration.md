# N1.2 Phase 1 第二批：Mission Detail / Mission History

日期：2026-10-01。接续 Identity Boundary 的三个提交，本批仅迁移 GET `/api/agentos/v2/missions/{missionId}` 与 GET `/api/agentos/v2/missions/{missionId}/runs`。

## 实际查询链与边界

`AgentOsMissionController → AgentOsClient.get → AgentOsGatewayService → Python agentos_v2.py → IdentityQueryService → MissionDetail / MissionRunHistory`。

上游继续执行 `require_mission_access`，查询来源、请求路径编码、身份头、权限、缓存、网络超时、领域对象和数据库不变。Java 从已有内部 Map 做显式投影；Mapper 不查询、不写入、不调用 Runtime。所有响应 DTO 字段均为明确标量或 typed List，不继承领域对象，不使用 Map/Object/JsonNode 或自动属性转换。

成功 body 为 MissionDetailQuery / MissionRunHistoryQuery，错误 body 为 QueryError；共同输出标记为 QueryResponse。错误 code/message/requestId 来自已有 gateway 的规范化结果，不重新判断权限或清洗错误。requestId 缺失时不新增 null 字段；`_httpStatus` 仅决定 HTTP 状态，不进入 DTO。正常上游成功和错误 HTTP 状态保持；缺失必需字段、错误类型、无效时间或版本的畸形成功响应使用已有 `AGENTOS_CONTRACT_INVALID` / 502 协议，不能伪造空的成功数据或回显原内部载荷。

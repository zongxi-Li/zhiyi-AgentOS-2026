审计日期：2026-10-01。源码基线：`eb3f3c1313e8637b7b188ccb38c2341639ce04f0`。审计开始时工作树干净。

本次仅新增本文，不修改 Java/Python、API 行为、ACG Kernel、依赖、数据库或冻结文档，不提交。结论来自静态源码，未调用在线 API、未运行服务或业务测试；字段可达性不等于已观测到生产数据泄漏。

## 1. 当前 Query 架构

业务查询：Controller → Application Service → Repository（平台持久化）或 Client Contract → Client Implementation → Python Runtime。

AgentOS 查询实际为 Controller → `AgentOsClient` → `AgentOsGatewayService` → Python `/ai/agentos/v2`。这不是遗漏 Application Service：`apps/backend/ARCHITECTURE.md:137` 明确保留纯 gateway/projection 直连契约、不套空 Service 的例外。SSE 由 `AiSseGatewayService` 唯一打开，N2 才演进事件协议。设计应继续遵守该冻结边界。

`AgentOsClient.get` 返回 `Map<String,Object>`；Gateway 成功响应解析为 Map 并添加 `_httpStatus`；`AgentOsControllerSupport.response` 只移除该标记、投影 HTTP 状态，不裁剪业务字段。错误响应另有 N1.1 映射，不能把成功响应透传与错误治理混为一谈。现有 `AgentOsMissionResponse` / `AgentOsRunResponse` 是 POST 命令响应，本次 GET 并未使用它们。

Python 已有 `project_run`、MissionListItem、MissionWorkspaceProjection 等投影，但部分仍嵌入领域模型或开放 dict。Java 类型上没有 Runtime 类，并不意味着 JSON 边界没有 Runtime 数据。

### 覆盖口径

扫描 `apps/backend/src/main/java/com/kinlin/ai/controller/` 全部 Java 文件，包括非重点 Controller。下文列出全部显式 GET，并另列 GET 通用代理。路径为 Controller mapping 拼接，不附加反向代理部署前缀。没有独立 ResourceController；资源目录由 AgentOsArtifactController 提供；Spring `Resource` 是二进制响应载体，不是资源目录领域模型。

Emotion、RoleFusion、Recommendation、Voice 等无显式 GET，不因此忽略其 POST 查询式行为：这是冻结文档 §14 的后续契约范围，不能宣称本 GET 清单涵盖所有读操作。Actuator 非此目录的 Controller，也不计入清单。

### 指定类型搜索结论

- Controller 没有直接返回 Repository 接口/Repository Row，也没有直接返回 JsonNode 或 Java ExecutionState、TaskPlan、ACGBlueprint、CompiledACGPackage、BindingManifest、ExecutionBinding、GraphPatch 类。JsonNode 命中位于 AiProxyService 的内部解析。
- Map 存在大量实际返回；Python Response DTO / DomainModel dump 经 Map 到达北向，不具有 Java 公共 Query DTO 的稳定性。
- TaskPlan 在 workspace projector 内被读取用于任务、依赖和图展示；MissionDetail 没有 TaskPlan 字段。不得声称所有 Mission GET 都返回完整 TaskPlan。
- AcgBlueprint 经 MissionDetail、execution-tree 全量序列化；graph 接口复制节点/边。CompiledACGPackage/BindingManifest 完整正文未在显式 Java GET 路径确认，但 execution-tree 有 package 身份摘要，Run 有 executionBindings，AttemptDetail 有 ExecutionBinding。
- GraphPatch 本体未在这些显式 GET 确认；graphPatchRefs/sourcePatchId 引用可见。scheduler 决策与统计可见，不能推断全部调度器内存状态可见。

## 4. Projection Boundary Design（仅设计）

目标为：内部模型或上游 wire payload → Projection Mapper → Stable Query DTO。Mapper 只白名单选取/重命名/格式化，不规划、不绑定能力、不计算调度、不装载编译包、不重新推断 Python 执行结果。授权、错误、HTTP 状态仍在原 owner；不能通过 Mapper 扩张可见数据。

建议 `com.kinlin.ai.projection` 下设 `mission/`、`run/`、`artifact/`、`observation/`（各自 dto、mapper）；另设 conversation/、role/、user/、resource/、platform/ 承接普通业务。GET 与 POST 的响应类型分离。不得为 Query DTO 引入 Python 内核 Java 镜像类。

AgentOS 可在现有直连契约之后由独立 Projection Mapper 做真实查询映射；如需要编排再设有实际职责的 Query Application Service，不能仅为了五层图添加空壳。旧 AgentOsClient Map 是传输输入，不是公共 DTO；后续可演进内部 wire DTO，但 public DTO 不得继承/嵌入 wire DTO。业务 Service 在事务内读取 Entity 并映射，保持 OSIV=false，不在 Controller 懒加载。

## 5. Architecture Rule Proposal

以下是建议，不是本次新增的守卫：

1. 覆盖 GetMapping、含 GET 的 RequestMapping、组合注解与未限制 method 的映射；按实际 HandlerMapping 清单核对。不能只 rg GetMapping。
2. 递归展开 ResponseEntity、Mono/Flux、List/Page、数组、泛型边界、DTO 字段及 getter；禁止可达 Entity/JPA proxy、Repository 模型、内部 Runtime/wire 类型。Map 包着 Entity 仍违规。
3. 稳定 JSON Query 响应不许 Object、JsonNode、Map<String,Object>、未受控 `?`、@JsonAnyGetter。binary/SSE 用精确 method+route+媒体类型例外，不按 byte[] 类型整体豁免。
4. Projection DTO 禁止引用 TaskPlan、ACGBlueprint/AcgBlueprint、CompiledACGPackage、BindingManifest、ExecutionBinding、GraphPatch、ExecutionState 等内核对象；显示图用独立 GraphNode/EdgeQuery。检查传递引用，不仅直接 import。
5. 公共 Query 结构禁止 executionState、checkpoint/checkpointId、scheduler/schedulingDecisions、executionBindings/resourceBindings、controlFrames、leaseStatuses 与 package 内部结构；检查 fixture JSON 路径及开放字段可达性。公共 canResume、状态计数、纯显示任务 id 不是 scheduler。不能对用户正文做全局词汇过滤。
6. Mapper 不依赖 Repository、WebClient、调度/编译组件，不执行写入；Service 维持现有事务与缓存 owner。Entity 禁止直接作 HTTP body，但内部业务/Repository 仍可用 Entity。
7. `/ai/**` 建立精确 allowlist/路由归属和 Projection 覆盖检查；AgentOS query 别名只能路由到同一投影边界，不能以 bytes 成功绕过字段守卫。该演进需单独兼容性变更，本文不改 proxy。
8. SSE 精确例外保留到 N2；N1.1 错误信封、六个 Controller owner、AgentOsPaths、transport ownership、OSIV=false、数据库与 CI 冻结规则继续有效。

利用现有 JUnit/Spring/Jackson 与反射/源码检查，不新增 ArchUnit 等依赖。已有 ArchitectureGuardTest 的 ACG 权威符号扫描以“Java 不实现执行语义”为目标，还允许 TaskPlan 展示概念；N1.2 应补充公共类型/JSON 边界守卫，不能用全面禁止文档词汇或内核输入字段的字符串扫描替代。

## 6. Migration 顺序

本次无迁移。未来按以下顺序提交独立、可回滚变更：

1. 固定 route+query 参数清单、真实 fixture 与前端消费者矩阵；重点核对 agentos.ts、Workbench 图/Inspector、历史重开、reviews、fragment/download、/ai 直连调用。记录每个字段的消费者、授权和兼容动作，未验证消费者前不删字段。
2. 优先 User passwordHash，再完成 Conversation/Role/Message/Feedback Entity Projection。仅 DTO 转换保持既有合法字段；敏感字段删除须明确记录契约差异，覆盖 LoginResponse/用户写响应复用风险。
3. 收敛低复杂度 Mission list、Run summary、Attachment、Review、Health/Statistics；保持分页、过滤、排序、时间与错误行为。不能因默认 summary 路径安全就漏测 summary=false。
4. 收敛 Mission detail/history 与 Run detail，再处理 graph/execution-tree/workspace。保留展示图和任务身份，但隔离 binding/checkpoint/package；跨模型字段转换必须测试 identity 与 fallback 两分支。
5. Artifact/material/fragment/output 与 Resource catalog；保持正文完整、checksum、cursor、下载 Content-Type/Content-Disposition，统一 identity/fallback 形状。
6. Trace/memory/provenance/resource usage 与 KG/DH/RAG/Profile 等动态 DTO；POST 查询式接口列为第二批，不遗漏 ARCHITECTURE §14 中 Emotion/RoleFusion。

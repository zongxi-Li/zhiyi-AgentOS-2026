# N1.2 Phase 3 Query Projection Migration

2026-10-02。基于开工令 `abb0609b`，本阶段连续实施高级观察查询、Phase 2 查询收尾与平台静态查询。Python Runtime/domain、ACG、数据库 schema、依赖、命令业务与权限代码未修改。提交均为本地提交，未 push。

## 1. 当前结果与边界

查询链路为：已有 Entity / Service result / Python wire → 纯 Projection Mapper → 显式 typed DTO → Controller JSON response → 前端表示适配。Projection 不写状态，也不参与 Planner/Scheduler/Executor。

Trace、Memory、Provenance、恢复可用性、Identity Health、outputs、resources、history-config、统计/质量/画像、知识图谱、RAG、DigitalHuman、Emotion、RoleFusion 已迁移；Recommendation 复用既有 closed DTO 并进入 strict。收尾补齐 material/attachment、告警、诊断、Token 验证与文件列表。Run/Review/Graph 等已有投影也已纳入统一 strict 查询注册。

**代码完成不代表真实业务验收完成。** 用户选择用自己的账号手动验收；执行者不索取凭据，不新建 Run。操作与回填模板见 [手动验收清单](N1.2-phase3-manual-acceptance.md)。真实 Workspace item、Artifact 成功路径、Trace/Memory/Provenance、资源分页和历史配置的页面验收仍待回填。

Phase 4 `/ai/**` 动态代理和 SSE 未实施。Python context-packs、step-executions provenance 在本仓 Java 无对应显式 handler，不新增路径将既有 404 变 200。它们是接线缺口，不是已迁移查询。

## 4. 已核对的生产合同与纠正

先前 KG 三查询“远端载荷无本仓证据”的登记不准确：`apps/agent/app/api/knowledgegraph.py` 明确 envelope，`services/knowledgegraphservice.py` 明确 entity/related/entity-extractor/reasoning/search 形状。补核后已完成迁移，不再登记为代码受阻。

EntityExtractor 的 properties 由 name 构造，build_from_documents 补 role_id；search 的 vector_results 则来自任意请求字典，不能将其整个对象作为公共 DTO。Mapper 只构造上述可证明字段，不复制未知 metadata；原检索/排序/推理调用保持。

Operational Query Mapper 没有 Service 类型依赖。对 Alert/File 的既有嵌套 Service model，由 Controller 读取 getter，将值传入 Mapper 构造 DTO；Mapper 不持有或调用 Service，也不降低原守卫。

## 5. 守卫与例外

- 全 Controller 返回闭包禁止 User/Role/Conversation/Message/UserFeedback 等实体；实体例外集合仍为空。
- 所有 projection DTO 检查 Map/Object/JsonNode/raw/wildcard、自定义动态序列化、内部执行类型和敏感字段；Mapper 无基础设施、服务调用或状态写入。
- Role 自由 JSON 只允许既有精确配置字段；outputs JSON grammar 只允许 OutputQuery / LegacyOutputItemQuery / ContentValueQuery / ContentMemberQuery。实际 owner 使用集合与登记集合比较，不再做恒真断言。
- checkpointId 仅允许 CheckpointItemQuery；其余 DTO 的同名字段由负例固定拒绝。
- 静态 GET JSON 查询统一 strict；另外精确登记三条 Binary（含 User avatar）、一条 SSE、一条 Phase 4 proxy。HTTP method/path/return type/produces 按 Spring HandlerMapping 精确核对，新增未投影 GET 或例外漂移必须失败。
- POST query：Emotion、RoleFusion、KG search/reason、RAG query、Recommendation 均 strict。创建/训练/注册/上传等命令保留既有业务回执，不用查询迁移重写。

## 6. 路由核对与明确缺口

使用当前 Controller 的 Spring MVC standalone HandlerMapping 注册核对，Controller 由 Mockito 替身提供，仅检查真实 Spring 映射，不执行业务。登记共 121 个 method/path 行，其中 68 条 GET：63 条 strict JSON 查询 + 5 条精确传输例外。User avatar 先前也受 strict 检查，但输出本身是 Binary，不能重复计作 JSON。它不是生产容器认证/权限或成功数据验收的替代物。

路由全表附在本文末尾。context-packs、step-executions provenance 没有独立 Java handler；不按前端声明虚构已可达接口。`/ai/**` 的候选由 Phase 4 单列。

剩余风险：`observation=str(exc)` 公开异常文本可能包含内部信息，本轮保留既有生成行为并登记债务；有限字段守卫不能证明所有公开字符串的语义均安全。旧 Role 配置例外与正文 grammar 也是明确合同，不能宣称全部控制面内容已经被语义净化。

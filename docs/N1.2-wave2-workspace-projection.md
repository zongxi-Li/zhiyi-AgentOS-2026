## 三、metadata 归一规则（E1 复审纠正后定案）

复审实证前端 text/list 接受数字、布尔与混合标量数组，String-only 过滤不等价。Mapper 按消费函数逐字段定规则（全部有单测锁定）：

| 键 | 规则 | 消费函数 |
|---|---|---|
| outputRef / outputSummary / runtimeStatus | String 原样；非 String 省略。前两者依据消费端 typeof-string 守卫；runtimeStatus 依据已核实的 str 生产契约，其消费者实际使用 String(value \|\| '未观测')，不能声称任意非 String 值均展示等价 | TaskEditor、RuntimeInspector、ProjectTaskExecutionInspector |
| artifactKind/artifact_kind/schema/schemaName/confidence | String 原样；有限数字→展示字符串（JS 语义：整值浮点收敛为整数，`2.0→"2"`）；布尔→`"true"/"false"`；对象/数组/null/非有限数→省略，**永不 stringify** | artifactProjection text() |
| agentName / agent | 同上但**布尔省略**（safeText 拒布尔）、数字映射 | runDocument safeText |
| evidenceRefs/evidence_refs/upstreamInputs/sourceStepIds/traceLinks/traceRefs | 数组→逐元素按标量规则映射后过滤非标量（一个坏成员不丢弃有效成员）；非数组→省略（list() 渲染空）；可产出空数组 `[]` | artifactProjection list() |
| taskPlanVersion（entry.metadata/graph/诊断 details） | null/int/整数字符串→精确 Integer；分数/溢出/对象/布尔→省略（异常指针不回显、不 502） | ProjectGraphInspector、ProjectRunSidebarView |

结构字段（entryId/kind/name/group/各 id/时间戳等）保持 QueryWire 严格规则：类型错误大声 502，不静默造值。

## 四、七类诊断映射

RUN_DELIVERABLE_MISSING(runId)、GRAPH_TASK_NOT_FOUND(acgNodeId,taskId)、TASK_PLAN_TASK_NOT_FOUND(semanticTaskKey,runId)、LEGACY_ARTIFACT_IDENTITY(count 非负 Long)、PLAN_SNAPSHOT_UNRESOLVED(runId,taskPlanVersion 按上表)、PLANNING_PROJECTION_PENDING(runtimeStatus/lifecyclePhase/errorCode，null→省略)、NO_ACTIVE_RUN(空 details，severity info)。未知 code 保留 code/message/severity，details 置空（无兜底动态容器）。前端现状：ProblemsPanel 只用 code/message、MissionWorkspaceView 只判 `PLANNING_PROJECTION_PENDING`、无组件读 details——异常 taskPlanVersion 省略对展示零影响。

## 五、系统文档重建（mission.md）与登记差异

仅 `entryId=="overview:mission.md" && kind=="virtual_document"` 不透传 Python 文本，按同一 wire 的白名单公开事实重建（章节结构与键名与 Python 版逐行同形）：`# {goal}` →（空行+description，如有）→ `## Current Run`（- Run/- Status/- Completed；无 Run 时 "No Run has been created."）→ `## Input attachments`（`- **{originalFilename}** (`{attachmentId}`) - {status}, {sizeBytes} bytes, `{sha256}``；无则 "No input attachments."）→ `## Planned steps`（entries 中 kind=="task" 行 `- **{name}** (`{semanticTaskKey}`): {objective}`，不含 Constraints 行）。

登记差异：①`## Mission metadata` 章节整体移除（四个系统键均不公开）；②计划节点 constraints JSON 行移除；③Python 的 "## Semantic tasks" 回退章节与 Planned steps 合并为同一来源（entries 的 task 行），**无 Run 时重建文档无步骤章节**（上游会列全部 SemanticTask）；④计划节点缺对应任务时重建文本不生成假任务（缺净），全缺则省略章节；⑤Python mission.metadata 为空的占位行语义由章节整体省略承接。其余正文逐字节透传（有单测）。

## 六、登记 wire 变更（全为登记内收紧或展示等价归一）

1. **null→缺席归一**：模型字段与 metadata 内 null 值不再出现在 wire（NON_NULL）。所有已核读取点（`?.`/`||`/`??`/`== null`/typeof 守卫）行为等价；PLANNING_PROJECTION_PENDING.errorCode=null、TASK.parentTaskId=null 等从 `"key": null` 变为缺席。
2. **metadata 白名单化删除键**：identityVersion、metadata 级 logicalRole（entry.logicalRole 原位保留）、sourceAttachmentIds、parentTaskId、projection（run-history 标记）。
3. **activeGraph 白名单化**：删除 blueprintId 与 blueprint 簿记键、node/edge 执行规格（现状全透传到前端）。
4. **候选键标量归一**：数字/布尔→展示字符串（非 String-only 过滤，E1 复审纠正）；对象永不 stringify。
5. 未知诊断 code 的 details 置空（当前无未知 code 实例）。

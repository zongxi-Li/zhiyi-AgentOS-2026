## 一、activeGraph 同构性结论：不同构，需独立 DTO

**workspace activeGraph 的构造**（`runtime/v2/workspace.py#_graph_snapshot`）：

```python
{**dict(blueprint.graph), "blueprintId": ..., "graphId": ..., "missionId": ..., "graphVersion": run.graph_version, "taskPlanVersion": plan.plan_version}
```

**实测 blueprint.graph 顶层键集**（122/122 一致）：complexityLevel、createdAt、edges、graphId、metadata、missionId、nodes、objective、priority、updatedAt、version。信封覆盖后 graphId/missionId 与 graph 内同名键重复（信封值胜出）。

**与 GET `/runs/{id}/graph` 的 wire 对比**：/graph = {runId, blueprintId, graphId, graphVersion, nodes, edges, taskBindings, completedStepIds, activeStepIds, skippedStepIds, graphPatchRefs, resourceBindings, source}——多出运行域展示状态与内部引用（graphPatchRefs/resourceBindings 属禁投影键）；activeGraph 多出 taskPlanVersion 而无 runId/step 状态。**两者不同构**。

**实施落点**：
- 不复用 `GraphQuery`（其 runId 与三个 step-id 列表在 activeGraph 侧不存在，强行复用会伪造运行域事实）。
- 新建 `WorkspaceGraphQuery(graphId, graphVersion, missionId, taskPlanVersion, objective, complexityLevel, List<GraphNodeQuery> nodes, List<GraphEdgeQuery> edges)`；节点/边逐项复用既有 `GraphNodeQuery`（nodeId/nodeType/name/description/goal/agentName/capability/controlType/display）与 `GraphEdgeQuery`（edgeId/sourceId/targetId/edgeType/activation/display），display 从 node/edge 的 metadata 子对象按 `GraphProjectionMapper.display` 同一规则提升——与 TS `AcgNode/AcgEdge/GraphProjection` 声明逐键对齐（前端实读形状已核实）。
- **真实 nodes 键集含大量执行规格**（实测出现：inputSpec/outputSpec/schema、loopSpec/consensusSpec/parallelSpec/conditionSpec/joinNodeId/controlSpec、memoryIds/skillIds/evidenceIds、retryLimit/timeout/maxConcurrency/modelName/priority、metadata 等）——现状 Map 透传把这些全部带到了前端。白名单化后仅保留上述 9 键，属登记内的行为收紧，删除依据 = 计划"不嵌原 policy/config/执行条件"。

## 三、mission.md 泄漏实测与公开内容方案（定案）

**泄漏点实测**（`workspace.py#_mission_document`）：
1. `## Mission metadata` 章节把 `mission.metadata` 全量 JSON dump 进正文。实测 157/157 mission 的 metadata 键集为：`identityGeneration`、`principalSource`、`runtimeDomain`、`runtimeIntent`——系统写入的身份溯源/域意图标记（非用户自由输入），属内部控制面事实，mission 列表/详情批已确立 metadata 不公开。
2. `## Planned steps` 每节点追加 `Constraints:` 行 = `plan.nodes[].constraints` 全量 JSON（执行约束规格）。

**非泄漏章节**（字段均已在其他端点公开）：标题/描述、Current Run（runId/status/completedAt）、Input attachments（originalFilename/attachmentId/status/sizeBytes/sha256——与 inputAttachments 端点同白名单）、Semantic tasks 回退（title/key/objective）。

**消费者核实**：MissionEditor.vue 渲染 `entry.content` 为 markdown（fallback `# {mission.goal}`）；RunProgressEditor.vue 仅作导航锚点；TaskArtifactDocument.vue 自建 fallback，不读该 content。该条目是唯一 `VIRTUAL_DOCUMENT`（entryId 固定 `overview:mission.md`）。

**方案（采用预审方向 a）**：Java workspace Mapper 对 entryId=="overview:mission.md" 的条目**不透传 Python 文本**，基于同一 workspace wire 的白名单公开事实重建同构 markdown（章节结构、标题与键名与 Python 版本一致）：

```
# {goal}
（空行 + description，如有）
## Current Run            ← activeRun?.runId/status/completedAt（无 Run 时 "No Run has been created."）
## Input attachments      ← inputAttachments[]：**{originalFilename}** (`{attachmentId}`) - {status}, {sizeBytes} bytes, `{sha256}`
## Planned steps          ← entries[] kind=="task"：- **{name}** (`{semanticTaskKey}`): {objective}（不含 Constraints 行）
```

- metadata 章节整体移除（四个键均不公开，无"公开摘要"可写；Python 侧 `mission.metadata` 为空时的占位行语义由"章节整体省略"承接）。
- 语义任务回退分支（无 plan 时）与 Planned steps 合并为同一来源（entries 的 task 行已覆盖两种上游形态），差异登记于迁移记录。
- **禁止**对任何其他条目的 content 做删改（用户/Artifact 正文原样 String 透传）；不修改 Python 生成业务。
- 备选方案（b，正则删改或删除该条目）否决：正则删改被预审禁止；删条目破坏 MissionEditor 渲染与 RunProgressEditor 导航契约。

## 五、envelope 其余部分设计要点（实施批逐键落表）

- **mission**：WorkspaceMissionQuery{missionId, goal, description, status, createdAt, updatedAt}；userId/metadata 删（详情/列表先例）。
- **activeRun/runs**：WorkspaceRunSummary 已是干净投影（runId/status/parentRunId/sourceRunId/createdAt/completedAt/isActive），逐键映射保留。
- **entries**：显式字段照单；不要把 outputRef/outputSummary 直接提升后删除原路径。TaskEditor 读取 `entry.metadata.outputRef`，ProjectTaskExecutionInspector 读取 `metadata.runtimeStatus`，ProjectGraphInspector/ProjectRunSidebarView 读取 `metadata.taskPlanVersion`。优先保留 JSON 路径 `metadata`，将其类型改为显式字段的 WorkspaceEntryMetadataQuery；这是 typed DTO，不是自由 JSON 例外。artifactProjection.ts 还读取 artifactKind/artifact_kind/schema/schemaName、evidenceRefs/evidence_refs、upstreamInputs/sourceStepIds、traceLinks/traceRefs、confidence 及 outputRef。需逐一追生产者、确定公共性和 scalar/list 类型，只保留有证据的公共字段，不能把未知对象转成 String 或开放 JSON。identityVersion 等内部版本仍删除；是否删除其他键须有完整消费依据。content 原样保留，只有系统生成 overview 条目重建；graphNodes 9 键照单。
- **diagnostics**：{code, message, severity, details}，severity 为 info|warning。details 不止 deferred 分支：RUN_DELIVERABLE_MISSING 使用 runId，GRAPH_TASK_NOT_FOUND 使用 acgNodeId/taskId，TASK_PLAN_TASK_NOT_FOUND 使用 semanticTaskKey/runId，LEGACY_ARTIFACT_IDENTITY 使用 count，PLAN_SNAPSHOT_UNRESOLVED 使用 runId/taskPlanVersion，PLANNING_PROJECTION_PENDING 使用 runtimeStatus/lifecyclePhase/errorCode。逐类用显式 typed details 字段承载；公开标识/count 保留，不暴露内部 plan 内容。taskPlanVersion 来源于 run.metadata，异常类型须沿既有坏载荷规则处理，不能包为 Object。
- **错误与状态规则**：沿用 projectedResponse/QueryError；补非 2xx 与坏成功载荷契约测试。
- **前提状态**：图不同构、生成正文来源与附件字段已有依据；Workspace 元数据消费追踪和 diagnostics 完整白名单尚需闭合。不能直接宣布 E 全部具备实施条件。完成上述核对和契约方案后再实现，不提前修改 Python 或前端流程。

模型 descriptor 的自由键保留入口已由 contracts/artifacts.py 的 canonicalize_artifact_identity 与 node_runner 定位；Workspace 仅转发，并不会保证上述候选键的值类型。当前 identity 库样本没有这些值，不得据此声称类型契约已经被证实。

### 混合类型兼容门

artifactProjection.text/list 接受 string、number、boolean，而 DTO 必须具有稳定的显式类型。执行前对候选字段做只读类型核对，只汇总键/类型/数量，不打印正文、身份或敏感值。String/List<String> 是设计候选，不是未经核对就执行的截断规则。

若现有公开值确有混合类型，提供最小脱敏复现，并选择可验证的显式输出规则：需要 scalar 到展示字符串的变化时，逐项登记 old type → new type → consumer，并用现有前端读取函数验证展示等价；禁止把对象或任意 JSON stringify 为 String。不能直接转 null、删掉类别/引用、静默造值，也不能添加 Map/Object/JsonNode 或复制 Role 可扩展 JSON 例外。无法证明兼容时只暂停受影响字段的迁移决策，继续完成其他领域的设计和测试准备。

## 九、字段级修正：diagnostics.details

保留 JSON 路径 details。建议一个显式 WorkspaceDiagnosticDetailsQuery，字段均可选，按 code 白名单构造；不得将源 details 整体复制。可用 @JsonInclude(NON_NULL) 保持旧 exclude_none 的缺字段行为，不额外补齐原本不存在的事实。

| code | 当前生产者 | 允许字段及类型 |
|---|---|---|
| RUN_DELIVERABLE_MISSING | workspace.py 运行完成却没有交付物 | runId: String |
| GRAPH_TASK_NOT_FOUND | workspace.py 图绑定引用缺失任务 | acgNodeId: String、taskId: String |
| TASK_PLAN_TASK_NOT_FOUND | workspace.py 计划节点无法找到任务 | semanticTaskKey: String、runId: String |
| LEGACY_ARTIFACT_IDENTITY | workspace.py legacy manifest 回退 | count: 非负 Long |
| PLAN_SNAPSHOT_UNRESOLVED | workspace.py 历史 plan 指针不可解析 | runId: String；taskPlanVersion 原 metadata 值无固定类型，见下文 |
| PLANNING_PROJECTION_PENDING | agentos_v2.py deferred 规划回退 | runtimeStatus/lifecyclePhase/errorCode: 可选 String |

PLAN_SNAPSHOT_UNRESOLVED 的 taskPlanVersion 不能作为必有 Integer：Python 会在其类型异常时生成本诊断。数字合法时精确映射公开版本号；异常类型的公共展示策略必须与该诊断场景单独定案，不能因计划指针不可解析就把整个可用 Workspace 判为伪造成功，也不能输出原始对象。迁移时覆盖 null、数字、数字字符串与对象四种输入，记录字段输出与 HTTP 行为。

未知 code 保留公开 code/message/severity，details 只按已核定规则输出，禁止兜底动态容器。所有现有生产 code 都须覆盖；新增 code 的测试应要求审查其 details 字段，不必将整个 Workspace 拒收为 502。message 不从其他内部对象拼装。

## 十一、E1 交付复审补充

E1 `88184d39` 已新增 typed DTO 与 fixture，未改变 Controller/API，也未提前登记 strict handler。NO_ACTIVE_RUN 已补入诊断，共七类。PLAN_SNAPSHOT_UNRESOLVED 的可选 Integer 决策与 null 归一登记方向可接受，真实映射行为需 E2 测试证明。

需纠正“无 Python 生产者，因此类型不符省略等价”的论证：canonicalize_artifact_identity 保留模型 descriptor 的任意 metadata，Workspace ARTIFACT entry 再完整转发。当前库没有候选值，只能说明当前样本为空，不能消除这个生产入口。artifactProjection.text 接受数字/布尔，list 接受混合标量数组；例如 confidence=0.87、evidenceRefs=["ref-a",42,true,{"internal":"SECRET"}]，原 UI 分别展示 0.87 与 ref-a/42/true，而只认 String/List<String> 的整体过滤会丢失公开展示。

E2 必须针对这些复现值固定输出规则。可以在明确登记 scalar/list 到展示字符串的 wire 类型归一后采用现有 String/List<String> DTO，但须调用现有消费者验证前后展示等价，不能简单忽略数字/布尔或因数组含一个对象就丢弃全部合法成员。字段之间不得共用未经核对的规则，例如 runDocument 的 agentName/agent 读取与 artifactProjection.text 不应被假定完全相同。

对象、执行 schema、原始约束或其他内部上下文仍不得 stringify；数字非有限值不得转成 Infinity/NaN 字符串。若规范化改变现有可见内容，应提供脱敏复现并先解决该字段兼容问题，不能用“样本零值”作豁免。

# N1.2 Phase 3 手动验收清单

2026-10-02。执行者已完成查询投影迁移、自动测试与部署核对；本清单的真实成功路径由项目负责人使用自己的账号完成。测试通过不代替本清单验收。无需提供账号、密码、Token 或正文给执行者。

## 1. 准备

1. 打开 `http://127.0.0.1:9050`，登录你自己的账号，按 Ctrl+F5 强制刷新。
2. 选择名下已有的项目和历史运行，最好有图节点、产物、Trace 和资源调用记录；不要新建项目或 Run。
3. 按 F12，进入 Network，选择 Fetch/XHR，勾选 Preserve log，然后清空旧请求。只观察请求状态和查询响应结构，不复制 Authorization。
4. 全程只读取。不点击“再次运行”“从失败处继续”、停止、审核提交、重试、上传、保存配置或资源注册。
5. 如果缺少对应数据，填写“未执行：无既有数据”，不要把空态记为该成功路径通过。

## 4. 错误与隔离（可选，有第二个既有账号时）

最方便的方法是在 Network 中选中上述 **GET** 请求，右键 Edit and Resend（浏览器支持时）；保留参数结构，只修改 path/query。不要分享完整请求或 Token。Chrome 没有该入口时，可使用 Sources → Snippets：下方脚本只读取当前登录 Token，在请求中使用，不输出它。

先在 Network 抄下一个自己可访问的 runId，填入变量。脚本不输出正文，仅输出状态、公开错误码和顶层键名。

```javascript
(async () => {
  const runId = '替换为你自己的已有runId';
  const token = localStorage.getItem('token');
  if (!token) throw new Error('请先登录；不要手动粘贴 Token');
  const root = '/api/agentos/v2/runs/' + encodeURIComponent(runId);
  const paths = [
    root + '/trace',
    root + '/trace?view=workspace',
    root + '/trace?view=invalid-view',
    root + '/resource-usage/calls?cursor=invalid-cursor',
    '/api/agentos/v2/runs/n12-acceptance-nonexistent/trace'
  ];
  for (const path of paths) {
    const response = await fetch(path, { headers: { Authorization: 'Bearer ' + token } });
    const body = await response.json().catch(() => null);
    console.log({ path, status: response.status,
      code: body && typeof body.code === 'string' ? body.code : null,
      keys: body && typeof body === 'object' ? Object.keys(body) : [] });
  }
})();
```

预期：两个有效 Trace 查询为 200；非法 view 与非法 cursor 为既有 422；不存在的 Run 为 404，错误信封不附带内部模型。若本机 Token 存储方式已更改，脚本直接停止；通过 Network 验证即可。

跨账号检查：若你拥有第二个既有账号，先保留账号 A 的一个 Run ID，再退出并登录 B。只读访问该 Run 的 Trace/Workspace 等端点应不可见（既有 404）；不要为本次验收创建账号或修改数据归属。没有第二账号则填写未执行。

## 4. 已作出的关键裁决

### 4.1 Trace 公开详情

采用 typed 字段 + `List<TracePublicDetailQuery>`，详情至少 key/value/kind，**有限公共键白名单，不是任意 extras**。规则按事件家族与嵌套路径登记，未知键直接省略，已知键错型不得原对象降级回显。对象必须先投影公共子字段，再格式化展示。条数/文本预算仅约束展示详情，不截断公开用户正文、事件列表或计数。

未知/历史 eventType 不失败：保留公共事件骨架、安全既有摘要，payload 仅保留该类型已批准的公共字段。没有家族依据时不能套“所有已知字段”兜底任意新 payload。eventCount 原样为全量；events 保持上游排序/视图过滤，不重排、不要求与 eventCount 相等。

`[redacted]`/`[truncated]` 是上游 unavailable 状态，数字不得造 0。可选观察字段局部省略或映射显式可用性；结构坏载荷与可用性问题分开，前者走既有 contract-invalid，后者不毁整个 Trace。按实际消费函数逐字段决定 String/Long/有限比例/List/封闭对象。

删除 promptAudit/profile/selectedBindings/pendingMemory 内部策略、checkpoint 内部引用、patchId/patchRef、binding/runtime state 等，不因为 generic 详情当前显示就继续暴露。topologyAudit 只保留可证明公开的计数/诊断，不包装整个内部结构。字段删除影响需登记，必要时显示既有公共事件类型/摘要，不生成假的状态。

### 4.2 字符串与用户正文

保留既有公开 observation/message/comment/reason/输出摘要；普通文本出现 binding/checkpoint 等词不能作为删除理由。`str(exc)` 兼容风险按具体生产者登记，当前不修改 Python 异常生成，不声称截断/正则已解决所有文本泄漏。不得新增对内部对象 stringify 后放进“安全字符串”的通道。

默认 Trace 可含公开模型 delta，workspace 视图上游已过滤；保留各自既有语义，不在 Java 统一删除正文。对文本来源缺乏证据的原始对象不推断成公开正文。

### 4.3 outputs 独立内容合同（批准实施）

禁止复用 Trace 的有界详情承载完整产物。固定公共字段能表达则用固定 DTO；动态用户产物可使用 **仅限输出 content 的显式 typed JSON value grammar**：kind + String/Boolean/精确 Number scalar，List<Value>，List<ContentMemberQuery(name, value)>。必要时采用不同 typed variant，允许自引用数据结构，字段不得为 Map/Object/JsonNode。不是原 JSON String，不继承原模型。

此 grammar 仅表达用户产物正文，不能用于 Trace/Memory/Provenance/health/history-config 或任何控制元数据；不扩散 Role 既有自由 JSON 例外。守卫精确限定允许使用它的 DTO/字段/handler，并验证不会嵌入控制对象。闭包扫描处理递归要有 visited 集合，不能因此跳过其他类型检查。

Mapper 不读取 output_spec/数据库，不调用 Runtime；来源核对在实施审计完成，输入只取现有 wire 的公开 content 及固定公开产物元数据。核对全部写入路径与 legacy，不再假设 output_spec 恒有；不能按关键字删合法正文。无法分辨的内部附带数据如实局部上报。

前端在 API/表示入口解码回既有消费结构，完整保留报告、risks/evidences、动态 capability 路径、GenericArtifactPanel JSON 展示。保持字段名/嵌套/数组顺序/正文长度/布尔/null/数字；无 24 项、2000 字符或深度 4 的内容截断。避免 prototype pollution，不把传输 kind/member 当业务字段。后台 DTO 与前端适配须同一兼容提交，不部署中间不兼容状态。

### 4.4 Provenance 与平台动态属性

fieldsByProducer 等有真实消费者的动态关联键用 typed 关联行（producerId、fields 等）表达，前端入口做必要表示适配。公开语义优先复用，不共享原始 Map。平台检索 sources/knowledge nodes/role fusion 等按实际生产合同和消费声明映射，不能把“动态”当成批准任意 JSON 的理由。只有 outputs 用户正文获上述 grammar 批准。

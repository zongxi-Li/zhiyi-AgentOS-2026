# 异构执行与资源抽象：阶段 1—2 整理审查

关联：[阶段 1 实施记录](异构执行与资源抽象-阶段1实施记录-2026-11-15.md)、[阶段 2 实施记录](异构执行与资源抽象-阶段2实施记录-2026-11-15.md)。

## 1. 审查结论

前两个阶段存在局部实现冗余，主要来自多实例登记接入后仍保留的旧索引，以及不同入口复制的校验和容量换算。本轮整理 4 个生产文件，保持当前执行语义与阶段边界。

本次审查针对前两个阶段的相关改动；工作区既有规划、展示和前端等修改不属于本轮整理范围。

## 2. 已整理的内容

| 位置 | 原有冗余 | 整理方式 |
| --- | --- | --- |
| [AgentRegistry](../../apps/agentOS/service/agents/registry.py) | `_agents` 与 `_defaults`、`_registrations` 同时维护默认实现，替换和注销均要同步多份状态 | 移除 `_agents`；默认视图从实例索引与当前注册记录派生，保留登记顺序及删除默认实例后不自动提升其他实例的行为 |
| [Registry](../../apps/agentOS/service/agents/registry.py) / [Pool](../../apps/agentOS/service/agents/pool.py) | Pool 逐次遍历所有注册记录查 ref，Registry 的解析、注销又分别实现当前 ref 检查 | 统一为 `get_registration()`，按 instanceId 直接查找并核对完整 ref 和 scope；Pool 删除 `_current()`，解析与注销复用该入口 |
| [RuntimeStore](../../apps/agentOS/src/components/resource/infrastructure/runtime_store.py) | 内存、SQLite 的 `update_capacity()` 与 `update_profile()` 共四处复制已占槽位、可用槽位及利用率公式 | 提取内部纯函数 `_resize_snapshot()`；各存储原有锁、事务、CAS 与快照版本递增留在原入口 |
| [AgentInvocationAdapter](../../apps/agentOS/src/adapters/agent_invocation.py) | 精确 ref 与旧 ID 两条分支各自重复实现对象身份检查 | 解析后统一核对原选中对象；同时简化父子异常重复捕获，保留相同错误码和可信 not-invoked 证明 |

一并移除了 generation CAS 中已被数值不相等条件覆盖的重复分支；当前代次、删除后 ABA 与 generation 预留规则不变。

`get_registration()` 只读取当前登记事实，不进行调用准入、不把逻辑 Agent 标记为已绑定。`resolve_registration()` 继续额外核对启用、声明快照和执行资格。禁用实例仍可被控制面观察，读取元数据也不会提前封闭启动来源 stamping。

Pool 的精确 ref 查询不再逐次全表遍历；这不代表整个 Pool 列表查询的所有关联计算均已变成常数时间，也未新增反向索引或状态缓存。

## 3. 保留的结构与检查

以下内容承担不同职责，本轮继续保留：

- `AgentProfile` 是兼容的可变配置入口，`AgentDefinition` 是已发布的不可变声明快照。合并两者会丢失对未登记配置变化的检测。
- Registry 的逻辑禁用与 ResourcePlane 的实例 enabled/draining 分别表达逻辑准入和实例管理事实，不能相互替代。
- READY 选择和真实调用前的校验发生在不同时点；后者用于拒绝选择后发生的禁用、替换或声明变化。
- 聚合 embedded Runtime 仍承载现有执行租约，AGENT_INSTANCE 目前承载实例事实。阶段 3 完成具体实例分配、宿主容量协调和恢复前，两者仍需共存。
- `ModelCallGateRegistry` 共享路由门控，独立包装器保存各次调用状态。缓存整个包装器会重新引入 Attempt/流式状态串扰。
- Pool 与 ResourcePlane 对注册身份、宿主和存储版本的检查分别保护控制入口与资源存储边界；没有为了减少重复行而放宽这些检查。

没有引入新的调度器、busy 账本、共享包装器缓存或执行协议，也没有提前启用 AGENT_INSTANCE 调度。

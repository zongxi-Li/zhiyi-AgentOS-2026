# Chat 流式中断修复记录（2026-10-28）

状态：代码修复及相关回归完成，待用户人工验收。用户明确自行验收后，不再继续浏览器演练。未提交、推送或发布。

## 问题与证据

用户截图中的两次回复均只显示思考和“流式响应意外结束”。原环境日志显示 DeepSeek 请求成功后，Java `SessionRecheckGate` 报 `SSE session observation lease expired before event delivery`，随即取消上游生成。

独立测试账号复现：浏览器流在约 1165ms 收到 `auth.invalidated`；对应网关首查成功的墙上时间为 10:39:04.091，拒绝交付为 10:39:13.596。浏览器实际经过时间远小于网关墙上时间差。同一容器另有 `Started KinlinAiApplication in -5.733 seconds`。这证明墙上时钟发生跳变，不能用于衡量进程内租约的经过时间。

## 修复

- 网关租约起点、续期与交付检查统一使用 `System.nanoTime()`；比较采用差值，处理计数器回绕。登录会话的绝对到期时间仍由现有 IAM 权威判断。保持 3 秒复核、1 秒查询超时、5 秒租约和失败即停止交付的约束。
- Chat 按完整 SSE 帧解析，保留 `event:` 字段，识别网关会话失效和错误；支持分块、CRLF 和结尾残帧。
- 正常完成、错误、意外断流和主动停止均结束运行展示；有部分正文时保留正文并另外显示原因，错误后的 `done` 不再变成成功。
- 历史通过既有 `executionSummary` 保存完成、失败、取消状态，不新增公开 DTO 字段。取消清理异步保存并防止同一次流重复保存；不保存原始思考内容或 Provider 错误负载。
- 失败回复不再进入后续模型上下文；通过 `X-Chat-Context-Id` 提前同步会话，失败后重试仍归属原对话。
- 展示已选择的模型名称，实际用量事件可更新为有效模型；Chat 使用独立输入提示。思考耗时也使用单调计时。

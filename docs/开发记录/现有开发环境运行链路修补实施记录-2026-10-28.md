## 1. 实际修补

- Compose 显式传入语义收敛、C2 Authority、Dispatch、Legacy 四个开关。通用默认 false；现有 `.env.windows` 仅将前三项改为 true，Legacy 保持 false，未改部署 ID、端口或 Secret。
- Windows preflight 校验合并后的实际布尔值及开关依赖，提前拒绝不合法组合。
- 新增 `scripts/prepare_agentos_runtime.py`：默认检查真实数据卷，`--apply` 调用既有 C2→Dispatch 升级器，再验证；`--initialize-empty` 必须显式给出且与 apply 配合。维护不导入 app.main，不构建 Runtime。
- 两种 AI Dockerfile 都包含维护入口。维护写入使用现有 Runtime 的同一 OS 单例锁实现；被运行实例占锁时拒绝，不删除或重建数据库。
- `up.ps1 -ApplyAgentOSSchema` 先停止 AI，再运行一次性维护容器；升级失败不执行后续 up。普通启动只检查，Runtime 仍保持 verify-only。Java V11 沿用 Flyway。
- Python 测试取消对整个 `.tmp-tests` 的过期扫描，仅清理本次创建的目录；补齐临时数据库环境路径隔离。
- 浏览器实测发现观察器在临时网关故障后停止轮询，同一 Run 刷新又被订阅去重跳过。新增失败回归，允许对已结束且不可用的观察结果重试，保留正在进行的读取和已确认终态的原有行为。
- 为 SSE 会话门补充无凭据的终止原因日志，区分租期过期、会话无效和查询异常类型。未放宽 3s/1s/5s 会话合同。

公开业务 API、DTO、Permit、Dispatch、审核策略及执行状态机没有改动。未新增 Scheduler 或恢复引擎。

## 2. 现有库的兼容性问题与限定修复

首次只读维护检查拒绝两个历史布局，原始回执保留：

1. Workflow 缺 `mission_revision_decisions`。现有语义初始化器支持增量创建，但 C2 检查器把它一律作为损坏。仅允许在**尚未安装任何 C2 表**、其余前置结构均通过时，复用原初始化器添加此空表；C2 安装后再丢失该表仍拒绝，不能补造历史事实。
2. Identity 的官方旧版迁移通过 ADD COLUMN 将 `semantic_key` 追加到表末尾；检查器却只接受新建库的列位置。现在在临时参考库重放现有官方迁移，只额外接受它产生的精确表定义，未改写现有 Identity 文件，也未放宽任意 SQL/约束。

永久回归先取得两项失败，再验证升级成功、Identity 文件不重写，以及已安装 C2 后丢失前置表仍然拒绝。原有 Schema/历史依赖完整性测试同时复跑。

按用户明确要求没有增加备份步骤；未删除卷、清库、重建数据库或初始化现有非空库。升级前后、创建演练任务之前，实际记录计数完全一致：

## 4. 身份与 SSE 验证

- 单独浏览器标签页使用正常会话建立短任务的观察连接，保持约 131 秒；在另一页确认登出后，约 **388ms** 收到 auth.invalidated 并结束。随后原凭据普通请求和新 SSE 均 401。
- 另一个正常注册用户读取主 Run、final 下载和 SSE 均 404；匿名读取 401。检查后撤销第二用户的演练会话。
- 主任务最终批准时，真实 SSE HTTP 200 收到 run.completed；实时模型阶段也收到节点/模型活动及连续序号数据。

必须保留的异常：前两条模型阶段流在会话仍可通过 HTTP 认证时提前收到 auth.invalidated；未因此取消业务 Run。新增诊断日志后，后续长时间空闲连接、显式撤销及终态事件正常，但**尚未定位前两次提前终止的具体触发原因**。不将其称为“所有模型输出持续推送已稳定通过”，不修改超时或租期掩盖异常。

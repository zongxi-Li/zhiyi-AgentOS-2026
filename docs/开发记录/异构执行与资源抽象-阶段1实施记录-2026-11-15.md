## 2. 生产改动

### 2.1 模型包装器独立，调用门控按路由共享

修改 `apps/agentOS/src/adapters/guarded_model.py` 与 `src/runtime/acg_execution.py`。

- `ACGExecutionService` 持有自己的 `ModelCallGateRegistry`，统一服务 `_build_runner` 和 READY 阶段的包装器工厂。
- 每次工厂调用返回独立的 `GuardedModelRuntime`，不共享 `last_attempt_id` 等调用状态。
- 注册表路由按“注册表对象、规范化 provider、model”共享 gate：provider 去首尾空白并转小写，model 仅去首尾空白。版本、流式标记、Run、Step、Attempt 均不会拆出新的门控容量。
- 资源模型路由按“ResourcePlane 对象、endpointId”共享 gate。不同端点维持各自的本地调用上限。
- 同一路由的冲突策略明确拒绝，不通过新增缓存键绕开已有上限。缓存查找与创建在同一个同步锁内完成。
- gate 在首次异步使用时建立 Semaphore/Lock。同一服务顺序用于多个 `asyncio.run()` 时，旧 loop 关闭后可以重新建立原语；两个尚未关闭的 loop 不能共享使用同一 gate，会明确拒绝。
- 起始间隔使用 monotonic 时钟保留。流消费主动关闭时，先关闭底层 iterator，再释放共享槽位。

这修复了 READY 重建包装器后并发上限失效的问题，同时避免通过缓存整个包装器引入流式 Attempt 身份串扰。

共享范围是同一个执行服务内的同一路由。这不是分布式 quota，也没有合并默认 fallback、注册表路由、资源端点路由之间的预算。它限制受保护的顶层调用；内部供应商重路由、修复请求的逐次速率与远端取消确认不在此处承诺。

### 2.2 名称与角色提示不能绕过 Agent 准入

修改以下现有入口：

- `service/agents/registry.py`：名称与能力解析统一检查 enabled 和所请求能力；`resolve_by_id()` 拒绝 disabled Agent。保持原领域回退、登记顺序与 scope 约束。
- `src/runtime/acg_execution.py`：READY 名称/角色解析带入 Step 的 capability；历史 ID 回退同样核对所请求能力。
- `src/components/planner/cognitive_router.py`：排名前排除 disabled Agent；显式空候选列表保持为空，不再回退到全注册表。其余语义排名规则保持原样。
- `src/components/resource/runtime/embedded_runtime.py`：disabled Agent 不贡献能力和容量；无可用 Agent 时聚合 Runtime 不再作为启用候选。

兼容边界：

1. 没有请求 capability 时，仍可按名称调用 capabilities 为空的启用 Agent。
2. 请求了 capability 时，空列表不是通配能力，必须显式声明。
3. 禁用阻止后续准入；不取消已经进入 `agent.run()` 的调用。
4. 已选中但尚未调用的 Agent 被禁用后，现有 Adapter 的最终 ID 解析会拒绝，并保留可信的 not-invoked 证明。
5. 本阶段不承诺禁用与并发认领的原子截止，也不解决同 ID 热注册后的实现漂移。

## 3. 回归基线修复

### 3.1 Permit 数据库副本隔离事件总线

建设前的 5 项 Permit 失败均随 fixture 隔离修复而消失。数据库副本保留同一 Run ID，但路径不同；共用进程级 Broker 会在被测权限断言之前触发正确的 Store ownership 拒绝。

- 新增测试 helper `tests/components/planner/_runtime_events.py`。
- 种子构建与各数据库副本分别使用独立的 Broker。
- 明确替换 live_events、node_runner、agent_tools、model.native 的既有模块别名，确保测试 hook 与实际发布者一致。
- fixture 退出前 flush；复制数据库继续使用 SQLite backup，不复制未合并 WAL 文件。
- 审计测试改为读取当前 Broker，移除三处宽泛 `except ValueError`。只有真实更改 durable activation head 的用例按精确错误消息捕获。
- 增加实际到达 `node.started` 的断言，transport retry 必须观测到真实的 B/B 调用。
- 新增直接测试：同 Broker、同 Run、不同 Store 路径拒绝；同路径重开允许；独立 Broker 可以承载副本。

生产 Broker ownership 与 Permit 检查均未放宽。这个 helper 用于顺序执行的测试生命周期，不提供同一进程内两个并行 monkeypatch context 的隔离。

### 3.2 架构门禁恢复实际覆盖

修改 `tests/architecture/test_capability_upgrade_gates.py`：

- Scheduler 检查指向 `components/resource/scheduler` 并断言来源非空；遗留目录如果重新出现 Python 源码也会被检查。
- Resource 禁止的既定 facade 文件名改为递归检查，避免只扫描根层。
- 退役 `apps/local-runtime` 只容忍明确的 pycache/pytest cache 生成物，新增源码、配置等仍然拒绝。
- `subprocess` 仅精确放行现有 Marketplace 安装器与内置包服务模板，检查 argv、shell、调用位置、间接调用与额外参数。
- 安装器只允许既有两个方法内的两个 `Popen`。包服务模板只允许 `serve.Handler.do_POST` 启动固定 `agentos_local_tools.worker`、timeout=30、shell=False，且不能引入平台执行权威依赖。
- 新增嵌套 facade、空扫描、源码回流、别名、间接启动、参数覆盖和 worker 模块篡改等对抗测试。

补充建设前审查遗漏：`components/marketplace/builtins/server.py` 也有既有 subprocess 调用。`builtins/catalog.py` 将该模板打包为 ZIP 中的 `agentos_local_tools/server.py`，由安装后的工具服务使用；本轮没有新增这种执行路径，也未将整个 Marketplace 目录加入豁免。

这些是架构覆盖检查，不能单独作为完整授权或隔离证明。

# OScode 工作上下文预算与持久投影改造方案

状态：四阶段代码已落地，已完成隔离回归与本机离线性能测量；加载与验收记录见文末。不额外提交真实模型任务。

## 依据与问题边界

参考本机 ZCode `fec975905a2abd4c07e35c40d51fa097a2258ec9` 工作树，以及已检出的 DeepSeek Harness `39163dd30f703a79079e2d2446545cff3c453738`。未宣称这是它们远端的最新版本，也未运行两个参考仓库的完整测试。

用户截图的网关准备 93 ms、本地准备 8.4 秒、最近模型请求首字节约 30 秒、整轮首段进展 38.4 秒。图中的 99.7% 明确标为上轮缓存命中，不能用来证明正在执行这一轮已命中缓存。此前历史去重改变过投递前缀，本轮可能重新建立缓存，但需要该轮的供应商 usage 确认，不能直接认定原因。

`contextPreparationMs` 当前覆盖配置解析、协议会话、Agent/客户端构建、SDK 输入组装等整个准备过程；8.4 秒不能全部算作摘要、Token 计数或数据库读取。最近请求的网络指标也不能与整轮指标无条件相加。

## 参考实现中实际可复用的做法

| 来源 | 实际机制 | 本项目应借鉴的部分 |
| --- | --- | --- |
| DSH `compaction-basic/src/index.ts`、`config.ts` | 每个安全 step 边界测量压力；按实际 provider/model、输出预留、headroom 解析阈值；先 prune，重新计量，仍超限才摘要 | 单一预算决策；模型级覆盖；先本地、后模型的分层处理 |
| DSH `compaction-tool-result-pruner` | 长文本保留首尾并标记中间省略，默认阈值 8192 字符、头 4096、尾 1024；原会话日志追加替换关系 | 复用本项目已移植的 `pruneResults`，保留原始证据与来源关系 |
| DSH `compaction-basic/src/region.ts` | 按最近尾部的 Token 预算选区，向工具调用/结果完整边界移动；不是只按用户消息轮次截断 | 长任务按已完成工具周期收缩，保留进行中的调用 |
| DSH `token-meter/src/index.ts` | 同一服务拥有估算与每会话 replay fold；仅在请求 envelope 匹配时复用 usage anchor | 用真实单次请求统计校准增量估算，避免每轮重新全量计量 |
| ZCode `compact/microcompact.ts` | 纯本地微压缩；按工具组选择旧结果，默认保留最近 5 组；默认不清理错误和媒体结果；生成 boundary 记录 | 低成本日常清理，与完整摘要分开；保留选择与审计边界 |
| ZCode `runtime/methods/microcompact.ts` | 运行时显式配置启用微压缩，替换工作历史并记录事件 | 不把“代码存在”误认为功能默认已开启 |
| ZCode `runtime/methods/compact-persistence.ts` | 压缩生命周期、摘要与保留尾部的边界持久化 | 页面刷新、会话切换和进程重启不丢投递状态 |
| ZCode `runtime/context-composition`、`local-ttft-compaction.ts` | 给类别与条目大小，记录实际压缩生命周期与 TTFT 事实 | 分类统计与独立压缩耗时，不靠总时长差额猜测 |

两个参考实现的容量阈值不能直接当成本项目的低延迟默认值。下面的软预算是建议试验配置，不是 DSH/ZCode 的原始默认值。

## 目标结构与唯一所有者

```text
完整协议日志（SQLiteSession，原始证据，追加保存）
                │
                ├── 历史界面 / 按引用读取原始工具结果
                │
                └── Python 上下文投影所有者
                       ├── 已提交 checkpoint + journal 尾部游标
                       ├── 保护当前意图、约束、未完成调用和近期工具组
                       └── 本次不可变工作输入 → 原 SDK Runner / Provider
```

Python 是协议日志与投递投影的唯一写入所有者。Node 继续管理执行收流与持久展示，浏览器只发 `/compact` 命令、订阅状态和读取统计；不再由浏览器内存 Map 决定长期投递状态。SSE、既有 Runner、审批和取消路径保持原职责。

## 改造一：容量硬边界与速度软预算分开

硬输入上限继续来自已验证模型能力：

`hardInputLimit = contextWindow - actualOutputReserve - safetyMargin`

新增按 provider/model 配置的工作集软预算。第一轮灰度建议：

| 参数 | 初始试验值 | 含义 |
| --- | --- | --- |
| `working_set_trigger_tokens` | 65,536 | 超过才准备一次收缩，不等到 1m 窗口接近满 |
| `working_set_target_tokens` | 40,960 | 收缩后留出增长空间，避免每轮反复摘要和改变缓存前缀 |
| `recent_tool_groups` | 5 | 优先保留最近已完成工具组，另受尾部 Token 预算约束 |
| `recent_tail_tokens` | 12,000–16,000 | 工作尾部参考预算，不得拆开进行中的工具周期 |
| `checkpoint_output_tokens` | 2,000–4,000 | 摘要供应商输出上限，独立于主任务推理设置 |
| 自动摘要总调用预算 | 2 次以内 | 一次正常摘要，最多一次已有结构修正；不走无限修复或层层 map/reduce |

这些参数必须与硬输入上限取更小有效值。工具 schema、固定指令、当前用户材料都计入工作预算；保护内容本身超过软预算时应明确记录 soft-over-budget，不能丢弃当前材料。超出硬上限且无法安全收缩时明确失败。

预算计数优先用匹配模型的 tokenizer；无可靠 tokenizer 时，使用标明方法的估算，并在 envelope/投影版本匹配时参考最近一次真实 `last_input_tokens` 与新增尾部。请求体字节仅作字节统计，整轮累计 input/cached tokens 不用作单次工作输入预算。64k/40k 要通过同模型、同推理档位的真实样本 P50/P95 校准，不宣称它们保证某个秒数，也不每轮动态修改阈值。

## 改造二：每次请求先走无模型的 microcompact

复用 `apps/agentOS/src/oscode-context/src/tool-result-pruner.ts`，在软预算决策中将本地整理与语义摘要解耦；整理后重新计量，达到目标就结束，不调用摘要模型。

- 保留已有完全相同 alias 的无损去重。
- 优先处理较旧且已确认完成的工具组；最近 5 组、未完成调用、审批中调用、媒体附件及未解决错误受保护。
- 较长的成功日志保留首尾、退出状态、截断标记与原始结果引用。工具生命周期 completed 不等于命令成功：非零退出码、timeout、unknown outcome 不能按成功日志清空。
- 复用 journal 保存原文，不为每个输出再复制一个新存储。若现有 `get_command_output` 只能读取短期进程句柄，则补一项有界只读的历史结果读取能力，按当前会话的 `callId`/引用读取日志；不把过期句柄当作永久证据，不暴露宿主路径。
- 剪裁选择与替换结果一旦提交，后续请求稳定复用，不在每轮重新裁剪全部旧结果。

调整 `history-segmenter.ts`：当前 `retainTurns=2` 以用户轮次保护尾部；一轮长任务有几十次工具调用时会保护过多历史。应优先保留当前意图与必要约束，再按尾部 Token/工具组选择边界，并沿 `balancedCuts` 向安全边界移动。协议需要的推理与对应工具续答作为原子单元保护，不直接批量删除历史 reasoning 字段。

## 改造三：checkpoint 持久化并增量读取

目前手动 checkpoint 在前端 `contextCheckpoints` Map 中；自动投影的 TS worker 和摘要缓存属于一次 Runner，结束时关闭。仅打开自动开关会有重复投影/摘要及跨请求状态丢失的风险。

在既有 SQLite 增加应用自有投影记录，不改 SDK 表结构、不另建存储服务。至少记录：认证 owner scope、provider/model/role、policy version、projection version、原始日志已覆盖范围及末端 cursor、源 hash、checkpoint、裁剪结果引用和时间。迁移与删除都跟随会话归属。

读取时组装“固定前缀 + 已提交 checkpoint + cursor 之后的必要协议尾部”；避免每轮读取、转换和序列化整个原始日志。稳定行/事件游标替代前端按消息正文匹配历史边界的方式；已提交旧前缀保持稳定，只追加新尾部。

构建后台候选时仅读取已完成前缀的不可变快照。同一会话合并为一个整理任务。提交时验证 owner、route、policy 与已覆盖范围的 hash；尾部追加可接受，分支/历史修改导致覆盖范围变化则拒绝陈旧候选。只能在下一个安全模型请求边界采用新版本，不在进行中的 HTTP 请求中换输入。

`/compact` 改为调用同一后端投影命令；刷新、切会话及重启仍能恢复同一 checkpoint。旧客户端传入 context 仅用于兼容，不能成为新的持久权限或投递权威。

## 改造四：语义摘要按需、增量、尽量离开发送关键路径

microcompact 后仍超过软预算才复用 `ContextCompactionEngine` / `LLMSummarizer`。正常只处理“旧 checkpoint + 新完成但尚未覆盖的片段”，不反复摘要全档案。

摘要继续使用既有无工具调用、八字段 schema、明确不可信 user checkpoint、结构/收缩/引用校验。主任务保留用户推理档位；摘要单独使用供应商明确支持的低推理配置，不虚构“关闭”能力。失败保留当前有效版本；软预算失败可继续使用仍在硬边界内的有效工作集并显示失败，硬超限不能静默发送。

优先在轮次结束后的空闲时预生成候选；有新输入时不让后台整理抢占或改写活跃执行。第一次为已有超大历史建立 checkpoint 仍有成本：若没有可用候选，只能做一次明确可取消的前台整理，并立即显示其真实状态，不能承诺背景化能消除首次迁移开销。

## 改造五：定位 8.4 秒准备并给出正确的前端统计

继续拆分当前 broad preparation：配置/档案、journal 打开与读取、投影查找、本地整理、摘要、Agent/HTTP 客户端构建、SDK 转换/JSON 序列化。先用离线 profile 和无模型 loopback 定位，确认成本后再复用相应缓存/客户端；不先假定 8.4 秒全是历史读取。

每次模型调用必须带 request/attempt 标识，区分首次请求与最近请求。界面同时显示模型容量、工作集使用/软预算、归档条目数、估算方法及当前/上轮缓存；压缩耗时是独立 span。复用原 SSE 发布准备、裁剪、摘要、提交、失败事件，不发送模拟模型正文。参照 ZCode 的 TTFT 事实记录增加浏览器接收与显示阶段，补齐服务端首段事件到真实显示的观测空白。

## 实施顺序与验收

1. 先补 preparation 子阶段、输入组成和单次请求标识，验证 8.4 秒真实来源。
2. 增加后端持久投影所有者、迁移、cursor/hash/CAS；接通 `/compact`、恢复与删除。这是后续自动策略的前提。
3. 接入 microcompact、按工具周期保留与软预算；先灰度一个 provider/model，不调用额外摘要即可完成大部分整理。
4. 复用现有摘要器做增量 checkpoint 与空闲预生成，再展示两类预算和完整 TTFT。

验收覆盖：100 次工具调用只有一条用户指令时仍能收缩；工具调用/结果和必要推理配对不破坏；错误/审批/媒体保护；历史结果按引用可追溯；页面与服务重启恢复；新增输入使陈旧候选失效；同一前缀不重复摘要；失败不伪装成功；未改档位时测量不同工作集的收益。

以完整 20 万级历史、microcompact 后和 40k 目标工作集做同条件对照，分别记录冷/热缓存、准备、首段进展、首段正文、总耗时及摘要成本。模拟服务先验收本地路径；真实供应商数据用后续正常请求或明确安排的小规模对照，不靠测试额外重复用户的长任务。热路径本地准备 P95 可先设 500 ms 工程目标，首次初始化/摘要单列，结果以实测为准。

## 2026-11-14 实施记录

### 已落地的路径

- Python `context_compaction/store.py` 在原 SQLite 中维护应用自有投影表，不改 SDK 日志表的列或写入协议。记录 owner/route、policy/version、覆盖行游标、累计源 hash、投影校验和、摘要/剪裁统计和单次 usage anchor。提交在事务内验证版本、历史 epoch 和源范围 hash；尾部追加允许，历史更新/删除会使投影失效。投影损坏时恢复原日志。
- `ProtocolSession` 热读取只解码已提交工作输入与游标后的新行。Runner 仍完整保存原消息、思考、调用和结果。手动 `/compact` 走同一个会话所有者，页面不再维护 checkpoint Map，也不在后续发送中重放浏览器摘要。旧客户端的请求级投影只作兼容，不能覆盖已经提交的持久投影。
- 复用 TS `pruneResults`、安全工具边界和 `ContextCompactionEngine`，新增工作软预算及按工具周期/Token 尾部选择。最近 5 个完整工具组、当前用户意图、思考与调用配对、失败/未知/超时、审批和附件受保护。允许一次有界摘要跨过受保护片段；受保护原文完整保留。
- 裁剪后的长工具结果携带 `journal:CALL_ID`，新工具 `read_archived_tool_result` 通过当前认证会话及模型路由读取原日志，单次最多 16,384 字符，不接受用户指定数据库或宿主路径。
- 每个 Runner/空闲整理任务共享摘要调用额度。试验路由上限 2 次，含一次结构修正。完整轮次结束后合并一个空闲任务；新请求先取消并等待旧整理退出，再取得会话。持久投影只在安全请求边界采用，旧前缀不会每次重新摘要。
- 无匹配 tokenizer 时继续明确标注 UTF-8 保守上界；仅当 provider/model、固定指令、工具 schema 和输入前缀 hash 匹配时，以对应单次请求的 `prompt_tokens` 加新尾部保守上界进行校准。不会把累计 Runner usage 或网络字节当成真实输入 Token。
- 只为 `https://open.bigmodel.cn/api/coding/paas/v4::glm-5.3-flash` 默认启用试验软预算：65,536 触发、40,960 目标、14,000 参考尾部、5 组工具、4,096 摘要输出、2 次摘要额度。真实模型窗口仍来自能力表，主任务推理档位保持原设置；输出预留对应该路由现有声明的 65,536 上限。环境里的显式模型策略可以覆盖默认值。
- 复用原 SSE 添加读取、整理、摘要、提交/未保存阶段；持久展示工作集、容量、覆盖条目、版本、测量方法。请求携带实际 provider 请求序号及逻辑 attempt/turn，区分首次与最近请求。浏览器记录首段接收及 DOM 提交后帧回调，后者不宣称是物理屏幕绘制时间。

### 定位出的本地准备开销

离线构建默认 `httpx.AsyncClient` 的 5 次测量为 **1,733 / 1,757 / 1,648 / 1,788 / 1,469 ms**。`cProfile` 单次 1.578 秒，其中 4 次 `load_verify_locations` 累计 1.433 秒；直连和环境代理传输重复读取同一信任库。

`llm/tls_context.py` 因此只缓存不可变的、开启证书和主机名校验的 SSLContext；HTTP 客户端、连接池、取消、回调和请求计时仍每轮独立。保持 httpx 的 CA 环境变量语义，证书配置/文件变化使缓存失效，并有 5 分钟刷新边界。修复后独立测量客户端构建为 **632.78 / 0.38 / 0.21 / 0.19 / 0.18 / 0.17 ms**，首个为冷启动。没有为了该问题引入跨任务共享 HTTP 客户端。

离线合成准备测试使用 201 条原协议记录、11 条工作输入，热请求解码归档行数为 0。首轮独立运行的 1 次冷启动 + 20 次热样本得到：冷准备 **473.89 ms**，热 P50 **12.80 ms**，热 P95 **19.57 ms**。与各测试套件并行的最终复测为冷准备 **637.69 ms**、热 P50 **17.17 ms**、热 P95 **40.27 ms**。范围是日志打开、投影读取、Agent/客户端构建和本地输入过滤，**不包含 SDK 发送、供应商等待、首次语义摘要和真实浏览器端到端延迟**。最新证据位于 `.tmp-tests/oscode-context-preparation-profile.json`，不能将此结果直接当成用户实际 TTFT。

### 验收边界

真实供应商的首段进展、首段正文、冷/热缓存和质量收益仍需后续正常请求采样，未额外付费重放用户长任务。第一次迁移巨大旧历史仍可能等待一次真实摘要；该阶段显示实际状态并支持停止。软预算整理失败保留有效输入，硬超限仍阻止发送。

空闲候选提交不向已经结束的执行伪造正文或追加模型内容；新投影在下次安全请求边界恢复并通过 SSE 展示版本/统计。浏览器接收与帧回调指标属于当前页面观测，服务端不伪造历史浏览器时间。

隔离浏览器已确认容量与软预算分开显示、信息栏无横向溢出。截图和合成统计位于 `.tmp-tests/oscode-context-budget-20261114.png` / `.json`。该浏览器使用独立临时资料目录，没有提交模型请求或重载用户正在编辑的页面。

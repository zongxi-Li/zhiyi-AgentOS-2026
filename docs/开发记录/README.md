## 整理说明（2026-10-30）

### 做了什么

- **原始 47 篇 Markdown + 1 份 JSON** → 当前目录 **16 篇 Markdown（含本索引）+ 1 份 JSON**，归档目录 **6 篇 Markdown（含归档索引）**。
- **40 篇**按同一阶段/同一主题合并为 **12 册**「合并记录」；**2 篇**独立归档；**5 篇**原样保留（EX-00、C2A-1、门禁规范、Chat 流式中断修复、交互设计）。
- 合并册的**正文逐字保全**，只做两类机械处理：标题层级下移一级、指向已合并/已归档文档的相对链接改写。结论、数字、失败记录与代码块没有改写。

### 如何确认没有丢内容

每册合并时都对原文做了归一化比对（忽略标题层级与链接目标），逐篇校验通过；每册附录列出全部来源文件、日期、性质与字节数，方便逐条核对。原文件完整保留在 Git 历史中：

```powershell
# 查看整理前的文件与提交
git log --oneline -- docs/开发记录

# 恢复某一篇原件（整理提交前）
git checkout HEAD -- "docs/开发记录/<原文件名>"

# 恢复某一篇原件（整理提交后）
git checkout HEAD~1 -- "docs/开发记录/<原文件名>"
```

### 约定

1. 同一阶段或同一 PR 的「实施 + 验收」可以合并为一册；**跨阶段不合并**，避免一册过长、结论混淆。
2. 合并稿只做机械处理，**不覆盖原文结论**；后续结论写在新记录或索引里，符合 `docs/README.md` 的审计约定。
3. 归档文档不随代码演进更新；其中命令、路径与验收结论只代表当时状态。
4. 新增记录时同步更新本页与 `docs/README.md`；若一条记录被取代，移入 `归档/` 并在其 README 中登记原文件名。

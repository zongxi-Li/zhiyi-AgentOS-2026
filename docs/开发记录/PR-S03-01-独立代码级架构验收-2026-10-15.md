## 3. 已证实 P1、反例与最小修复

### P1-1：最后一次身份读取后缺少来源重验

入场 graph_materialization.py:82 在 get_current_sources、source_provenance、safe_cut 之后调用 semantic_principal_provider。随后只重验授权、取消及 authority。身份提供器可能阻塞，期间发生的真实收据/Checkpoint 或注册表变化不会被授权检查识别。

独立反例 `test_final_identity_read_cannot_hide_trusted_source_changes` 用身份回调调度最后窗口的五种变化：真实 prepare_node_commit；真实 save_checkpoint（Checkpoint 已提交但 Run 未确认头，包含 node review）；Agent profile；Catalog output contract；Workflow domain（version 不变）。五项均错误 MATERIALIZED_INACTIVE，实际留下 Journal：**5 failed，6.27s**。没有伪造 package/proof，没有绕过模型合同；测试 hook 仅固定正常来源变化的时序。这是最后显式身份读取之前已完成来源检查的可避免缺口，不能归为不可解决的跨库提交瞬间。

修复只把最后身份捕获移至来源和 Safe-Cut 检查之前；最终仍执行身份一致性、当前授权、取消和两项 authority 检查。未降低任何来源/拓扑/审核校验，没有新算法或持久状态。五个失败反例与原 42 项合跑 **47 passed，62.75s**。

这不把不同数据库、外部权限提供器和内存注册表变成原子事务；最后一次各自来源检查之后的并发改变仍属明确保留窗口，S03-02 必须再次验证。修复前已经签发的历史 inactive 记录不能当作经过修复后策略的当前许可。

未发现 P0；五个 P1 反例已转绿，且修复被原集、独立集、定向、扩大及两次全量中的相关用例覆盖。未把下述流式失败推定为本轮新增的生产 P1，也未因其测试/适配器未改而宣布完全无关；完整门禁未通过构成最终 CONDITIONAL 的必要验证限制。

## 6. P2、性能和明确保留限制

1. 原 S02-03 已登记的旧模板逻辑资源比较较保守，本次真实 A→B 场景已独立证实；不放宽 Safe-Cut。当前无控制 DAG、来源完整且保护前缀逻辑合同保持的范围可工作；initial_plan、HTN/Horizon durable 消费、控制区域修订不在范围。
2. 同步编译/读取没有可抢占硬 deadline。GraphProvider 限当前 256 steps、1024 edges/receipts、64 inbox、256 profiles、512 descriptors、Run 2M 字符；Journal 4M，祖先 256。部分读取/反序列化在上限检查前，Checkpoint 历史、单条 receipt/profile/catalog/metadata 深度及总字节无统一硬界。不能把数量限制宣传为硬内存/时延保证。
3. Compiler 在写事务外；写锁内仍有有界祖先逐行解析、跨库来源读取、JSON/hash、Safe-Cut。Safe-Cut 继承约 O(N·(R+E+L)+B)，父集合有 visited；祖先额外 O(H) 查询及其载荷解析。最新 Checkpoint 对历史 C 的查询缺专门排序索引。BEGIN IMMEDIATE 是 Workflow 全库写锁，未测大历史/多 Mission 吞吐或 SQLite 5s timeout 压测；无错误接受证据，不升级为 P1。
4. Journal 自身验证实际表/唯一索引 SQL；等价但不同管理定义可能保守拒绝。Planning ledger 对同名错误 graph-source 索引的既有 P2 未在此扩改。升级仅运行在临时 DB；不默认迁移。
5. 跨 SQLite 连接/进程唯一性已实际验证，不等于全系统多实例 Runtime 安全。Run lock 单进程；Workflow 事务不覆盖 Identity/value/Checkpoint/权限服务/内存目录，仍需激活前重验。未进行真实 kill/断电/WAL 损坏实验；commit/ack 故障为真实连接包装注入，恢复实验为实际新 Python 进程。
6. Package 和 Record 是可信服务代码产生的规范化内容，没有密码学签名/进程失陷防御。测试的单字段包腐坏保留原 checksum；源/绑定重哈希反例独立验证语义来源。不声称能抵抗管理员任意重写全部内容、指纹、SQL 索引或替换可信 Compiler。
7. **UNVERIFIED／未解决的回归门禁：** 两次最终全量的 test_private_provider_activity_keeps_stream_alive_until_public_json_arrives 均在 asyncio.sleep(0.01) 等待 provider activity 时被截止期取消，抛 model stream activity deadline exceeded。该测试 ttft_timeout=0.02、idle_timeout=0.03、total_timeout=0.2；测试及 model_runtime.py 与冻结 HEAD 的 LF 规范化字节完全一致（SHA-256 分别 972c95e17af9d252632705318d7fc4aa9a0b0afbf537a51d7e781c9c7bf2daa7 / 9e541676fb3e98a064fa51011bee8d437e984c2935cd9fc7e0ccd79a8ec9319e）。相同默认计时环境定向复跑整个文件为 8 passed，0.48s，但全量确认仍失败。疑似运行上下文/调度/负载影响；未测量/更改系统定时分辨率，未在隔离 HEAD 上完整复测，不能声称已证明基线也失败或全部 OS 根因。没有修改适配器、放宽时限、跳过用例或请求 1ms；两次失败全部保留，不继续重复直至“刷绿”，不把该疑点定性成已证实 P0/P1。

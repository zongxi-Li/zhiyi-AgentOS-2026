# OScode 摘要与协议投影修复

日期：2026-11-14。
遵循 `PR-OSCODE-STREAM-01-链路审计与优化建议-2026-11-14.md` 的边界：复用 SDK Runner，分离模型输入投影与完整历史，不引入第二套执行器。

## 已复现问题

1. GLM 返回包含 Markdown 围栏的摘要，直接 `JSON.parse` 失败。
2. 仅要求 JSON Object 仍不足以保证八字段字符串数组结构。
3. 默认摘要限制在保守计数下实际为 2048 UTF-8 字节；超过限制后按字节比例缩小 Provider 的输出 token 上限，会把修正响应截断为不完整 JSON。
4. TS 引擎生成不可信 `user` 类型 checkpoint，协议日志适配将它当作原始用户消息校验，得到 `CHAT_CONTEXT_PROJECTION_STALE`。旧测试使用 `system` 类型占位摘要，未覆盖真实产物。

## 修改

- Python 宿主按模型能力声明请求 JSON Object；摘要调用仍不提供工具。
- TS 提示包含明确 JSON Schema；接受完整 JSON 或单个完整 JSON 围栏，不从混合说明文字中截取对象。
- 所有字段、内容、收缩和窗口校验保持；结构、大小错误共用最多一次修正及既有总调用预算，失败保留原文。
- 默认摘要 allowance 调整为 8192 个计数单位，继续受目标收缩和可用窗口裁剪。修正时不再按 UTF-8 字节比例降低 Provider token 上限。
- Python 识别 TS 的确切 checkpoint 信封，摘要仍为不可信 user 数据；仅对保留的真实用户轮次匹配协议日志，保留完整工具尾部，不改写原始归档。
- 新增真实 TS worker → SQLiteSession → 两轮 SDK 投递测试。另将既有中断续接测试的故障注入覆盖两次请求尝试，以适配并行线路已加入的有限恢复；未修改恢复实现。

## 验证及界限

- TS 引擎 39 项测试通过，TypeScript 类型检查通过。
- Python 压缩、HTTP、协议会话回归 23 项通过、1 项跳过。
- 隔离进程读取历史调用真实 GLM：`status=summarized`，一次摘要调用，Provider `finish_reason=stop`，JSON 有效。
- 保守估算 `31045 → 11335`，减少约 63.5%。计数方法为 `utf8-upper-bound`，不是供应商实际 token 节省或计费证明。

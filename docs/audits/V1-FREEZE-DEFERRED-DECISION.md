# V1 冻结延期决定

- 日期：2026-10-27
- 决定人：项目所有者
- 状态：已生效

## 决定

V1 阶段冻结（AgentOS 内核基线冻结）**延期，不设定期限**。冻结门禁 `scripts/freeze_gate.py` 不再作为当前研发的阻断条件；门禁 498 节点 vs 300 秒硬预算的结构性冲突登记为已知限制，不在本期解决。

## 背景

- 10-26 PR-C2B-INT-2E-CLOSEOUT 结束时，唯一剩余冻结阻断是正式冻结门禁在 498 个收集节点上以 `INCOMPLETE_TIMEOUT`（300.79 秒、约 375 项已过）失败；按线性外推全量约需 430 秒，超过脚本设计上拒绝上调的 300 秒硬顶（`DEFAULT_BUDGET_SECONDS = 300`，`--budget-seconds > 300` 直接报错）。
- 这不是测试失败：同一最终源码快照在分层重验 L1–L6 全绿（Python 两层 66+303 项、Java 53 项、前端 155 项、双构建、真实浏览器 E2E），证据见 `docs/audits/PR-C2B-INT-2E-CLOSEOUT.md` §5。

## 理由

1. 冻结所要换取的基线可信度已有替代证据（分层全绿 + 真实 E2E）。
2. 解决 498 vs 300 需要改动门禁合同（上调硬顶、拆分固定 manifest 或以分层证据替代整跑），继续投入与当前主线（产品能力开发）不成比例。
3. 近期审计/整改循环出现了自续轮次倾向，本决定同时作为止损声明。

## 止损规则

- 审计、门禁、复审类工作今后**仅凭项目所有者明确立项的任务书启动**，不再自续轮次。
- 冻结门禁脚本、基线、manifest、时长缓存保持现状，任何人不得为"让门禁通过"而清空历史耗时缓存或修改预算。

## 重启条件

出现真实的发布/打 tag 需要时，再就以下选项之一单独裁决：

1. 上调 300 秒硬顶（改 `freeze_gate.py` 合同）；
2. 拆分或缩减固定 manifest；
3. 以分层验证证据链替代整跑门禁作为冻结条件。

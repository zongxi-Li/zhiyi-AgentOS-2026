# 基于实际观察的四阶段 ACG 实现计划

日期：2026-11-17。状态：四阶段实现已部署；实际运行暴露的正式规划交接缺陷已修复并验证。

## 目标与运行流程

新建的工作区勘察任务先通过正式执行链获取事实，再生成详细工作图。流程为：初始化探查图 v1 → 基于证据形成正式图 → 执行及局部审查 → 验收交付。全部阶段保留同一个 Run 和已完成节点，范围与工作图通过正式修订演进。

初始规划没有先行工作区观察；现有覆盖合同无法表达排除项，目录优先的确定性补图会让 `.git` 等大型树持续占满工作页。必须同时修复观察、范围表达和规划决策，不能仅增加提示词。

## 实施步骤

1. **探查与范围合同**：增加兼容旧记录的明确排除路径语义；区分用户显式证据要求与系统推导范围。阶段、范围及调整理由记录在正式 TaskPlan，复用已接受计划作为唯一来源。旧冻结要求和已执行图不改写。
2. **初始化探查**：对新建且绑定工作区的原生勘察任务创建最小探查图。通过原 NodeRunner、Agent ReAct、工具运行时和 Hands 执行只读操作。读取关键配置及必要源码，以足够规划为提交依据。已有模板和无工作区任务保留原路径。
3. **正式规划与局部演进**：把已提交探查结果及经核验的目录/文件观察投递给 Planner。正式规划仍走规划提交、safe-cut、图激活与接管；保留探查前缀，仅新增或调整未执行工作。模型可按证据选择补读优先级及调整推导范围；用户显式范围仍须满足。覆盖信息用于验收和补充观察，不机械覆盖模型的任务判断。
4. **验证与收尾**：覆盖初次准入无工具调用、探查读取真实素材、同 Run 版本递进、忽略目录和显式全量、范围修订、局部恢复、最终报告和历史兼容。执行必要回归并更新文档。部署前核对活动任务，不中断当前运行，也不自动恢复已取消任务。

## 上下文和记忆

- Planner 通过正式已提交证据获得目录结构、关键原文、来源引用、读取完整性及未知项。模型生成的结论继续标明信任边界。
- 原文、收据和请求保存在既有受控值仓库，图与检查点仅引用。原文按工作所需投递，继续支持授权分页读取。
- 记忆提供相关结论和索引，不能证明当前文件已读。保持已有按 Run 召回与按节点提交冻结的记忆快照。
- 不增加固定执行、补图或审查轮数；没有新证据和实质变化的重复动作由现有无进展机制处理。

## 验收标准

- `.git`、依赖和产物等目录的处理依据正式范围与任务目标，排除有记录且能修订，用户明确要求的范围不会被悄悄删减。
- 正式详细图建立前已有实际 Hands 文件观察；Planner 获得实际关键文件内容及可追溯证据。
- v2 及后续版本不重复执行已提交的探查节点，引用与执行账本保持一致。
- 同时兼容旧任务、旧 WAL、显式工作流模板与非工作区任务；不直接 SQL 修改任何任务状态。

## 已实现

- 初始准入复用 `workspace_discovery` 两节点前缀，通过原执行器及只读工具探查；正式规划重新调用现有意图解析和语义分解器。已完成理解节点直接复用，后续图沿用同 Run。
- `workspaceScope` 随正式 TaskPlan 修订生效，支持字面路径排除、理由和真实来源引用。保留原冻结要求；显式来源范围不能缩减，历史任务不能借补丁直接升级协议以绕过初始化。
- 补读交替安排文件和目录；新协议由模型根据当前证据决定下一步，确定性补页作为可审查候选。单次规划及可选 Planner ReAct 共用缺口反馈、信任封装和交付验证。
- Planner 接收受控值仓库中的已提交原文：固定探查依据、最新因果结果、最新审查及对应读取页。Agent 结论与读取事实分开标记，observation 和检查点只持有引用。旧审查页正文不累计投递。
- 两种 Planner 共用模型图投影：保留所有任务身份与依赖、正式范围和交付要求；活动工作、并行因果前沿及直接证据保持完整，较早已完成节点仅投递状态与引用摘要。附正式计划指纹，摘要不替代权威 TaskPlan。120 批增长测试保留 246 个任务身份，完整节点正文保持 8 个。
- 范围变化即使没有节点或边变化，也经过完整语义提交、图生成、激活、接管与新 Permit。已完成节点和输出引用不改写。保留旧载荷默认序列化，已有记忆提交快照与回放语义不改。
- 图派生被拒且存在未激活新提交时保留执行屏障及具体拒绝原因，禁止以旧 Permit 标记可执行重试；语义提案自身被拒且旧图仍有效时继续使用原自动修正流程。后续未激活提交的自动修复不通过放宽 Permit 实现。

# Safe 已认证传输：阶段实施记录

日期：2026-11-15。承接既定拆分推理计划的 P2，复用已通过的模型、会话、回执和 FP32 codec。保持现有目录和依赖方向。

## 本阶段交付

1. 请求认证基础：独立 HMAC-SHA256 域，覆盖凭据 ID、method、规范 path、UTC 时间、nonce 与最终请求体 SHA256。凭据由注入源按请求读取，支持撤销；owner 仅来自认证结果。nonce 独立于业务 request ID，原子消费、容量有界、时窗内禁止重放。
2. 专用 HTTP 接口：capabilities、创建会话、step、查询回执、关闭会话。先限额读取原始字节、认证，再严格解析 JSON；拒绝重复键、未知字段、编码歧义、重复认证头和未批准 manifest。所有异常只返回稳定码。HTTP 客户端只发送协议 DTO，使用批准 HTTPS origin、证书验证、新 nonce，禁止重定向、环境代理和隐式 step 重试。
3. 独立回环 TLS 验收：后段在独立子进程持有会话和 KV，前段通过实际 HTTPS socket 调用。证书和假凭据在临时目录生成，测量真实请求/响应体字节与耗时，验证端到端 token 与回执一致、跨 owner 拒绝、篡改/重放拒绝、双端终态回收。

## 协议选择

- URI 基址 `/safe/v1`。会话 ID、请求 ID 的路径段只允许 ASCII 字母、数字、`_`、`-`，长度 1–128；拒绝 query、百分号、点路径、尾斜线和重定向。请求体仍使用既有严格合同。
- 认证头：`X-Safe-Protocol: safe-v1`、`X-Safe-Credential`、`X-Safe-Timestamp`、`X-Safe-Nonce`、`X-Safe-Signature`。时间为规范十进制 UTC 整数秒，默认允许 ±60 秒；nonce 为 32 位小写十六进制。签名每次传输重建；业务 request ID 和已编码激活不变。
- 签名域 `SAFE-HMAC-SHA256-V1`；HMAC 使用至少 32 字节的独立密钥。签名保护请求完整性，TLS 负责链路与服务器认证。响应依赖经过验证的 TLS，客户端仍核验响应 DTO、身份关联及限额。
- 当前只有 `safe:infer` 作用域。撤销后新请求立即拒绝，已有 KV 由终态或 TTL 清理；不提供绕过认证的关闭入口。
- 正常请求体上限 12 MiB，step 元数据上限 16 KiB；响应有独立限额。分块传输同样累计上限，不信任 Content-Length 声明。超过限额不能推进模型。
- 超时是结果不确定：既有本机用例先查询已提交回执，查不到则终止，不重发 step。

## 验证与阶段边界

先运行基线，再以失败测试驱动认证与 HTTP 实现。完成后分别执行规格审查、质量审查、Safe 全回归和真实回环 TLS 实验，再按用户既定要求合并、提交并同步 Gitee/GitHub。独立工作区避免混入其他正在进行的前端工作。

本阶段是可独立验收的认证传输基础；回环实验不能替代公网、异构设备、生产负载或完整 P2 验收。DP、持久预算、反演攻击评估和产品入口仍在后续阶段，不能据此宣称激活天然保密。

# ACG 器件协作修复

日期：2026-11-18。状态：实现、联合复核与服务加载完成。

## 职责与事实来源

用户意图形成 Task；Step 声明目标、输入和输出合同；Planner 根据工作依赖生成和局部修订 ACG。能力目录描述执行能力及输入要求，不自动扩张业务目标。

ResourcePlane 管理模型、工具、环境、配额及注册事实；AgentRegistry / AgentPool 管理 Agent 定义与实例（能力、宿主、版本、健康、容量）。沿用现有动态注册和异构执行适配器，不再建立第二个资源池或调度器。ResourceBinder 同时确认宿主与 Agent 实例租约；工具操作单独获得 Hands 租约。忙碌表示等待，未知外部结果必须先对账。

NodeRunner 从已提交上游产物、正式证据引用和受控记忆组装 ContextPack。内部记忆快照保证同次执行重放一致，不是文件读取或外部动作证据。执行结果经既有值仓库和节点提交链交付；审查消费已提交结果，发现真实缺口后向 Planner 提交反馈，局部修订后继续验收。

## 实施工作

1. 将容量等待收敛到调度器，复用原子租约、取消和授权复核，修复 Hands 暂忙导致并行节点整体失败的问题。
2. 抽取可信内部记忆校验，执行、恢复与未派发证明共享同一合同，保留外部动作完整性校验。
3. 清理能力提示生成冗余业务 Step 的机制；保留已完成前缀和真正输入依赖；验收基于实际证据，修订结果重新审查。
4. 图版本错误按请求和选择隔离，恢复成功清理旧错误；执行展示从当前生命周期派生。
5. 使用隔离数据库和可控传输验证资源竞争、等待取消、恢复重放、规划依赖及前端状态；更新验证记录。

不直接修改真实任务数据库，不自动恢复旧 Run，不增加执行或审查轮数上限。现有协议和持久记录保持兼容。

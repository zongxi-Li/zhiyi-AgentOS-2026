# AgentOS 端边云适配第一阶段设计

## 目标

将当前主要面向本地 Agent 的资源调度，扩展为可表达端、边、云执行位置，并建立从资源观测、调度绑定到执行适配的可测试接缝。第一阶段采用“模型位置选择”，不实现神经网络层切分。

## 当前问题

当前 `ResourceProfile` 已有资源类型、位置、数据区域、成本和容量字段，`SchedulerService` 也能筛选、评分并申请租约。但 ACG 运行时在准备绑定时固定要求 `ResourceType.AGENT`，调度完成后又通过本地 `AgentRegistry` 解析 Agent，因此模型、Worker 或远程节点即使登记成功，也不能被真正调用。健康监测主要保存在进程内，运行时还会为本地 Agent 主动刷新心跳，无法代表远程节点真实存活状态。

## 设计方案

### 1. 资源语义

在共享资源合同中增加一等的部署层级和执行端点：

- `DeploymentTier`: `terminal`、`edge`、`cloud`；
- `ResourceEndpoint`: 协议、地址和认证引用，不保存密钥；
- 计算能力：CPU、GPU、显存、内存、带宽；
- 模型能力：可提供的模型标识和执行模式；
- 任务约束：允许的部署层级、最大延迟、隐私级别、是否允许远程执行。

原有 `location`、`dataZone`、`costMetadata` 和 `metadata` 保留兼容，但核心调度字段不再依赖自由格式的 `metadata`。

### 2. 资源观测

增加可持久化、可版本化的资源观测入口。远程节点主动上报心跳、容量、利用率、延迟、GPU/显存、模型缓存和观测序号。运行时不再替远程资源刷新心跳。超出 TTL 后资源进入不可调度状态。

观测的一致性规则如下：

- 远程节点必须为每次观测提供单调递增的 `observationSequence`；
- 低于当前权威快照序号的观测会被拒绝，不会覆盖容量、延迟或健康状态；
- 内存和 SQLite ResourceStore 都执行相同的顺序校验；
- API 对过期观测返回 409，调用方必须重新读取当前快照后再上报；
- 运行时的资源心跳不能替代远程节点的真实观测。

### 3. 调度与执行接缝

调度器继续负责硬约束过滤、软约束评分和租约申请，但评分增加部署层级、延迟预算、数据区域、模型匹配和远程成本等因素，并把选择理由写入 `ExecutionBinding`。

调度器在租约申请后会重新读取资源快照；如果快照版本已经变化，则释放刚申请的租约，不生成基于旧快照的绑定，并继续处理其他候选资源。

执行器通过 `ExecutionAdapter` 调用已绑定资源：

- `LocalAgentExecutionAdapter`：兼容当前进程内 Agent；
- `HttpExecutionAdapter`：为边缘或云端 HTTP 执行节点提供最小远程调用能力；
- 后续可增加设备 SDK、RPC 或消息队列 Adapter，而不修改调度器核心。

### 4. 故障切换

一次执行必须遵循：申请租约 → 调用 Adapter → 记录结果 → 释放租约。远程超时或心跳失效后，当前资源被标记为不可用，运行时从有效 Checkpoint 重新选择候选资源并继续执行。已完成步骤不重复执行，输出引用保持幂等。

## 第一阶段不做的事情

- 不实现神经网络层级切分和中间激活值传输；
- 不引入真实云厂商 SDK；
- 不重写现有 ACG 图模型；
- 不把端边云资源伪装成仅名称不同的本地 Agent；
- 不修改与端边云无关的领域 Pack。

## 验收标准

1. 资源合同可以区分 terminal、edge、cloud，并表达执行端点和关键算力约束。
2. 调度器能排除不满足部署层级、隐私、延迟、模型或显存约束的资源。
3. 本地 Adapter 保持现有 Agent 测试通过。
4. HTTP Adapter 可以在测试中调用一个真实的本地 HTTP 服务，并记录执行资源。
5. 远程资源停止心跳后不再被调度，不能由运行时本地循环假造心跳。
6. 一个端到端测试能证明边缘资源故障后切换到云端资源，并从 Checkpoint 继续。
7. API 和前端投影能显示资源层级、当前绑定、调度理由和切换事件。
8. 文档明确区分“模型位置选择”与“模型层切分”。

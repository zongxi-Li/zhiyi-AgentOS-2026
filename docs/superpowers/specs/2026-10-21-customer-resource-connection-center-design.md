# 客户资源与连接中心设计

## 目标

将 `/agentos/resources` 从面向内部运行时目录的页面，升级为客户可理解、可自助管理的“资源与连接中心”。客户能够接入、验证、启用、停用并查看自己的设备、模型和工具；平台继续以 ResourcePlane 作为端—边—云调度的唯一资源真源。

## 用户与边界

- 主要用户：使用知弈 AgentOS 的客户管理员与技术负责人。
- 客户只可读取与操作其 `owner_scope` 下的 Node、Runtime、模型端点和工具服务。
- 凭据秘密只在首次注册或轮换时返回一次；列表、详情和日志仅展示凭据元数据。
- 停用仅阻止后续调度，不删除资源配置与历史使用记录。
- 调度器内部实现（Redis 键、租约版本、原始评分权重）不在默认客户界面展示。

## 信息架构

页面名称统一为“资源与连接中心”，并保留 `/agentos/resources` URL 与既有 `tab=models` 兼容。

### 资源概览（默认）

1. **健康总览**：本地、边缘、云端资源数量；可用性；正在使用数量；数据位置/隐私提示。
2. **端—边—云视图**：三列资源分组，客户以“我的设备 / 边缘节点 / 云端服务”理解部署位置。资源卡显示名称、健康、能力、可用容量、位置和最近活跃时间。
3. **资源目录**：支持按资源类型（设备、模型、工具）、位置、状态、数据区域与关键词筛选。
4. **连接问题**：仅在存在异常、离线、过期观测时出现，使用可行动文案，例如“检测连接”“查看原因”“切换到云端”。

### 接入资源

“接入资源”替代“注册资源”，提供三条明确路径：

- **接入设备**：创建 Node 与执行 Runtime。收集名称、部署位置、算力、数据区域和允许的能力；返回连接凭据/连接器指引。
- **接入模型**：创建或选择云端模型端点。收集供应商、模型名、兼容 API 地址、上下文窗口与数据区域。
- **接入工具**：创建 HTTP/MCP 工具服务。收集地址、协议、能力标签、访问范围与隐私等级。

每条路径均先完成表单校验，再调用既有注册接口；注册成功后自动执行连接检测。连接失败时保留草稿和可重试动作，避免客户重复填写。

### 资源详情

详情抽屉拆为两层：

- **概览**：状态、用途、部署位置、隐私/数据区域、能力、容量、近期任务和最后连接时间。
- **高级设置**：启停、连接检测、凭据轮换、标签/约束、健康历史、调度说明。高级区域使用“为什么不能用于新任务”这样的解释性文案，而不直接展示内部 Redis 或评分实现。

## 数据与端边云逻辑

前端继续使用 `agentosApi.listResources()`、`listNodes()`、注册、启停、探测、使用记录、健康历史与凭据轮换接口。接口投影以现有 ResourcePlane 的 Node/Runtime/Profile/Snapshot 为真源：

1. Node 描述客户设备、边缘节点或云节点的位置与硬件能力。
2. Runtime 描述真正可执行的模型、工具或执行后端，并绑定到 Node。
3. 健康状态由服务端的 SQLite 快照与 Redis 心跳协调后返回；客户看到 ONLINE、DEGRADED、OFFLINE、UNKNOWN 等可理解状态。
4. 任务调度遵循数据区域、隐私、硬件能力、资源启用状态与可用容量约束；客户页只展示结论和原因。
5. 资源不可用时，系统仅在客户配置允许时提示或执行边缘/云端回退；不对客户隐瞒数据区域变化。

## 组件改造

- `ResourceCenterView.vue`：重命名标题与主要操作文案；保持现有路由契约。
- `ResourceOverviewPanel.vue`：拆出总览指标、端边云视图、异常提示和客户化资源目录；保留真实接口加载、详情抽屉与快捷刷新。
- `ResourceRegistrationDialog.vue`：改造为设备 / 模型 / 工具三类接入向导，复用现有 Node/Runtime 注册契约。
- `ResourceDetailPanel.vue`：客户概览优先，高级操作折叠；继续复用探测、启停、使用历史、健康历史、凭据轮换 API。
- 新增纯展示/映射组件和单元测试；不复制 ResourcePlane 的约束、健康或容量判定逻辑到前端。

## 状态与错误处理

- 加载失败：保留上一次成功数据，显示“暂时无法刷新”及重试。
- 节点目录失败：服务目录仍可用，显示非阻塞提示。
- 注册成功但探测失败：资源保留为待连接/离线，给出“重试检测”。
- 凭据轮换：显示一次性秘密与复制确认，关闭后不能再次读取。
- 停用：需要确认提示，明确“不会删除资源或历史记录”。

## 测试与验收

- 路由兼容：`/agentos/resources`、`?tab=models` 与旧重定向保持有效。
- 总览：真实 Node 与 Runtime 数据可按端—边—云正确归类，异常状态有客户可理解文案。
- 筛选：类型、位置、状态、数据区域、关键词组合正确。
- 接入：设备、模型、工具三种路径生成正确注册 payload；失败时保留可重试状态。
- 管理：探测、启停、健康/使用记录与凭据轮换继续调用既有 API。
- 权限：前端不构造跨 `owner_scope` 的管理操作；服务端仍为最终授权边界。
- 可访问性：可键盘访问、加载和错误状态使用适当 ARIA 语义，移动端资源卡不溢出。

## 非目标

- 本轮不把 Redis、PostgreSQL、SQLite 的存储实现暴露给客户。
- 本轮不实现神经网络层级切分、真实跨设备数据迁移或新的远程协议。
- 本轮不改变 ResourcePlane 的调度事实、数据库结构或现有公共 API。

## API 与迁移影响

- 对外 API：无 breaking change；复用既有资源、节点与观测接口。
- 数据库：无强制迁移。
- 配置：无强制配置变更。

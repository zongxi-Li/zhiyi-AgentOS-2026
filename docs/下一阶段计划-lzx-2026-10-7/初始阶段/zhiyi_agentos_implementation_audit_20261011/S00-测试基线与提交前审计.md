## 本次发现与修复

### 旧 Workspace API 两项夹具

`apps/agent/tests/test_agentos_v2_workspace_api.py` 两项旧夹具与当前合同不一致：StepNode 已不接收 agentName；伪造 Run 缺少 RuntimeRunRecord 的状态及必填字段。

### 已持久化 Run 的调度失败恢复

`apps/agent/app/api/agentos_v2.py` 的 `create_mission_run` 与 `retry_failed_step` 后继分支：首次请求保存 Run 后若 submit 失败，重复请求原先只返回 Run，未重新提交调度，可能永久停在 pending。

现在重复请求通过已有 ExecutionCoordinator 再次 submit 同一个持久化 Run；已删除 Run 返回 404；调度失败返回 503 并要求原 clientRequestId/请求体重试。首次准备/提交的 RuntimeError、SQLiteError 也映射为可重试 503。复用现有幂等准备、Runtime 和 Coordinator，没有第二套队列或状态管理器。

新增 `test_mission_semantic_audit.py` 使用真实 API/Runtime/Coordinator 与临时数据库，注入保存之后的调度失败，验证重复失败、再次恢复、不重复建 Run、请求内容冲突、删除边界、Mission 编辑后仍保留原 Basis，以及成功后重复请求不再次执行代理。

`test_agentos_v2_api.py` 旧单步重试 spy 只记录 submit 调用次数，调整为准确断言三次调度尝试；仍保留两次 prepare 和同一 child id 的断言。真实 Coordinator 的去重及完成后不重新执行由上述集成测试证明，不能把调度尝试数当成执行次数。

### 隔离运行器

`scripts/verify_mission_semantics.py` 增加 audit 子集；内置别名附加的显式测试路径现在确实参与执行，原先会被忽略。临时 cwd/空 .env、各 SQLite/附件/Chroma 路径重定向、私有 basetemp、禁用缓存及根 conftest，避免打开业务存储或清理其他任务目录。此脚本不修改生产配置。

## 状态权威、并发与兼容审计

- MissionSemanticService/Store 仍是正式语义写入权威。Mission 的旧输入、Identity 投影和 Workspace 展示不是另一份正式语义状态。
- Revision 决定是绑定 Mission、Run、来源/目标 Revision、operationId 的持久化用户回执；Run/Graph 执行状态仍由既有 Runtime 管理。没有覆盖旧 Basis、TaskPlan、ACG 或执行结果。
- SQLite 语义提交、决定写入和幂等 Run 插入使用 BEGIN IMMEDIATE；正式 Revision 仍有 CAS。后继创建在写事务中重新校验 Mission 当前版本、最新决定、活动 Mission 和已取消且未删除的来源 Run，观察结果本身不冒充跨存储原子快照。
- Memory 实现使用既有锁和拷贝边界；SQLite 的并发连接、过期/跨 Run/权限/终态/取消规划竞争在回归中覆盖。未发现本次新增的无保护正式写入或并行状态权威。
- Mission 初始化、语义提交与调度不是跨 Identity/Workflow/进程调度的 ACID；恢复依赖已持久化幂等键、Commit Receipt/Outbox 及同键重试。此次补齐两个既有调度入口，不新增全局执行租约。
- `mission_revision_decisions` 是现有 v1 语义 schema 的可选增量能力表，仍在同一个 WorkflowStore。显式 `enable_mission_semantics=True` 才调用增量 DDL；正常 `enable_existing_mission_semantics()` 仅校验/附接，不执行 DDL。
- 新增测试证明：旧 v1 无决定表时，读取和编辑正式语义仍可用；Revision API 明确返回 503，绝不自动建表。显式升级执行两次不改变既有 Mission、Run、Snapshot、Commit、Receipt、Outbox；注入建表失败后事务回滚，保留原 v1 且无半张决定表。
- Feature Flag 关闭的旧创建/运行与旧 Run 的兼容路径由隔离回归覆盖；未更改 flag 默认值，也没有隐式迁移或历史正式语义回填。
- 升级需由操作者显式执行并核查能力表；不应仅依赖 version=1 判断已具备 S00-04。旧二进制读取原表兼容，但不应对升级后的数据库执行不认识新历史表的 hard purge。

# 端边云资源注册中心：两张表重构设计

> 目标：把现有单表 `ResourceProfile`（`resourceType` 统一区分 7 类）重构为**两张表**——节点资源表 + Agent 注册表，并一次性迁移所有调用方。

## 1. 资源类型归并映射（7 类 → 两表）

| 现有 `ResourceType` | 归并到 | 说明 |
|---|---|---|
| `agent` | Agent 表 | Agent 实例 |
| `skill` | Agent 表（`capabilities`） | 作为 Agent 的能力标签 |
| `worker` | 节点表 | 工作节点（设备） |
| `model` | 节点表 | 模型服务节点 |
| `embedding` | 节点表 | 向量服务节点 |
| `tool` | 节点表 | 工具服务节点 |
| `mcp` | 节点表 | MCP 服务节点 |

## 2. 节点资源表（Node）

**静态能力 `NodeProfile`**：`nodeId` / `nodeType(worker|model|embedding|tool|mcp)` / `deploymentTier(端边云)` / `cpuCores` / `gpuType` / `gpuMemoryMb` / `memoryMb` / `maxModelParams` / `privacyLevel` / `dataZone` / `costPerUnit` / `labels` / `location` / `enabled` / `metadata(荣耀字段)` / `version`

**动态状态 `NodeSnapshot`**（心跳实时刷新）：`nodeId` / `observationSequence` / `observedAt` / `cpuUtilization` / `gpuUtilization` / `availableMemoryMb` / `queuedTasks` / `latencyMs` / `healthStatus(online|busy|overloaded|stale|offline)` / `lastHeartbeat` / `consecutiveFailures` / `metrics`

## 3. Agent 注册表（Agent）

**静态属性 `AgentProfile`**：`agentId` / `capabilities(含 skill)` / `requiredModelIds` / `requiredGpuMemoryMb` / `minPrivacyLevel` / `allowedNodeIds(节点白名单)` / `labels` / `enabled` / `metadata` / `version`

**动态状态 `AgentSnapshot`**（事件驱动心跳）：`agentId` / `observationSequence` / `observedAt` / `state(idle|busy)` / `nodeId` / `currentStepId` / `successRate` / `avgLatencyMs` / `avgTokens` / `healthStatus` / `metrics`

## 4. 迁移顺序（每步保持可构建）

1. **contracts**：新增 Node/Agent 合同（保留旧 `Resource*` 过渡，标记 deprecated）
2. **components/resource**：store / service / health / algorithms / registry / models 切到两张表
3. **components/scheduler**：binder / placement / scorer / service 迁移
4. **adapters + API + tests**：`resource_execution.py`、`agentos_v2.py`、测试
5. **前端**：`agentos.ts` 类型 + 3 个 Vue 组件（去静态化 + 端边云分段表单）
6. **Java 网关**：`AgentOsGatewayController`
7. **删除旧 `ResourceProfile`/`ResourceSnapshot`** 及兼容层

## 5. 关键机制（后续阶段落地）

- **分级心跳**：守护进程上报；端侧后台降频、云端固定频率；扫地线程 3× 超时→`stale`（不接新任务）、6× 超时→`offline`（广播下线事件）
- **故障迁移**：节点离线广播 → 绑定 Agent 标记待迁移 → 状态保存 → 重新注册 → 检查点恢复
- **自进化**：滑动平均成功率/耗时/Token 回写 → 自进化模块调调度权重
- **荣耀生态**：`metadata` 承载设备家族 / NPU 型号 / DLC 路径 / 魔法大模型层级 / YOYO Claw 标签

## 6. 风险

- 调度器 `scheduler/` 与兼容门面 `directory.py` 大量依赖单表模型，迁移需保持语义一致
- 心跳分级需新增状态机（当前仅单一 `heartbeat_timeout` + 自然过期）
- 前端 7 类徽章/注册表单需改为两表呈现

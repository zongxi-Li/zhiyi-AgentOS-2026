# N1.2 G2 Trace 预审任务书

2026-10-02。前置：G1 代码集中复审修正后通过；真实成功路径尚缺数据的验收继续登记。下一步先执行 G2-0 只读预审，不能因为 Trace 与资源用量都属于观察接口就照搬 G1 的简单字段策略。

## 1. 当前已核实链路

GET /api/agentos/v2/runs/{runId}/trace，Java getTrace 将可选 view 原样转发。Python get_trace 的 view 仅接受 workspace；load_run(readonly=True) → trace_store.export_json → 对 events 执行 _redact。export_json 的输出是 dict，不是 JSON 字符串。

生产 export_json 位于 apps/agentOS/src/components/auditor/governance/trace.py。信封字段为 runId、missionId、workflowId、domain、status、eventCount、events。默认导出全部已排序事件；workspace 过滤 runtime_event_classified 中 runtimeEvent 为 model.output.delta/model.activity 的记录，但 eventCount 仍是 len(run.trace)。**保留 eventCount 原语义，不擅自改成过滤后列表长度；不得再次过滤、排序或截断。**

前端 workflow.ts getWorkflowTrace / exportWorkflowTraceMarkdown，api/acg.ts 的聚合，以及 workbench/runtime/observation.ts 对 event.payload 的广泛读取均为审计范围。当前 payload 是开放 Record，消费者包括失败恢复、交互、工具、规划进度和模型输出，不能只保留 message/status 就声称兼容。

## 2. G2-0 必须交付

只读源码、既有脱敏 fixture 和授权既有数据；只写文档，不修改实现、不部署、不启动 Run。

1. 完整 Query 入口、两种 view、事件模型字段与类型、事件类型集合。区分当前生产者、legacy、测试模拟、SSE 事件，不根据 enum 名称猜生产形状。
2. 每种被查询消费者读取的事件：producer → wire path → frontend consumer → 展示行为 → 目标字段/类型。跨 api/acg.ts、observation.ts、组件继续追最终读取，不能停在转发入口。
3. payload 的所有实际读取键，以及嵌套列表/对象/fieldsByProducer 等动态键冲突；形成 old/new/consumer 表和复现样例。对象/string/数字/布尔的归一必须依据具体读取函数，不统一 stringify。
4. 字符串字段也要审计：observation、payload.message、错误文本、工具/模型输出是否混入 TaskPlan、constraints、binding、checkpoint、prompt 或内部路径。白名单键并不自动保证白名单内容安全。公开用户正文与内部控制数据要有可实施的区分依据，禁止盲删正文或用正则猜语义。
5. 目标 typed TraceQuery / TraceEventQuery 与有限详情 DTO/union 的设计，保留可兼容的 payload wire 键名；若有限 DTO 无法保留既有动态键展示，给出最小前端适配方案与影响，不擅自扩大 Role JSON 例外。
6. 未知事件策略：保留安全公共身份/时间/类型及可证明公开的摘要，未知 payload 不透传；不能使整个可用 Trace 因新增事件类型失败。坏的必有信封结构应 contract invalid，未知事件与结构损坏分开处理。
7. 测试矩阵、分批迁移方案、守卫注册点、成功路径验收条件与现有数据阻断。

输出 docs/N1.2-trace-projection-preaudit.md，附源文件位置和删改依据。若展示依赖控制面数据，明确列为待裁决冲突，而非隐瞒为“无消费者”。预审完成后交回集中复审，**本任务不授权 Trace 代码迁移**。

## 2. 背景与问题

本轮修改前，系统已经具备 ACG 图、任务规划、运行轨迹、角色能力包和报告展示等组件，但组件之间存在契约断点，导致界面上看似启用了 ACG，实际演示时却可能出现以下问题：

1. 律师任务只执行部分节点，没有形成完整合同审查流程。
2. 规划器只读取任务目标，忽略执行约束和预期交付物。
3. 能力名称、稳定能力 ID 与运行时 Agent ID 不完全一致，造成能力漏选。
4. 模型返回格式合法但内容为空时，流程仍会继续，最终生成空风险报告。
5. 风险清单存在，但报告风险汇总可能全部为 0，签署结论与风险事实矛盾。
6. 条款分类节点已经执行，但报告没有收到分类数据，仍显示“未生成条款分类”。
7. 联网开关虽然存在，但律师报告没有稳定形成可展示的公开证据链。
8. 工作台对律师任务仍使用通用默认目标和交付物，无法稳定触发完整链路。

这些问题的共同根因不是单一页面故障，而是“用户意图—任务契约—能力规划—数据依赖—运行恢复—最终交付物”之间没有形成闭环。

## 3. 第一性原理与验收标准

### 3.1 ACG 演示闭环的最小构成

一次有效的 ACG 演示至少必须满足：

1. 用户输入被转化为完整、稳定的任务契约。
2. 规划器依据契约选择正确能力，并生成可执行依赖图。
3. 每个节点收到其声明的输入，并输出满足契约的结构化产物。
4. 运行中出现证据缺口或契约异常时，能够触发有界恢复。
5. 最终报告必须由真实上游产物生成，不能与风险、证据和审核结果矛盾。
6. 界面能够展示初始图、动态图变化、运行状态和最终 Markdown 交付物。

### 3.2 轻量化边界

本轮没有复制《完成稿》中的全部生产级能力，而是保留最能体现 ACG 的核心机制：

- 完整任务契约；
- 动态能力规划；
- 稳定能力绑定；
- 低熵上下文投递；
- Evidence 缺口检测；
- 运行时子图修复；
- 人工审核门；
- 数据血缘与审计；
- 最终 Markdown 报告。

对于暂未建设的正式法律知识库、权威法条校验和生产级法务审核，系统采用公开网页检索、本地演示资料与明确免责声明进行轻量补齐，不将其伪装为正式法律意见。

## 4. 修改内容

### 4.1 通用 ACG：补全任务契约

修改位置：

- `agentOS/src/agentos/core/runtime.py`
- `agentOS/src/agentos/core/planning/intent_parser.py`

主要修改：

1. 规划输入不再只包含 `taskGoal`，同时纳入 `constraints` 和 `expectedArtifacts`。
2. 能力匹配同时检索稳定能力 ID、显示名称和别名。
3. 保留稳定 ID 作为跨界面、能力包和运行时绑定的统一标识。

效果：任务目标较短时，规划器仍能从约束和交付物中补齐必须执行的能力，避免只生成局部流程。

### 4.2 律师 ACG：补齐完整合同审查链路

律师默认任务目标调整为：

> 完整审查合同：解析合同并进行条款分类，识别风险，联网核验法律依据，生成修改建议、人工审核要点和最终合同审查报告。

默认交付物调整为：

- 合同审查报告；
- 风险清单；
- 条款修改建议。

由此可以稳定选择以下 7 个基础能力：

1. 合同文本解析；
2. 条款分类；
3. 风险识别；
4. Evidence 依据匹配；
5. 修改建议生成；
6. 人工审核；
7. 审查报告生成。

### 4.3 空风险结果的可审计兜底

原行为：模型返回结构合法的 `risks: []` 时，系统将其视为成功。

修改后：

- 只对合同中明确出现的高风险表达执行有限规则检测；
- 识别付款与验收脱钩、默示验收、数据披露、单方解除限制、单方变更等明确条款；
- 每条补偿风险标记 `detectionSource=explicit_clause_rule`；
- 模型元信息标记 `source=llm+deterministic_guard` 和 `empty_output_repaired=true`；
- 非法 JSON 仍然按失败关闭处理，不使用规则伪造完整分析结果。

该机制只用于避免“明显有风险条款却生成空报告”，不会替代正式律师判断。

### 4.4 风险汇总一致性

原行为：报告直接信任上游 `risk_summary`，可能出现风险条目存在但汇总为 0 的矛盾。

修改后：

- 最终报告以实际 `risks` 列表作为唯一事实源；
- 在报告生成阶段重新计算高、中、低风险数量；
- 签署结论使用重新计算后的高风险数量；
- 增加风险列表、风险汇总和签署结论的一致性测试。

### 4.5 条款分类数据依赖

原行为：条款分类已经执行，但报告节点没有直接消费其输出，低熵上下文投递时报告看不到 `clauses`。

修改后：

- 报告能力显式依赖条款分类能力；
- 固定律师 Workflow 增加 `classify_clauses → report_generate` 数据输入；
- 报告 Agent 同时兼容动态步骤 ID `clause_classify` 和固定步骤 ID `classify_clauses`；
- 增加“报告不得显示未生成条款分类”的回归断言。

### 4.6 联网证据链

联网开关开启后，律师 Evidence 节点会：

1. 根据风险标题、合同类型和法律主题生成检索请求；
2. 检索公开网页；
3. 将网页标题、URL 和引用文本绑定到对应风险；
4. 在最终 Markdown 报告中生成可点击链接；
5. 网络失败或超时时回退本地资料，并明确标注需要人工复核。

联网关闭时不会调用公开网页检索，保持用户选择可控。

### 4.7 工作台展示修复

- 律师能力包选中后自动填充完整审查目标和正确交付物。
- 任务材料统计使用律师合同正文长度，不再错误显示 0 字。
- 历史运行继续使用冻结的能力包和 Run ID，避免查看历史时发生能力漂移。
- 最终交付物直接以 Markdown 渲染，表格、标题、列表和链接可正常显示。

## 8. 当前能力边界与风险

1. 公开网页检索结果不等同于权威法律数据库，正式使用前必须由专业人员核验。
2. 确定性规则只覆盖少量明确风险表述，不应扩展为不可解释的规则专家系统。
3. 模型可能对同一条款给出不同风险等级，系统保证的是数据一致性和可审计性，而不是法律结论绝对一致。
4. 当前实现适合产品演示、流程验证和架构说明，不构成正式法律服务。
5. 《完成稿.docx》本轮采用结构化内容读取；当前环境缺少 LibreOffice，未执行 146 页文档的逐页视觉渲染校验。

## 9. 建议的四分钟演示路径

1. 进入 ACG 页面，新建任务并选择“法律能力包”。
2. 展示系统自动填充的完整审查目标和三类预期交付物。
3. 粘贴演示合同，保持“动态规划”和“联网检索”开启。
4. 启动 ACG，说明初始图包含 7 个律师基础能力。
5. 运行到 Evidence 节点时，展示证据缺口事件和 v1 → v2 的受控子图调整。
6. 展示 9/9 完成状态、动态图摘要和数据血缘。
7. 查看 Markdown 报告中的条款分类、风险汇总、风险清单和联网链接。
8. 以免责声明和签署前结论收尾，说明该版本已经完整体现轻量 ACG 的规划、执行、恢复、审计与交付闭环。

## 10. 结论

本轮没有通过静态假数据模拟 ACG，而是修复了影响真实执行的任务契约、能力标识、数据依赖、风险一致性和报告链路。最终版本能够在通用 ACG 基础上显式加载律师能力包，并以轻量方式完整演示动态规划、联网取证、运行时恢复、人工审核和 Markdown 交付。

当前版本已经满足完整走通产品演示流程的目标。

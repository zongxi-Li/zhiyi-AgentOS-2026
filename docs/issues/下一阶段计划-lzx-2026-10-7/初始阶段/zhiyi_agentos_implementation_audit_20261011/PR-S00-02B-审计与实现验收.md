# PR-S00-02B：Workspace 语义展示与查询收敛

## 基线与只读审计

基线：`5690bb40`，2026-10-11，开始时工作区干净。先审计真实查询与显示链路，随后按已确认的“当前 View / Run 冻结 Basis”边界实施。

审计发现：

1. `IdentityQueryService.mission_workspace → MissionWorkspaceProjector` 从 Identity 仓库构造只读投影；`mission.md` 的标题直接使用 `Mission.goal`，不读取 Semantic Store。
2. HTTP Workspace 查询在完整 Identity 图之外，还有延迟规划 Runtime 外壳，以及运行状态/历史合并；只有在合并后附加语义视图，才能统一这几条展示路径。
3. 前端侧栏、Mission 文档、任务面包屑、运行进度标题和文档兜底直接使用 `projection.mission.goal`。仅替换文档标题不能收敛这些读取。
4. 现有 Identity owner 检查仅在存在可信 actor 时执行；不能凭该检查为新增正式语义读取授权。新增语义读取必须通过既有 Semantic Service，使用当前可信主体逐次校验权限。
5. Runtime Run 的 `executionState.missionIntentBasis` 已由 S00-02A 冻结；Workspace 不应调用 freeze，更不能为历史 Run 捕获当前 revision。

遵循 ADR-0001/0002 及后续明确合同：不从 input/title/Identity goal 初始化正式语义；当前语义与 Run 历史依据分开；只读投影不成为状态拥有者。早期审计文档中 bootstrap 设想不覆盖后续已确认合同。

## 最小接入与数据流

```text
可信请求 Context
  → Semantic Service 当前 read 授权
  → EffectiveMissionSnapshot → 纯 MissionSemanticResolver → MissionSemanticView
  → 既有 Identity Workspace / Runtime 外壳与历史合并
  → 读取所选 Runtime Run 的已持久化 Basis（不调用 freeze）
  → 只读 Workspace DTO / 虚拟 mission.md
  → 前端当前 Mission 展示与历史 Run 展示
```

新增可选 DTO：

- `missionSemanticView`：正式当前状态、Objective、Constraints、missionRevision、Commit 与来源引用状态。
- `missionDisplay`：展示目标与来源，不回写 Identity；初始化后只使用正式语义，未初始化时按 Identity compatibility goal → Legacy input → Legacy title 选择，明确非正式。
- `selectedRunBasis`：原 Run 冻结依据副本；包括目标、约束、sourceRevision、Commit、指纹与来源状态。
- `selectedRunBasisStatus`：BOUND / UNBOUND / RUNTIME_UNAVAILABLE / NO_RUN。旧 Run 不回填；没有运行记录时不从 TaskPlan metadata 推断完整 Basis。

保留原 `mission.goal` 作为旧 Identity 合同字段，不覆写、不持久化派生目标。当前前端所有 Workspace 目标别名读取统一经过展示函数，正式 View 优先；所选 Run 的任务/进度标题使用历史 Basis，未绑定或不可用时明确标注。

Mission revision 与 Run sourceRevision 不同时仅提示历史差异，不宣称 Run 已失效，不触发重规划。来源引用保持 UNVERIFIED / NOT_APPLICABLE；没有来源可用性、事实核验或 Memory Overlay 承诺。

## 权限、删除和异常边界

- 沿用 S00-02A 的显式启用装配；只有注入 Semantic Service 时新增语义读取。关闭时保留旧 API 数据形状，前端标注兼容展示、未读取正式语义。
- 每次请求从可信 Context 获取主体，经过既有 Service owner/tenant 授权；缺失主体或拒绝授权返回 403，不显示旧 goal 兜底。
- 缺失 Mission 返回 404；语义/Run Basis 校验失败返回 503，不切换成兼容目标。
- 软删除 Mission 或所选 Run 返回 404；内部语义历史保留规则不变。
- Identity 查询与 Runtime Run 检查继续验证 Mission 归属及既有可见性；新的投影函数校验 Mission、Basis 与选择状态一致性。
- 不改 IdentityV2 Schema/Projection，不改生命周期消费者，不写 Semantic 或 Lifecycle Outbox，不执行任何业务库迁移。
- Snapshot 与所选 Run 是两个读取时点，不宣称跨实体或跨 SQLite 文件的原子一致快照；当前 View 是一次已提交语义读取，Basis 是历史持久化依据。

## 限制及后续

- 启用前仍需独立安装 S00-01 Schema，沿用 S00-02A 显式开关；本轮没有安装到业务库。关闭时不能宣称正式展示已生效。
- 项目列表、其他 Identity 查询端点仍保留旧 goal 合同；本轮只收敛 Workspace 及其直接展示消费者，不把所有 Identity 查询升级成正式语义根。
- Workspace 入口仍要求 Identity Mission 可查询；缺少 Identity Mission 投影时保留既有不可用行为。Runtime Run 尚未投影的外壳已覆盖。
- 旧客户端只读 mission.goal 仍可能展示兼容内容；新客户端明确读取新增 DTO。不回写 Identity goal 掩盖该兼容边界。
- 不提前实现 Decision Resolver、Planning Commit、Graph Activation、Memory Overlay、Effect Ledger、Artifact Version System 或公开语义编辑 API。
- 当前与历史读取可能跨时点；失效 Fence、规划承诺版本准入属于后续 S02/S03。

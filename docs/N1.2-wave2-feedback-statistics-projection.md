## 一、端点与调用链

| 端点 | Controller → Service | 旧响应 | 新响应 |
|---|---|---|---|
| GET `/api/feedback/user/{userId}/statistics` | #getUserFeedbackStatistics → getFeedbackStatistics(requireCurrentUserId()) | `UserFeedbackService.FeedbackStatistics`（Service 内部类，Map 动态键） | `UserFeedbackStatisticsQuery` |
| GET `/api/feedback/statistics` | #getGlobalStatistics → getGlobalStatistics() | `UserFeedbackService.GlobalFeedbackStatistics` | `GlobalFeedbackStatisticsQuery` |
| POST `/api/feedback` | #submitFeedback → createFeedback(...) | `Map<String,Object>` = {message:"反馈已提交", feedbackId} | `FeedbackReceiptQuery`（同形 record） |

路径参数仅为兼容保留、身份只认 SecurityContext 的既有语义未动（用户统计与列表同规则）；POST 仍使用请求体 userId 直传（命令语义未改）。

## 二、字段兼容表（结构变化登记）

统计端点标量字段同键同型同值；变化仅在分类计数的承载方式：

| 字段 | 旧 wire | 新 wire | 说明 |
|---|---|---|---|
| userId / totalFeedbacks / averageRating | 同名标量 | 原样保留 | totalFeedbacks=long、averageRating=double |
| averageRating 空数据取值 | 0.0（Service 把 null AVG 改写 0.0） | **0.0 原样保留** | 批内决策：不改 null/缺省，DTO 注释说明既有语义 |
| feedbackTypeCount | `Map<String,Long>` 动态键 | `List<{type,count}>` | 按分类键字典序（String.compareTo）输出；自定义分类原样保留 |
| sentimentCount | `Map<String,Long>` 动态键 | `List<{type,count}>` | 同上；null sentiment 仍被 Service 过滤（既有行为） |
| 空统计 | 两个 Map 为 `{}` | 空列表 `[]` | 同为封闭空容器 |

POST 回执：{message:"反馈已提交", feedbackId:UUID} → `FeedbackReceiptQuery(message, feedbackId)`，字段名、类型、文案与 HTTP 200 逐项一致（序列化测试以"旧 Map JSON 树 == 新 record JSON 树"证明）。

排序决策：旧 Map（HashMap）输出键序不确定，新列表固定为分类键字典序，属登记内的确定性化，无消费者依赖旧序。

- 新增 `projection/feedback/dto`：CategoryCountQuery(type,count)、UserFeedbackStatisticsQuery、GlobalFeedbackStatisticsQuery、FeedbackReceiptQuery；新增 `FeedbackStatisticsProjectionMapper`（纯输出适配：Map → 字典序列表；不 import service/repo，无副作用）。

# N1.2 Phase 1 第一批：Identity Boundary

## User 输出兼容表

覆盖 GET `/users/me`、GET `/users/{userId}`、PUT `/users/{userId}`、POST `/users/{userId}/avatar`。写接口仅对已有 Service 结果做输出映射；请求体、修改行为、认证判断、HTTP 状态与错误处理不变。

| old field | new field | frontend consumer |
|---|---|---|
| id / username / email / avatar | 同名、同类型 | `services/api/user.ts`、`stores/user.ts`，资料编辑与头像流程 |
| createdAt / updatedAt | 同名 LocalDateTime，沿用原 Jackson 时间配置 | User API/Store 读取 createdAt；未确认 updatedAt 的专门展示消费者 |
| passwordHash | 删除，不属于 Query DTO | 前端 User 类型没有此字段，源码未发现消费者 |

保留两个读取接口现有 email 可见性，不增加本人/他人差异权限；该权限策略不属于本批迁移。Entity 仍在业务内部和既有更新请求中使用，不能作为 Controller 响应。Mapper 只调用 Entity getter 并构造 UserQuery，不读取 credential、不查询、不写入。

User 验证包含完整字段白名单序列化、GET/PUT/avatar HTTP 响应、DTO body 类型及现有 400/404。Role 与身份架构守卫在后续独立批次追加，本文不代表其他 Query 域已经迁移。

User 批次验证：相关测试 57 项通过；完整 `mvn -B -ntp test` 309 项通过，0 失败/错误/跳过（含现有数据库、缓存与 MVC 集成测试）。编译目标为 Java 17，本机 JDK 21。未执行真实浏览器验收。

## Role 输出兼容表

覆盖 builtin/custom 列表、cached detail、context，以及创建/更新的已有返回值；路径、Service 调用、缓存 owner、权限、状态码（含创建 201）、异常捕获不变。

| old field | new field | frontend consumer |
|---|---|---|
| id/name/description/roleType/systemPrompt | 同名、同 JSON 标量类型；roleType 改独立公共 enum | `services/api/role.ts`、角色 Store、创建/编辑 dialog |
| userId/stableKey/createdAt/updatedAt | 同名、同 JSON 类型 | 保留现有身份与时间字段；未确认专门 UI 消费者 |
| dialogueStyle/personality/avatarConfig | 同名、原 JSON 对象形状与自定义键保留；内存表示改独立 typed RoleConfigurationQuery | `EditRoleDialog.vue` JSON stringify 回填再提交；`CreateRoleView.vue` avatarConfig.colors/style；相关自定义角色消费者 |
| context.role_id/system_prompt/dialogue_style/name/description/personality | 保持蛇形/原字段名与 JSON 形状；外层明确 RoleContextQuery | 未发现前端直接调用 context 的消费者，保留现有协议 |

配置边界按用户澄清保留可扩展 JSON，仅允许在 Role 的三处既有配置槽（context 复用其中两处）。RoleConfigurationQuery 保存不可变 typed Property/Value，值限定 text/decimal/boolean/null/array/object-properties；无 Map/Object/JsonNode 字段，不保存 Entity。专用序列化写出原 JSON 对象，不是把 JSON stringify 藏进 String；也不采用 JsonAnyGetter 或自动字段拷贝。外层身份/上下文始终白名单构造，未知外层字段不传播。该局部配置值类型不得作为其他 Query DTO 的通用 metadata/payload 扩展。

输入 RoleCreateRequest 与数据库自由 JSON 不改；Mapper 只从已有 Role 或 getRoleContext 结果复制有限 JSON 值，不调用 Service/Repository/Runtime/缓存。不用固定配置键丢弃自定义数据，不改变角色编辑流程；其他 Query 域没有新增代码。

Role 批次验证：相关测试 65 项通过；完整 `mvn -B -ntp test` 317 项通过，0 失败/错误/跳过。包含已有 RoleIntegrationTest 与 Redis/数据库集成测试。测试确认 HTTP 结果和配置序列化兼容，未执行浏览器中的角色编辑实测。

## Identity serialization guards

新增 IdentityProjectionArchitectureTest：扫描真实 Controller handler，禁止直接/嵌套 User、Role 返回；对 User/Role 响应和 DTO 闭包额外禁止 Map、Object、JsonNode、内部类型、raw/wildcard、未批准的自定义序列化。实体请求输入不在输出守卫范围；其他 Query 域的历史 Map/Entity 本批不迁移。

配置树只允许 RoleQuery 的 dialogueStyle/personality/avatarConfig 与 RoleContextQuery 的 personality/dialogueStyle，其他 Projection 槽不能借它承载 metadata/payload。守卫检查 sealed value 子类、字段与 getter，含负例证明包 Entity/动态 DTO/配置扩散会失败；不因工作目录错误跳过。Mapper 另检查基础设施依赖、自动字段转换和状态修改调用。

新增参数化 credential guard：null、空、真实哈希式字符串和敏感字段名值都不触发 credential getter，不输出 passwordHash；UserQuery 字段白名单固定。此守卫只覆盖本批已经迁移的身份响应，不宣称全仓 Query 已隔离。

第三批验证：定向测试 61 项通过；最终完整 `mvn -B -ntp test` 327 项通过，0 失败/错误/跳过。最终 `mvn -B -ntp package -DskipTests` 成功生成 Spring Boot 包，打包复用此前完整测试结果。未部署该包，未执行真实浏览器或线上请求验收。

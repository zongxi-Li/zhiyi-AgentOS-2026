# N1.2 H 批 outputs 查询预审

2026-10-02。只读预审：仅提出 typed 内容与兼容方案，不实现、不修改前端。随 G2-0 一并交回集中复审。

## 0. 结论

1. 两个端点：`GET /runs/{runId}/outputs/{outputRef}`（活跃，前端聚合每输出引用逐一消费）与 `GET /runs/{runId}/legacy-outputs`（**前端零消费**，纯前-identity 兼容端点）。
2. `content` 是**用户产物正文**：模型按 `output_spec.properties` 合同产出、白名单键过滤后落执行值仓库，构造上没有内部控制数据的注入通道；但键集按节点能力动态（report 类字符串键、`artifacts.<capability>.*` 动态路径、artifact 清单封套），且历史存量 payload 不受当前白名单约束。
3. typed 方案与 Trace payload 同构：信封 typed + 已知键 typed + extras 键值列表（与 Trace 共用 `TracePayloadEntry`，一次实现两处受益）。是否迁移、何时迁移随 G2-0 裁决一并定；若 content 表示暂不裁决，最小替代是先迁形状封闭的 legacy-outputs、`/outputs/{ref}` 缓行。

## 4. content 正文审计

- **是用户产物正文**：模型按 output_spec 合同产出、白名单键后落库。审计元数据（modelInvocations/memoryAccess 等）走 trace 与节点结果，不进 content；prompt 不经此通道。
- **artifact_generation 封套键**（`artifact`/清单引用）由 `_persist_artifact_manifest` 注入，属"已知键"。
- **动态性来源**：各能力 output_spec.properties 不同（`report_generate.report_markdown`、`risk_detect.risks`、`legal_evidence_match.evidences` 等），无法静态枚举全部键；已知消费路径集中在顶层报告类字符串键与 `artifact`/`artifacts` 子对象。
- **风险登记**：值仓库历史 payload 无 schema 迁移——存量 run 的 content 键集不受当前白名单约束，mapper 不能假设"白名单=实际键集"。`[redacted]` 问题在此端点不存在（`_redact` 只作用于 /trace 导出）。

## 5. typed 方案建议（待裁决，随 Trace payload 一并定）

```
OutputQuery(runId, outputRef, content)
  — runId/outputRef: requiredText；content: 输出负载（同 Trace payload 表示）
LegacyOutputsQuery(runId, items)
  — items: 必有列表；行 = {stepId, name, status, content}（全 requiredText + content 负载）
输出负载（推荐）：已知键 typed（顶层 final_answer/report_markdown/report/final_report/content 字符串键、
  artifact 子对象 typed、artifacts 字典化受限）+ extras: List<TracePayloadEntry>
```

- 错误语义保持：404 透传；无分页参数；`AgentOsPaths.output` 已做 segment 编码，不动。
- 守卫注册：`AgentOsArtifactController` 两 handler 纳入 strictOutputChecked（仅迁移哪些由裁决定）。
- 最小替代（若 content 表示暂不裁决）：仅迁 legacy-outputs（形状封闭：4 个 requiredText + content 负载仍需定，故实际仍受同一裁决约束；或整批缓行——本预审不替评审决策）。

- 错误路径可活体验收：不存在 run → 404、跨账号 → 404（identity 归属校验）；不存在 outputRef → 404 "output not found"。

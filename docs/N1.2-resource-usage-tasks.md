## 1. 范围与不变量

仅迁移 AgentOsObservationController 两个查询：

| Handler | 路径 | 原参数 |
|---|---|---|
| getResourceUsage | GET /api/agentos/v2/runs/{runId}/resource-usage | runId |
| getResourceUsageCalls | GET /api/agentos/v2/runs/{runId}/resource-usage/calls | runId、stepId、cursor、pageSize（默认 20） |

保留参数转发、权限获取、HTTP 状态和既有 QueryError 格式；分页与过滤仍由 Python 处理。不要在 Mapper 中重新分页、排序、计算用量、推算费用或调用任何存储/Runtime。禁止修改 Python、schema、调度器、运行图、Checkpoint Store。不要顺带迁移 trace、history-config、memory、provenance 或资源注册接口。

## 2. 开工事实核对（G1-0）

逐层追踪 Java handler → AgentOsClient → Python `agentos_v2.py` 的 `get_resource_usage` / `get_resource_usage_calls` / `_model_call_projection` → 前端实际读取。提交前形成 old field / new field / consumer 表、脱敏 fixture 与异常类型策略。

已核对的入口消费者：AcgVisualizationView、ResourceSidebarView、RunResourceStrip、AcgResourceInspector；calls 的分页入口在 agentos/api/runtime.ts。不能仅凭 TS 接口决定白名单。

现有总览顶层为 runId、capability、capabilitySource、outputPolicy、usage、contextPressure、composition、scheduler。Python calls 每行还含 capability，但 TS ModelCallUsage 未声明它；必须核对真实消费者后决定保留的 typed 公共能力字段，不得直接转发这个 dict。

**scheduler 处理已定：删除整个对象，不改名转移内部状态。** 当前生产前端未读取 resource usage 的 scheduler；acg.ts 是声明，AcgCapabilityPanels.spec.ts 是 fixture。AgentOsRunSummaryCard 的 checkpointCount 是另一个组件 prop，不能据同名推断该 API 有消费。G1 开工再次全仓核对，若新增真实消费者则上报具体位置，禁止静默删掉其展示。记录四个旧子字段 activeSlots/queueDepth/checkpointCount/recoveryCount 均变为缺席。不要影响其他已批准的公共计数契约。

capability.features 是动态键风险：枚举生产者、字段类型与消费者，选择有限显式字段或删除未消费键；禁止新增 Map/JsonNode/Object 或扩展 Role 的自由 JSON 例外。遇到真实兼容冲突先给出样例与可选方案。

## 3. DTO 与 Mapper

放在 projection/resource/dto 与 mapper，采用显式 record/字段，不继承内部模型。顶层实现 QueryResponse，错误复用既有类型。

建议 RunResourceUsageQuery + ResourceCallPageQuery，共享 TokenUsageQuery、ModelCapabilityQuery、ModelCallQuery，另有总览 UsageSummaryQuery、ContextPressureQuery、CompositionQuery。名称可调整，字段必须来自核实后的白名单。现有 run/ResourceUseQuery 表达资源绑定展示，语义不同，不强行复用。

usage 保留上游已计算的 token 数、callCount、retryCount、latencyMs、cacheHitRatio；contextPressure 保留公开压力值、token 计数与 source；composition 保留公开材料/任务/产物计数、完成状态与 taskProgress。calls 保留公开调用标识、模型/供应商、时间、耗时、typed usage、结束原因与已消费的输出策略/额度/压力信息，逐字段记录未消费键的处置。

精确计数用可承载现有范围的整数类型与 exact 转换，禁止 int/long 截断、浮点钳制；比例只接受有限数，异常值不得制造 Infinity/NaN 或伪造 0。null/缺席是否保留按真实 wire 与前端判空逐项登记；结构坏载荷走既有 contract invalid，正常无调用的 0 与未观测 null 要区分。所需集合缺失不得默认成正常空数据，分页 nextCursor 原样，不自行解析重写。

## 5. 验证门槛

- 序列化键集闭包、嵌套 capability/usage 白名单、内部 SECRET 哨兵不可达；根及嵌套结构缺失/错型不能伪造成功。
- 无调用/声明能力、真实 observed 用量、混合多调用、可选值、计数边界、非有限比例、未知内部键；样例须追溯生产者，不构造不可能的期望。
- Controller：路径/参数/200 DTO、非 2xx 透传、坏载荷 contract invalid、不回显内部载荷；calls stepId、cursor、pageSize 原样转发，正常末页与空页保持语义。
- 全局守卫精确注册这两个 handler，DTO 无动态容器/内部类，Mapper 无 I/O/状态修改；不要仅凭方法名豁免。
- 部署本批 backend 后，使用授权可访问的既有 Run 验证总览和 calls 正常、筛选、分页、空调用及不存在/跨账号错误；浏览器查看资源面板与加载更多。不得为验收启动新 Run、猜密码或改归属。缺数据则明确登记成功路径未执行。
- 验收基线要包含本轮 Workspace 修正；顺便补 Workspace item 与 Artifact detail/fragments/download 成功路径，但仅在有授权既有数据时进行。

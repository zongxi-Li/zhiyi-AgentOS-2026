上下文倾倒
上游结果全量传给下游，token 成本高，重要字段容易被噪声淹没。
→
字段契约通信
COMMUNICATION 边声明 input.fields，ContextAssembler 精准组装 ContextPack。
过程不可追踪
只看到最终答案，看不到步骤、证据、模型调用、人工审核与数据来源。
→
Trace 黑匣子
TraceStore 记录 STEP_STARTED、DATA_CONSUMED、CHECKPOINT_CREATED 等事件。
失败只能重跑
模型超时、证据缺失、Agent 崩溃时，缺少局部恢复和复盘依据。
→
Checkpoint 自愈
故障注入、步骤重置、恢复轨迹与检查点快照组成可演示的韧性闭环。

三个核心设计

规划、执行、通信在 ACG 中闭环

演示时重点讲这张图：用户意图先变成 ACGBlueprint，再由执行器调度 Step，最后通过字段契约完成低熵上下文投递。

ACGBlueprint 6 类节点 + 7 类边
多智能体任务的结构化 IR
1

Planning

IntentParser 解析目标，TemplateMatcher 静态优先，forceDynamic 时由 ACGBuilder 生成差异化任务图。

PlanningEngine.plan(force_dynamic=True)
2

Execution

ACGExecutor 根据依赖与控制节点计算 ready_steps，支持并行就绪集、故障注入和 Checkpoint。

ACGWorkflowAdapter · ACGExecutor._drive()
3

Communication

COMMUNICATION 边携带 dataFields，下游 Step 只获得 input.fields 声明的必要字段。

ContextAssembler.assemble()
4

Governance

Trace、Provenance、Review、Recovery 让图执行过程可以被展示、复盘和审计。

TraceStore · ProvenanceLedger
Core innovation: Graph IR + Runtime Harness + Low-Entropy Context
低熵通信

让 Agent 只接收真正需要的字段

这张图适合配合右侧“低熵通信指标”面板讲解：节省 token 的来源是字段级上下文投递，不牺牲数据血缘。

Agent A 输出 { contract_summary, clauses, risks, evidences, metadata, ... } COMMUNICATION 边: dataFields = ["risks", "risk_level"] ContextPack: 只投递 risks + risk_level
22%+ 演示链路平均 token 节省率
字段级 按 input.fields 精准提取
可追踪 DATA_CONSUMED / DATA_PRODUCED
可审计 ProvenanceLedger 记录来源

数据血缘示例

contract_parse → clause_classify 消费字段：contract_type / payment_terms / scope
risk_detect → legal_evidence_match 消费字段：risks / risk_level / risk_score
revision_suggest → report_generate 消费字段：revision_suggestions / manual_review_focus

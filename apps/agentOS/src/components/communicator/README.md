# 通信器

通信器按已编译的 ACG 依赖与字段许可，将上游产物交给下游 Agent，并记录生产、消费和交互来源。它不决定业务步骤是否验收通过，也不创建图修订或重新调度 Agent。

## 一条正文路径

执行器通过 `CommunicationBroker.assemble_context()` 读取上游引用并组装 `ContextPack`。Agent 运行中通过 `CommunicationReader` 补读；Reader 只绑定当前 Run、消费节点及上游引用，实际读取仍进入同一个 Broker。`CommunicatorService` 负责消息封装和血缘记录，不再维护第二套正文读取或装配逻辑。

旧的 `assembler.py`、`algorithms.py` 和 `compressor.py` 已删除。通信器不按字符数截断文本，也不按字段名猜测价值后静默丢弃字段。

## 内容和来源

- `sourceData` 按生产步骤保存已授权、实际投递的原字段值。多来源同名字段各自保留。
- `data` 是供现有输入合同使用的兼容扁平投影；同名字段可能覆盖，完整来源以 `sourceData` 为准。
- `evidenceRefs`、字段名、校验摘要和读取统计进入血缘记录。读取事件不复制正文，产物原文仍由 Value Store 保存。

Broker 在读取前校验 Run、产物所属生产步骤、图依赖和字段许可。未授权字段不能因知道产物引用而被读取。必填输入缺失会明确标记为无效，不会制造空值来伪装完整输入。

## 大内容与预算

完整读取返回所请求字段的原值。显式配置的请求、节点、通道或运行预算不足时，Broker 报错，不用截断或摘要替代内容。`estimate_tokens()` 是统计估算，不是模型分词器的准确计费。

分页读取返回当前页和 `nextCursor`，剩余内容保留在原产物中。调用方沿游标继续读取，直到游标为空；不能把一页当作整个产物。无法在当前页预算中容纳的条目会报错，调用方需调整读取请求。

## 可靠引用与协作模式

SQLite 引用队列支持发布幂等、待处理查询和消费确认。`pending()` 默认返回该 Run、消费节点的全部待处理消息；只有调用方显式提供 `limit` 时才限制本次批次。

EVENT 和 BLACKBOARD 保留通知、快照等现有语义。DEBATE 的阶段变化由共享纯函数 `next_debate_phase()` 实现，独立协调器与执行器复用同一逻辑。这只统一阶段推进，不代表通信器已经承担完整的多轮 Agent 调度；业务审查、补充工作和图修订仍由审计、规划及调度链路负责。

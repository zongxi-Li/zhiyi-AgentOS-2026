## 1. 仓库入口地图

| 路径 | 当前职责 | 状态 |
| --- | --- | --- |
| `apps/agent/` | FastAPI 应用、API 路由、运行时装配和领域 Agent Packs。`app/execution/wiring.py` 创建 `ExecutionRuntime`，`app/main.py` 注册 AgentOS API。 | 应用接入层 |
| `apps/agentOS/` | AgentOS Python 内核，包括运行时、领域部件、契约、存储和 Agent 基础类型。 | 活跃源码 |
| `apps/local-runtime/` | 独立本地能力进程，按授权执行文件和进程能力；协议模型位于 AgentOS 的 `src/contracts/local_runtime.py`。 | 独立运行边界 |
| `apps/frontend/`、`apps/backend/`、`apps/desktop/` | 前端、产品后端和桌面宿主。它们不是 AgentOS Python 内核的一部分。 | 产品接入层 |

AgentOS 请求的入口和完整产品链路以根目录架构图为准；本表只标出仓库中主要应用的边界。

## 2. AgentOS 目录职责

| 路径 | 负责什么 | 阅读提示 |
| --- | --- | --- |
| `apps/agentOS/src/runtime/` | `ExecutionRuntime` 的任务准备、执行、审核、恢复和状态投影编排。 | `workflow_runtime.py` 是 ACG 运行时主入口。 |
| `apps/agentOS/src/runtime/v2/` | Mission、Task、Run、Attempt 等身份生命周期服务、查询投影和对账。 | 它不调度或执行 ACG 节点；真实执行仍由 `ExecutionRuntime` 负责。 |
| `apps/agentOS/src/components/` | 按业务能力组织的部件，如 `planner/`、`executor/`、`scheduler/`、`resource/`、`recovery/`、`communicator/`、`memory/` 和 `auditor/`。 | 部件内的 `models.py` 通常是该部件的类型或导入入口，不是全项目统一模型注册表。 |
| `apps/agentOS/src/contracts/` | 跨部件和跨进程传输的类型合同。 | 新增跨边界的数据结构优先放在这里；避免让消费者依赖另一个部件的内部实现。 |
| `apps/agentOS/src/domain/` | Mission、SemanticTask、Run、Attempt、StepExecution 等领域身份、生命周期和仓储接口。 | 领域实体与 SQLite 表结构不是同一层。 |
| `apps/agentOS/src/adapters/` | 模型、Agent、工具、检索和 Local Runtime 等外部能力适配。 | 外部实现应通过合同和适配器进入运行时。 |
| `apps/agentOS/src/storage/v2/` | Identity V2 的 SQLite schema 和仓储实现。 | 运行时工作流存储还包括 `src/support/stores/`，不要将两者混为一个存储层。 |
| `apps/agentOS/src/support/` | 运行时支持设施，包括工作流存储和现存的 ACG 共享代码。 | 其中 `support/acg/models.py` 职责过宽，是已记录的模块边界债务，见下文。 |
| `apps/agentOS/service/agents/` | Agent 基础类型、调用上下文和注册表。 | 这是 AgentOS 运行时会用到的源码目录，不是评测或草稿。 |
| `apps/agentOS/src/tools/` | ACG 导出、序列化和图形表示工具。 | 主要服务于展示和导出，不是执行器。 |

## 3. ACG 当前执行链

```text
apps/agent/app/main.py
  -> app/execution/wiring.py::build_default_runtime
  -> apps/agentOS/src/runtime/workflow_runtime.py::ExecutionRuntime
  -> ACGGraphCompiler
  -> ACGExecutionGraph.astream
  -> Scheduler / Resource 与 ACGNodeRunner
  -> Workflow、Checkpoint、ExecutionValue、Memory、Provenance、Audit 等存储
```

`ExecutionRuntime` 是实际执行的编排入口。ACG 蓝图经 `ACGGraphCompiler` 编译后，由 `ACGExecutionGraph` 推进就绪节点；节点工作交给 `ACGNodeRunner` 和相应适配器。当前 `ACGExecutionGraph` 是 AgentOS 内部实现，源码注明其改写了 LangGraph 1.2.10 的 StateGraph、channel 和 Pregel 调度思想；它不是直接调用上游 LangGraph 运行时。执行状态和 checkpoint 按引用保存，完整节点输入、模型输出正文放在独立的值存储中。

身份链与执行链要分开读：`runtime/v2/` 负责 Identity V2 生命周期、投影和查询，不是第二个执行器。需要查看端到端产品层时，回到[全系统架构图](../../../docs/02-架构设计/kinlin-agentos-current-architecture.md)。

## 5. 已知边界问题与文档状态

1. **`support.acg.models` 职责过宽。** 它同时承载 ACG 类型、图校验、规划辅助逻辑和内置能力目录；`AgentOS后续工作清单.md` 已将其列为边界收敛事项。该拆分是待办，不应误读为已经完成。
2. **执行器文档存在时间差。** 当前 `components/executor/graph.py` 说明它已在 AgentOS 内改写 LangGraph StateGraph/Pregel 机制；较早的后续工作清单仍写着不引入该机制。以当前源码描述实际执行，以日期和阶段识别旧计划；后续应把冲突的计划条目标为完成、替代或过期。
3. **有两个容易混淆的“当前梳理”。** `当前系统实现审查.md` 是 2026-08-11 的审查快照；本文是 2026-09-25 的目录与运行链梳理。后续更新本文时同步更新日期，并避免把旧审查中的 TODO 当成现状。

### 阅读顺序与事实来源

1. 判断一个模块是否现役：从应用装配和生产调用点追到具体实现。
2. 判断行为边界：查看对应测试；测试未运行时不报告为已通过。
3. 理解系统关系：查看根目录的全系统架构图。
4. 查阅设计计划和迁移报告时，先看日期、阶段和“已完成/待办”状态；如与当前源码冲突，先按当前代码描述，并登记文档待同步。

## 3. 独立发现的 P1 与最小修复

### P1-1：伪造未调用异常可被结算（已修复）

修复前 NodeRunner 信任异常的 not_invoked 属性与 AGENT_NOT_IN_SCOPE 错误码。独立反例先实际进入 Agent.run，再抛出伪造异常；assert_settled_operations 未拒绝，预期 raises 失败。问题在 Agent 异常传播边界，不是模型文本能定义新权限。

修复位置：src/adapters/agent_invocation.py:41-76、src/components/executor/node_runner.py:435。只在真实 registry 解析失败、尚未进入 Agent 时，在 Adapter 内登记异常对象和上下文。消费要求同一 Adapter、同一异常实例、同一上下文且只能一次；不再信任可写 not_invoked 字段。可信事实才写 FAILED/AGENT_NOT_IN_SCOPE；未知副作用仍保持 prepared WAL 阻断。

### P1-2：同头恢复漏检 receipt-only 切口（已修复）

子进程在 B 的 node.completed 事件处 os._exit(73)：receipt 已 committed，独立 NodeExecutionRecord 尚未 committed，Workflow 无 B 完成投影。修复前同头分支跳过 committed receipt，对账未拒绝。该场景不属于允许自动恢复的合同。

修复位置：src/runtime/permit_recovery.py:24-60。核对每份 receipt 与独立 NodeExecutionRecord、phase、operation/commit/run 身份及 Workflow 完成集合。promoted 前缀后的记录必须匹配当前 generation 与 Step attempt 的精确 operation/executionInstanceId。等头分支也检查；没有把不支持切口扩展为补造完成或重新调用。

### P1-3：Agent 已调用后 retryable 可重复整次副作用（已修复）

独立反例先实际执行 Agent.run，再抛普通 RuntimeError(retryable=True)。修复前 B 实际调用三次：`['B','B','B']`，预期仅 `['B']`。通用 retryable 不是未调用证明。

修复位置：src/components/executor/node_runner.py:438-452。Permit 图只有真实未调用证明才允许有界自动重试，每次保留调用前 guard；Agent 内部异常保持未知 WAL，拒绝自动整次重调。非激活 Run 保持原重试行为。安全重试尚在继续时不提前写 FAILED 终态。

旧 transport retry 测试的目标和全部断言保留；夹具从“Agent 内任意异常”改为真实 Adapter registry 未调用失败，验证可信边界上的重试与撤权。没有放宽旧断言。

## 4. 独立实验、身份与故障矩阵

新增永久测试：tests/components/planner/test_permit_recovery_final_audit.py，含参数化共 9 项。全部使用临时真实 SQLite；进程实验采用 Windows spawn/os._exit，不把 Python 异常当作进程死亡。

| 场景 | 实际命中窗口与证据 |
|---|---|
| Checkpoint committed、Run 未确认 | child 在真实 after_checkpoint_hook 中 os._exit(71)；断言头不同、Workflow 已有 A/B；新 Runtime 对账后仅执行 C/D，文件副作用日志 B 一次，旧 Worker Run 拒写 |
| Agent 已进入、结果未知 | child os._exit(72)，存在 prepared WAL，对账及执行 claim 拒绝，不自动重试 |
| Receipt committed、Workflow 无完成投影 | 独立 child os._exit(73)，明确断言 B receipt committed 且 Run 不含 B；对账拒绝、Run 不变、无新调用 |
| 两 Runtime 同时对账 | child 完成首次 _evidence 后 Event 停顿；父实际同时对账收到 OS Fence busy，非 sleep 猜测重叠 |
| 读取后操作员输入或取消 | 同一 Event 窗口，父通过正常 save_run 或 Runtime.cancel 写入；子最终事务完整 Run CAS 拒绝，保留输入/取消，不推进旧头 |

| 独立记录缺失/伪造/旧 generation | 删除 NodeExecution、改 attempt、同时改 receipt 和 record 的 executionInstanceId；均拒绝，Run 不变 |
| 未调用证明伪造/重放 | Agent 真进入后伪造错误码、属性和 retryable 不结算、不重调；不同 Adapter/context、二次消费均失败 |

既有关键测试在最终门禁重跑：Checkpoint 头/内容/版本/generation/Permit 投影损坏、node.started 后撤权、迟到 Head/binding/cancel/Identity 修改、部分 Identity 晋升、Checkpoint 成功 Identity 失败、Workflow rollback/ACK 丢失、原 Key 新进程重放、不同 Key 冲突，以及真实失败审核与显式 Retry。

Retry 路径为：B 可信未调用失败→真实审核拒绝→原系统显式同 Run Retry→独立 Runtime 重建→B/C/D 成功。Permit、AttemptGeneration 保持；旧失败 Attempt/StepExecution 不变，新 AttemptId/StepExecutionId 不同；旧失败 NodeExecution 改 COMMITTED 被终态保护拒绝；A 不重跑。普通节点审核批准只沿用当前 Permit，并由原审核链完成 deferred memory，不发放新 Permit。

_evidence（src/runtime/permit_recovery.py:63-157）要求 Checkpoint 等于已有 Workflow 执行投影，只允许确认 checkpointId 与清理已完成 active；完成集合精确一致，并对 Compiler 有效边闭合。promoted 前缀及引用不得退化。新完成节点必须具备独立 record、committed receipt、allow Audit Decision、真实 output/context、Provenance checksum/operation、Workflow success Trace、成功 Identity Attempt/StepExecution 与 Scheduler 资源绑定，全部归属当前 generation。不能由 Checkpoint 单独增加 completed。

最终事务内重验并不等于跨库联合 CAS：最终外库读取之后仍有独立库变化窗口。保证限定于同机受控写入协议，不宣称恶意直接 SQL 或分布式原子性。

## 6. 剩余限制与下一阶段合同

- 跨 Workflow、Checkpoint、Identity、ValueStore 无联合事务和跨机器持久租约；仅保证同机规范化路径与 OS Fence 协议。

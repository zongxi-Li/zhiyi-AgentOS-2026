## 3. 独立发现：未修复问题

### F1 / P1：正式Mission读权限撤销后，Artifact正文仍返回

**真实复现**：使用真实样例完成的Run、真实成功D Attempt与sealed Artifact；挂载原 `create_router` 和 `InternalServiceAuthMiddleware`，使用有效服务token及正确owner/tenant。随后把已注入的可信 `MissionSemanticService.authorize` 改为显式拒绝当前read授权。没有伪造客户端身份、删除权限检查或改动生产源码。

两项独立反例分别请求Artifact ID和Manifest ID，实测均为：

```text
workspace: 403
artifact fragments: 200
returned_fragments: 6
```

期望正文返回403/404，两项断言失败。原始命令与输出见 `tmp/c1_audit/independent.json`、`.log`，函数为 `test_revoked_formal_read_access_blocks_artifact_body[artifactId/contentRef]`。

**源码原因**：`agentos_v2.py:1559-1565` 的Workspace调用当前语义读授权；`:278 _require_access` 仅检查Run输入中的owner/tenant；`:733 load_run`和`:761 require_manifest_access`未重验正式Mission读授权。`:2644 get_artifact`及`:2658 get_artifact_fragments`沿用后者，因此在有效旧owner身份下仍返回正文。C1修复了ID映射，但没有解决这一权限差异。

**影响与定级边界**：这是显式装配支持的可信授权提供者撤销未传递到产物读取端点；不是“不同tenant可直接读取”（相应反例已拒绝），也不是跨机器执行撤销问题。默认应用当前owner型授权未提供独立撤权UI，不影响该注入式权限合同下的反例成立。属于C1集成暴露的既有查询缺口，不能归咎于Permit签发或宣称B2核心恢复被破坏。依据本轮“无权限Manifest/撤销引用不得绕过”的标准，P1未关闭，阻断ACCEPT。

**只提建议，不实施**：统一Artifact/Manifest与Workspace的当前Mission读取授权，在两种ID解析入口保持同Run、owner/tenant与正式授权并行验证；保留正向ID映射和历史查询语义，补永久权限撤销回归后再复验。

### F2 / P2：无效样例恢复会创建Workflow数据库

建立只含合法example.json的目录，调用 `open_runtime(folder, initialize=False)`。操作最终因缺少正式语义Schema拒绝，但失败之前实际创建：

```text

```

根因：样例:121只验证marker，随后:129调用SQLiteWorkflowStore；该Store构造器:51先执行_init_schema（:1031），再检查已有Mission语义Schema。恢复不是完全无副作用的只读预检。

不支持该目录时仍无Permit、Run或执行权，不等同任意生产目录覆盖；已有非样例目录和新建目录保护成立。因此定P2，不将该现象夸大为执行授权漏洞。建议未来先以只读方式检查必要文件/Schema，避免无效恢复产生数据库。未修改实现。

### F3 / P2：Artifact ID下载没有使用已解析的Manifest ID

对同一个真实成功Attempt生成的canonical产物，使用Manifest ID调用下载接口，200且正文非空；改用Artifact ID，元数据解析成功，但在响应正文生成时抛出：

```text
src/components/content/store.py:312
KeyError: 'unknown content manifest: artifact_7680de8c82e3'
```

根因：`agentos_v2.py:2792-2797`先通过`get_artifact`接受两种ID，却将原始请求参数传给`stream_assembly`；后者在`content/store.py:294`直接按Manifest主键读取。C1修复的fragments路径（:2667）已使用解析后的ID，download未同步遵守此映射。

永久修复未实施。受影响的是使用Artifact ID的下载别名；Manifest ID下载和两种ID的fragment查询正常。该问题是原查询代码的既有缺陷，在C1交付验收中被独立暴露，不是图执行权绕过或内容损坏，定为P2；F1仍是拒绝冻结的P1阻断。

Permit PREPARING没有执行权。Checkpoint与Identity晋升均可先提交，但只有 `execution_permit.py:191-217` 的最终Workflow事务同时提交ISSUED与Run投影后，执行入口才承认许可。表对key、handoff、activation有UNIQUE，_issue执行PREPARING/checksum CAS；进程锁不是最终唯一性证明。

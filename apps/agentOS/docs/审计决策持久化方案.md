# 审计决定仓库

> 创建（Git）：2026-08-14T22:49:24+08:00，WKN
> 最近一次 Git 修改：2026-08-14T22:49:24+08:00，WKN

ACG 节点的审计决定保存在独立 SQLite 文件中。环境变量 `AGENTOS_AUDIT_DB` 可指定路径，未设置时使用 `data/audit_decisions.sqlite3`。该文件不与工作流、检查点、输出正文、记忆或通信血缘数据库共用。

## 保存内容

每条记录包含：

- `decisionId`；
- `runId` 与 `stepId`；
- `outcome`、`policyRefs` 与安全审计元数据；
- 决定合同的 SHA-256 摘要；
- SQLite 写入时间。

仓库不接受 Agent 输出、ContextPack、记忆正文、prompt、response 或工具参数。相同决定标识只允许同一运行、同一步骤和相同治理结论重复写入；重试时仅 `decidedAt` 不同会复用首次记录。

## 节点顺序

节点固定按以下顺序处理审计：

1. 计算审计决定；
2. 将决定写入审计仓库；
3. 按 `runId + stepId + decisionId` 重新校验；
4. 才允许写输出引用、记忆或节点提交记录。

恢复时，审核检查点中的 `auditDecisionRef` 会再次读取仓库，校验摘要、运行归属、步骤归属和结果类型。任何缺失、篡改或跨步骤引用都会阻止恢复。

## 审核记忆隔离

- `allow`：按冻结策略立即写正式记忆。
- `deny`：不写输出、记忆或节点提交结果。
- `review`：保存受控 `outputRef` 和待写入策略意图，不写 `memoryRef`。

人工批准时，运行时先验证原审计决定仍为 `review`，再从受控值仓库读取 `outputRef` 并按冻结策略写入记忆。人工拒绝时不执行写入，待写入意图只作为历史审核证据保留在旧检查点中，不能被终态运行继续使用。

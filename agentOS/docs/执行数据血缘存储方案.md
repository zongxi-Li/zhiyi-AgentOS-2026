# 通信血缘持久账本

> 创建（Git）：2026-08-13T22:11:41+08:00，WKN
> 最近一次 Git 修改：2026-08-13T22:11:41+08:00，WKN

## 目标

低熵通信不只需要记录“哪个步骤读了哪个字段”，还需要在进程重启后证明这些记录没有被替换、删除或串入其他运行。

因此每个 ACG 运行使用独立 SQLite 血缘账本。默认文件由 `AGENTOS_PROVENANCE_DB` 指定，未设置时使用 `data/provenance.sqlite3`；它不与 WorkflowStore、checkpoint、输出正文或记忆数据库共用文件。

## 保存内容

账本只保存已经封存的生产、消费和交互事件：

- `runId`、`taskId`、事件标识与顺序；
- 步骤标识、字段名、字段来源、证据引用；
- 内容校验和、Token 统计、合同状态；
- 前序哈希与当前事件哈希。

它不保存 slot 正文、ContextPack 正文、Agent 输出、记忆正文、prompt、response 或工具参数。

## 恢复规则

每次 Runtime 为某个 ACG run 创建节点运行器时，都会：

1. 从 SQLite 读取该 run 的全部血缘事件；
2. 校验每个事件属于相同的 `runId` 和 `taskId`；
3. 依全局序号重放前序哈希与事件哈希；
4. 只有全部通过，才恢复账本并允许继续记账。

任何 JSON 结构损坏、未知事件类型、重复事件标识、跨运行事件或哈希不一致，都会统一抛出 `ProvenanceIntegrityError`。恢复被拒绝，不能继续追加事件。

## 与 Trace 的关系

SQLite 账本是完整性真源；运行 Trace 是面向审计和查询的安全投影。二者都不保存正文。并行步骤仍按生产者或消费者归属领取事件，因此不会因完成顺序不同而把 A 的事件投影给 B。

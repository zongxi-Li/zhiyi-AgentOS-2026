# 统一资源目录设计

> 创建（Git）：2026-08-13T18:03:06+08:00，WKN
> 最近一次 Git 修改：2026-08-13T18:03:06+08:00，WKN

## 目标

建立一个单机、可测试的统一资源目录：将可执行 Agent、模型、Skill 与 Tool 以统一资源
描述登记；按能力、领域、版本、健康状态和运行 scope 识别候选；在 ACG 运行准备阶段冻结
每个 Step 的 Agent 绑定。首期不接入远程节点、供应商 SDK、MCP 会话或消息队列。

## 现有边界

`service/agents/registry.py` 已能按领域、名称和能力解析 Agent，但不保存资源身份、版本、
健康状态或与底层资源的关联。`components/resource/` 已能登记计算资源及负载快照，却不能
登记 Agent、模型、Skill 或 Tool。`contracts/capability.py` 已有 `CapabilityManifest`，但其
三个兼容注册表仍是占位实现。

本设计不替换现有 `AgentRegistry`：它继续保存真正可调用的 `BaseAgent` 实例。新的目录只
保存可审计的资源描述和选择规则，并通过稳定 `agentId` 与 AgentRegistry 关联。

## 架构

新增 `components/resource/directory.py`，提供 `ResourceDirectory`：

```text
BaseAgent + CapabilityManifest + 资源画像
                ↓
        ResourceDirectory.register_agent
                ↓
      资源记录（Agent/Model/Skill/Tool）
                ↓
required capability + domain + scope + health
                ↓
       resolve_agent / resolve_capability
                ↓
冻结到 WorkflowRun.executionState 的 bindings
```

目录中的每一条 Agent 记录必须具有稳定 `agentId`、领域、能力列表、版本、可用状态、可选
`resourceId` 与 labels。模型、Skill、Tool 复用 `CapabilityManifest`，并使用 capability ID
作为唯一身份。重复登记同一身份但 manifest 或 Agent 描述不一致时必须明确失败，禁止静默
覆盖。

## 选择规则

Agent 识别按如下顺序稳定执行：

1. 过滤 disabled、unhealthy 与不在运行 scope 内的记录；
2. 优先精确 `agentName`，再按 `capability` 匹配；
3. 领域优先级为请求 domain，之后才是 `general`；
4. 同优先级候选按 `bindingPriority` 降序、`agentId` 升序确定唯一结果；
5. 没有候选时抛出明确的 `ResourceNotFoundError`，不回退到全局未授权 Agent。

资源健康状态由目录显式维护。首期支持 `healthy` / `unhealthy` 两种状态，默认健康；后续可
由 `ResourceHealthMonitor` 或远程心跳同步，但同步机制不属于本次范围。

## ACG 接线

`WorkflowRuntime.prepare_run` 在 ACG Blueprint 生成和 Agent 校验之后调用目录解析：对每个
Step 生成冻结绑定，保存到 `run.executionState["resourceBindings"]`。执行期的
`_build_acg_runner` 只使用冻结 `agentId` 解析 Agent，不重新进行全局能力匹配。若目录状态
在运行后变化，已准备 run 仍以冻结绑定运行；健康检查只影响新的 run。

这样避免“规划时选择 A、执行时因注册表变化转到 B”的漂移。

## 错误与安全

- 空的资源身份、领域、名称或 capability ID 必须拒绝；
- 同 ID 不同描述必须拒绝；
- unhealthy Agent 不得参与新运行的选择；
- scope 外 Agent 不得通过能力回退选中；
- Step 声明的名称和冻结 Agent ID 不一致时执行前失败；
- 目录只存元数据和实例引用，不存输入输出、模型 prompt 或工具参数。

## 测试

至少覆盖：

1. Agent、模型、Skill、Tool 的成功登记与重复冲突；
2. 精确名称、能力匹配、领域 fallback、优先级与确定性排序；
3. disabled / unhealthy / scope 外资源被排除；
4. Runtime prepare_run 固化 `resourceBindings`；
5. Agent 注册表变化后，执行仍按冻结 ID 调用；
6. 不存在或不健康的绑定在准备阶段明确失败；
7. 全量 pytest、py_compile 与现有导入边界检查。

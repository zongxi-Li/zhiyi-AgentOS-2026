# 本地前导网络与端云拆分推理：结构、攻击面、性能及改进路线

整理日期：2026-11-18。本目录收录 19 篇材料；另交叉使用差分隐私目录中的 SnD 和 DEL，不重复保存 PDF。完整标题、版本、下载来源及阅读深度见 [索引](README.md)。本文的“前导网络”指模型在可信本地执行的前 K 层；任务意图入口另见 [Intent Analyzer 综述](../intent_model/SUMMARY.md)。

## 1. 关键结论

把模型前几层放到本地，可以保留原始 token 的本地入口、控制发送边界并分担计算，但中间表示仍包含输入信息。前导层更深也不保证隐私风险单调降低。项目应把三类目标独立评估：拆分后的数值与会话正确性，真实网络下的延迟与资源收益，明确威胁模型下的隐私性质。

最适合 Kinlin 的近期路线是：保持现有 prefix/suffix 正确性基线，补充公开前段条件下的激活反演测试和真实网络测量；在独立实验中研究压缩、扰动和效用补偿；只有找到明确瓶颈后，再考虑把输出头移回本地、投机解码或结构改造。本文没有执行模型训练或攻击实验，所有外部性能数字均不能当作本项目结果。

## 2. 四种容易混淆的架构

| 架构 | 本地工作 | 云端工作 | 是否每 token 交换 | 与项目关系 |
|---|---|---|---|---|
| 直接端云卸载 | 预处理，或一个完整小模型 | 完整大模型 | 取决于请求与流式返回 | 路由问题，未必切分同一模型 |
| 前段/后段拆分 | embedding 与前 K 层 | 后续层及常见输出头 | 自回归通常需要 | 当前研究基线 |
| 两处切口 | embedding/前段及最终输出处理 | 中间 transformer 块 | 通常需要两向表示交换 | WAN split speculative 等工作的结构 |
| 低秩适配器拆分 | 私有适配器或部分低秩计算 | 共享基础模型与其他计算 | 可能在多个层来回交换 | PrivateLoRA，不等同于连续前 K 层 |

Split **learning** 还会交换训练梯度并更新参数；split **inference** 通常冻结参数。前者面临恶意梯度、标签推断和训练劫持，后者主要关注激活、输出及重复查询。训练防御可以启发推理方案，但必须重新检查适用条件。

## 3. 从早期拆分到大模型系统

[SplitNN for health](1812.00564_Split-Learning-Health.pdf) 展示多种分布式训练构型，不共享原始患者数据；[DDNN](1709.01921_Distributed-DNN-Cloud-Edge.pdf) 把网络分布在终端、边缘和云端，联合考虑局部推理、传感器融合与资源。它们提供架构起点，不能以“不传原始数据”的描述替代正式安全分析。

[Device–Cloud Multi-Modal/Multi-Task/Multi-Turn](2502.11007_Device-Cloud-LLM-Conversations.pdf) 的 TMO 研究在本地小模型与云端大模型之间选择推理位置和模态源，以受约束强化学习优化多轮质量、成本和延迟。它属于卸载/路由的重要参考，但不是把当前 Qwen 模型在某一层切开就能直接复用的算法。

[PrivateLoRA](2311.14030_PrivateLoRA.pdf) 利用低秩残差激活减少端云通信，把私有计算与共享计算分开。论文报告的通信和吞吐收益依赖其结构、模型及网络设置；对现有连续 prefix/suffix 的启发是研究低维瓶颈，而非直接照搬它的百分比。

两篇综述——[split learning 攻防分类](2505.05872_Split-Learning-Attack-Taxonomy.pdf) 与 [LLM split fine-tuning](2604.24468_Split-LLM-Finetuning-Survey.pdf)——适合用于查漏：攻击者能力、共享张量、训练阶段与网络拓扑应该成为实验表格的列，而不是把所有工作放到单一“隐私分数”排序中。

## 4. 为什么激活不能当匿名数据

### 4.1 从向量重建文本到激活匹配

[Text Embeddings Reveal (Almost) As Much As Text](2310.06816_Text-Embedding-Inversion.pdf) 将反演看作受控生成：生成候选文本，重新 embedding，利用与目标向量的差异逐步纠正。论文在其 embedding 模型、数据和攻击训练条件下，报告对 32-token 输入达到 92% 精确恢复。该结果说明向量可包含大量原文信息；它不是对任意模型、任意长度或本项目 Qwen 激活的统一恢复率。

[What Does the Server See?](2605.23158_What-Does-the-Server-See.pdf) 的 ActInv 面向 LLM 中间激活，核心是寻找输入，使本地前段产生的表示匹配所观察激活。方法涉及连续 token embedding 优化和后续恢复，效果依赖能否获取前段模型/权重、辅助信息和攻击预算。论文还研究 PAF 指标及 PriPert 防御；这些经验指标不是标准 `(ε,δ)`-DP 保证。

对于开源模型，攻击者获得前段架构和权重是现实的评估条件。项目不应把“服务端运行时没有装前段”直接解释为“服务端永远无法获取前段”。同时也不应将白盒攻击结论无条件套用到所有黑盒部署；应分别报告。

### 4.2 训练场景的攻击补充

[UnSplit](2108.09033_UnSplit.pdf) 研究训练协议下的数据反演、模型窃取和标签推断；[Unleashing the Tiger](2012.02670_Unleashing-the-Tiger.pdf) 强调恶意服务器可以劫持训练表示空间。这些攻击说明本地模型也可能在协作训练期间被诱导形成易反演表示，不能只检查最终一层的平均重建误差。

[Personalized LLM Inversion](2501.05965_Personalized-LLM-Inversion.pdf) 从信息瓶颈角度分析个性化 LLM 的中间表示并设计攻击。对项目的迁移问题是：如果以后用用户数据训练本地 adapter，既要评估训练样本保护，也要评估推理激活保护，不能把一个评估替代另一个。

### 4.3 传输安全与服务器可见性

认证 HTTPS 或 AES-GCM 保护传输中被旁观、篡改的风险；若云端持有解密密钥并看到明文激活，它仍可分析这些激活。[Efficient and Privacy Aware Edge Cloud](2607.13093_Efficient-Private-Edge-Cloud.pdf) 将认证 KV、量化、投机与端云分工结合，值得研究系统接口，但不能从“加密传输”直接推出“不可信服务器无法反演”。本文只对其摘要和架构主张做初筛，不背书未复现的安全/性能结论。

## 5. 防御路线及迁移成本

| 路线 | 代表工作 | 机制要点 | 应保留的限制 |
|---|---|---|---|
| 训练表示去相关 | [NoPeek](2008.09161_NoPeek.pdf) | 任务损失加输入与表示的 distance correlation 惩罚；本地 burn-in | 主要图像实验；去相关并非自动满足 DP |
| 信息分解 | [InfoDecom](2511.13365_InfoDecom.pdf) | 图像频域分解、信息瓶颈、校准扰动 | 视觉低频结构不能直接类比文本语义 |
| 信息论度量 | [FSInfo](2504.10016_Fisher-Shannon-Leakage.pdf) | Fisher 近似的 Shannon 信息量及防御 | 其度量和理论条件不等同 DP ε |
| 随机发布 | [SnD](../differential_privacy/2310.09130_Split-and-Denoise.pdf)、[DEL](../differential_privacy/2602.11513_DP-Split-Stochastic-Quantization.pdf) | 本地扰动，配合本地去噪或云端 soft prompt | 分清 metric privacy、GDP 与标准邻接；分析整个 transcript |
| 输出语义控制 | [Salted Inference](2310.13384_Salted-Inference.pdf) | 客户端控制输出语义的解释 | 原任务结构与开放文本生成不同 |
| 密文计算 | [CURE](2407.08977_CURE.pdf) | CKKS 支持的 inverted split learning | 主要为训练、标签/可选样本保护；并非即插即用 LLM prefix 协议 |
| 结构等变 | [ConjFormer](2606.16461_Orthogonal-Equivariant-Transformers.pdf) | 正交变换、归一化和权重共轭使旋转域计算可行 | 需改结构及威胁分析；不能只在任意 Qwen 激活上乘随机矩阵 |

### 5.1 NoPeek 和 InfoDecom 的具体启发

NoPeek 在训练时压低原输入与待发送表示的 distance correlation，同时保留任务损失；本地 burn-in 减少早期未训练表示的泄漏。它提示“先学一个有用且少携带无关信息的表示”，但这要求训练和任务分布。对开放式生成，输入的大量细节恰恰是完成任务所需信息，不能假设删除它们没有代价。

InfoDecom 在图像上先做频域分解，去除视觉敏感的低频成分，再通过信息瓶颈约束表示，最后加按 FSInfo 标准校准的噪声。该顺序有价值：先减少冗余，再承担扰动成本。但其“视觉可辨认性”、DCT 频带和相应理论属于具体任务。迁移到文本时应换成明确的任务变量、敏感变量和效用损失；不能把高频/低频的直觉当作文本隐私证明。

### 5.2 CURE 是另一种信任设计

CURE 采用 inverted split learning：服务器持有加密模型参数，对可选加密的数据执行部分训练；客户端保留标签和末端计算，解密输出并返回加密梯度。其 CKKS 机制和打包方案面向密文训练运算，安全依据是相应密码学假设与协议模型。

它与“本地前段、云端后段看明文激活”的方案有实质区别。若未来要求云端不能看到受保护中间量，应比较 HE/MPC/可信执行环境等另一个架构方向，并实测非线性运算、密文精度、通信和资源成本，不能只把 CURE 的加速倍数贴到现有系统。

## 6. 自回归拆分的实现细节

可把目标模型写为 `f = f_suffix ∘ f_prefix`。prefill 时，本地处理一整段 token，传递切口激活；decode 时双方分别维护自己负责层的 KV，逐步传递增量激活。这里最容易出错的不是单个矩阵乘法，而是状态一致性：

- tokenizer、权重 revision、层数、RoPE/position 和归一化必须对应同一个模型制品。
- 本地与云端 KV 分别属于自己的层和会话，不把整份 KV 打包跨边界以“省事”。
- phase、shape、dtype、position、batch、owner 和过期时间均要在执行前校验。
- 前向部分失败后，不能复用已局部推进但没有完整回执的 KV；需要会话失效或可证明的回滚。
- 重试要区分网络包幂等、模型状态幂等与隐私发布幂等，它们不是同一个 nonce 就能全部解决。

这些问题与 DP 正交：协议校验防止状态混用，DP 约束私有输入对外发值的影响。两者都需要，不能互相替代。

## 7. 性能模型：先算 RTT 和字节再调 K

忽略并发重叠时，单步 decode 可近似为：

\[
t_{step}\approx t_{prefix}(K)+t_{suffix}(L-K)
+r\cdot RTT+\frac{B_{up}}{BW_{up}}+\frac{B_{down}}{BW_{down}}+t_{codec}.
\]

`r` 是协议实际需要的往返数。对单切口，prefill 的上传激活量约为 `batch × sequence_length × hidden_size × bytes_per_value`，decode 增量则通常把 sequence_length 换成 1。切分层 K 不一定改变 hidden size，所以增加 K 未必减少上传字节；它增加本地计算与 KV，可能减少云端计算。

移动输出头回本地可改变服务器看到的输出，但也会增加本地权重/计算与下行表示。若传完整词表 logits，成本又与词表规模有关。应按真实协议分别测量，不能用“一次上传 embedding”代表整段生成。

[WAN split speculative](2602.16760_Private-Split-Speculative-Decoding.pdf) 将 embedding 和 unembedding 留本地，把中间层放云端；利用 n-gram lookahead 摊薄高 RTT 下的通信等待。这是两处切口的结构。其 greedy 条件下的 token 一致性不能直接推广到随机采样或加 DP 扰动；后两者需要自己的分布正确性或质量评估。

该论文与 ActInv 对“服务端能否获取 embedding/前段”的设定不同，所以其隐私实验不能视为推翻激活反演风险。研究时应把两篇放在相同模型知识、辅助数据和攻击预算下比较。

## 8. Kinlin 当前状态：已有证据与空缺

核查来源：[safe README](../../apps/agentOS/src/components/safe/README.md) 的带日期进展和对应实验报告。早期“骨架”表与后续实现状态不同，本文以具体新进展和代码为准。

| 项目内容 | 已有证据 | 不能据此推出 |
|---|---|---|
| 真实 prefix/suffix 与 KV | Qwen2.5-0.5B 研究链路，分层 cache 与制品校验 | 所有模型/GPU/精度均正确 |
| 本机配对 | K=2/24、CPU FP32；60 组共 1,146 个生成 token 与完整模型一致 | 已经获得拆分加速 |
| 认证 HTTPS 回环 | 60/60 组、792/792 token 一致及 KV 清理记录 | 公网链路性能、云端不可反演 |
| 当前性能 | 本机首 token/TPOT 耗时比中位数 1.24×/1.40×；回环也较慢 | 任意网络下都没有研究价值，或即将必然加速 |
| 隐私机制 | 全局 L2 裁剪实现；privacy profile 当前保证为 none | 已有 DP、完整预算账本或正式抗反演保证 |

这些为仓库已有报告值，本轮没有重跑或独立复现实验。建议下一轮保留同一配对方法，只增加一个变量，避免同时换模型、硬件、采样器和协议。

## 9. 改进路线及验收方式

### 第一阶段：形成可比较的边界

冻结模型 revision、K、dtype、采样模式、输入长度、输出长度及设备。记录 prefill/decode 上传和下行的实际字节、cache 峰值、codec、网络等待及重试次数。补充真实 RTT、带宽和丢包环境，与完整本地、完整云端及现有拆分三者比较。

定义威胁矩阵：被动/主动服务器，已知/未知前段权重，公开/辅助数据，单次/重复观察。对当前激活先做一个明确的基线攻击；不要为了得到好看的防御分数使用明显弱于白盒条件的攻击而不说明。

### 第二阶段：通信和效用的独立消融

比较 FP32/FP16、确定性量化、低维瓶颈、随机机制，分别记录模型误差和攻击结果。确定性压缩可节省字节，但不自动提供 DP。任何随机机制均按 [差分隐私综述](../differential_privacy/SUMMARY.md) 的完整发布范围核算。效用适配器或 soft prompt 先使用公开/明确授权数据，版本独立于基础模型。

### 第三阶段：由瓶颈决定结构实验

若 RTT 占主导，研究 lookahead/speculative 的批量候选验证；若字节占主导，研究低秩和压缩；若本地内存占主导，重新比较完整小模型路由与切层方案。每个实验先明确是否保留无扰动目标模型的 token/分布等价，还是接受效用下降换隐私与成本。

### 第四阶段：产品接入

Runtime 持有模型、会话、身份、隐私发布及预算权威。Planner 和 Intent Analyzer 只提出任务质量、时限、允许源和候选资源需求。禁止把前导网络“返回一个向量”当作其可以越过工具权限或自动外发的依据。遇到预算不足应按明确策略切换本地能力、减少任务范围或报告不可用，而不是静默关闭隐私。

可用实验矩阵为 `K × 输入长度 × 输出长度 × 网络条件 × 防御`，分阶段选取小网格，避免组合爆炸。主要指标是任务成功/生成质量、TTFT、TPOT、上下行字节、能耗/内存、实体恢复/文本恢复以及声明的 DP 成本。若测得更深 K 只增加成本而没有稳定隐私改善，应保留该负结果，并考虑架构变化而非继续盲目加深。

## 10. 值得进一步验证的研究问题

第一，能否依据任务所需信息学习一个比通用 hidden state 更小的受保护接口，并以标准 DP 而非仅重建指标约束它？第二，如何在自回归本地 KV 继续读取私有上下文时，对整段交互给出实用预算？第三，输出头本地化、低秩接口和投机解码能否在同一模型、网络与攻击条件下形成有收益的组合？

这三项是本文提出的后续假设，不是已验证的创新结论。实验设计应包含负对照、失败案例和效用成本，再决定是否值得扩展为论文或产品方案。

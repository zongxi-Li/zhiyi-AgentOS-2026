# 逻辑审查与实现约束

2026-11-19。审查对象为九张目标架构图。检查覆盖语义一致性、评测设计和发布边界；不构成运行系统的正确性证明。图、图注和本文件共同定义设计含义。

## 1. 当前代码与图的关系

既有实现包括 Run→Trajectory 投影、受限 `registered_validator_insertion` 候选及图演化依赖注入编排。生产图快照验证、真实任务回放与正式图版本发布仍有待接线。`apps/agentOS/src/components/evolution/skill_service.py` 的 `evaluate_trajectory`、`abstract_skill`、`propose_lifecycle_change`、`select_for_task` 仍抛出 `NotImplementedError`。现有 policy 原子发布不能等同于 J1 的完整图/技能清单发布。

因此图中生产权限、不可变制品、独立确认、快照和回滚均为待实现合同，不声称已有完整实现。本次只新增图与文档，不改业务逻辑，不运行或伪造效果实验。代码状态依据与后续路线见[联合计划](../../EVOLUTION_IMPLEMENTATION_PLAN.md)。

## 2. 图的对象、时间尺度与权限

| 对象 | 节点 | 边 | 合法性不能推出的结论 |
|---|---|---|---|
| 执行依赖图 | 执行步骤 | 前置条件、控制/数据依赖 | 无环不能推出副作用安全、无竞争或质量提升 |
| 候选血缘图 | 完整候选版本 | 派生或融合来源 | 血缘融合不能推出执行图可直接合并 |
| 技能关系图 | 精确技能版本 | 依赖、可组合等类型化关系 | 文本相似或关系存在不能授予执行权 |

离线演化修改未来 Run 可采用的版本。任务内恢复只对当前 Run 的受控执行拥有权限。二者可以共享证据，但不能以同一“更新图”接口越权修改活跃 Run。G2 的图仅表示局部补丁，完整快照校验必须覆盖未画出的输入和旁路，防止绕过验证器。

## 3. 证据身份与真实验收

证据按 Run 去重，保存任务族、来源、内容血缘、时间以及 graph/skill/model/tool/policy/retriever/环境版本。轨迹中同一失败的多条日志不能充当多个独立样本。`completed` 只表示执行状态，不能直接充当业务验收。优先采用产物合同、确定性检查及有来源的业务事实；模型 judge 保存版本、原始依据和校准记录。

诊断卡区分假设、支持证据、反例及适用范围。来源文档、日志和技能内容作为数据处理，不提升为系统指令或授权。敏感原文保留在授权存储，包中使用必要引用或经审查的抽象；去标识、摘要或技能化本身不提供差分隐私保证。

## 4. 候选身份与不可变包

候选至少绑定 `target + baseVersion/baseDigest + operator + contentDigest + dependencyDigests + evidenceRefs`。图补丁限制算子和作用范围，第一阶段只开放已注册验证器插入；技能第一阶段只支持 ADD/PATCH。PATCH 是派生新不可变包；MERGE/SPLIT/RETIRE 需额外兼容、影响和稀有能力检查。

包摘要覆盖文档、程序、资源和依赖的规范化清单。评测报告使用包摘要作为被评对象，不把自身再纳入被评摘要形成循环；可将报告摘要作为后续 release manifest 的关联证明。验证后修改内容、程序或依赖，必须重新生成摘要并作废旧报告。报告中的 checksum 不是证明真实性的签名，服务仍需核查可信评价器或签发主体。

## 5. 回放、搜索成本与实验隔离

development、selection、confirmatory 按任务族、内容血缘及时间隔离；不同 ID 不足以排除同题换写和同文档派生泄漏。生成器不能读取确认任务。候选冻结后再使用新鲜确认集；确认结果若回流生成器，该集合即成为开发历史，不能继续充当新鲜确认集。反复查看同一确认集会带来适应性选择偏差，需新的确认数据或明确的统计控制。

回放固定模型、工具、语料/索引、环境、采样配置、重复次数、评分规则和失败处理。外部写入用受控替身或可验证沙盒，记录预期副作用，不能因重放而真实重复下单或写入生产数据。随机模型采用预先约定的重复及成对任务，报告样本量、任务族分层、方差或区间；不能在结果出来后挑选有利 seed。

完整成本包括候选生成、失败候选、验证、搜索、选择/确认评测，以及实际推理、检索、调用、重试和时延。在线收益可单独列出，但不得隐藏离线成本。历史能力用预先声明的 reference 和非劣容忍度检查；观察到有限样本改进不能推出泛化单调上升。

## 6. 技能贡献与联合变化

S3 固定其他条件比较无目标技能、S₀、S₁。资源上限对齐并记录真实消耗，不通过填充无关文本制造表面公平。若需要识别技能注入本身的贡献，采用强制相同检索/注入条件的受控消融；若评价完整使用系统，则将未命中与误用计入，并明确 estimand。两种问题不能混报。

joint 评测使用 G₀S₀、G₁S₀、G₀S₁、G₁S₁ 四格。对于同一可加性标量目标，交互可写为 `Y11 - Y10 - Y01 + Y00`，但其解释依赖随机化、可比性和度量定义；不能机械地用于任意质量/成本复合指标。多技能同现成功不能平均分奖励后声称获得因果贡献。每个报告绑定候选/基线、任务集、评价器、环境及依赖摘要，缺少任一绑定不得发布。

## 7. 召回、注入、调用与核验

S2 的四种事件独立记录：retrieved 表示进入召回结果，injected 表示进入模型上下文，invoked 表示发生实际能力调用或可观测步骤遵循，result_verified 表示任务结果通过定义好的验收。自然语言技能若不能可靠观测“调用”，应记录可支持的证据，不能伪造函数式调用。末端汇总不表示每个候选都会经历全部阶段。

Run 启动时固定 release manifest、技能目录/索引快照、检索器和允许版本集合。运行时按当前任务选择子集，绑定实际使用的精确包摘要；不得读取可变 latest 别名。若显式图节点已绑定技能，检索不能替换为另一个版本。合同、权限和依赖过滤之外，实际工具调用还需主机重新授权，技能文本不能扩大主机能力。

## 8. 生命周期与召回策略

candidate/verified/deprecated/retired 是版本资格，active/dormant 是召回策略。低频不等于低价值，稀有但重要能力需保护集。S4 的回到 candidate 仅派生新版本，不修改旧 verified 包。研究 archive 可保存拒绝和证据不足；正式 registry 只暴露已授权可用版本。verified 字段本身不能绕过发布。

deprecated/retired 影响默认发现或未来采用，不静默重写活跃快照。历史引用应保留以便解释与审计；若有安全撤销或权限变化，独立安全策略可以阻断当前调用并记录原因。可追溯性与继续可执行性是不同保证。

## 9. 状态图的完整解释

G4 为解释性状态图，并非完整接口 schema。正常路径的每条边都有门槛；EVALUATED 表示有结果，结果通过才能进入确认。REJECTED、INCONCLUSIVE、STALE 可在任何适用阶段产生。过期候选若重新绑定基版本或依赖，就需要新候选身份与相应重评，不能把旧报告直接“更新版本号”后发布。

CONFIRMED 到 PUBLISHED 必须核验真实身份、审批策略、内容绑定和预期基版本。调用方提交的 `approved_by` 字符串仅为字段，不等于完成认证。图中省略的失败路径仍需在实现验收中覆盖。

## 10. 清单原子边界与失败语义

J1 的最低一致性方案是先暂存不可变制品，再原子切换一个权威清单指针。制品存储可跨库，图不假设跨库事务。发布门将有效报告与完整制品作为 AND 条件，检查所有图依赖的技能版本、程序与权限是否兼容；联合变化必须有对最终组合的有效证据。

建议发布顺序为：验证提案身份和授权 → 暂存并验证制品摘要/可读性 → 构建新不可变 manifest → 在权威事务中核验预期指针、CAS、记录幂等回执 → 返回结果。事务覆盖范围需实现时明确：若数据库不能同时持久化指针和回执，应使用可恢复日志并证明重试一致性，不能直接宣称 exactly-once。

| 故障 | 需要的行为 |
|---|---|
| 制品暂存失败 | 不切换指针，保留诊断，不发布半套组合 |
| 报告/内容摘要不一致 | 拒绝发布，候选重评 |
| 权限不满足或身份伪造 | 拒绝发布，保留审计 |
| CAS 竞争失败 | 保留当前清单，不部分更新图或技能；提案标记过期或重基并重评 |
| 暂存后、CAS 前崩溃 | 旧清单仍有效；未引用暂存物按保留策略回收 |
| CAS 成功后响应丢失 | 用幂等键查回执，返回同次发布结果 |
| 新 Run 解析引用/摘要失败 | 明确失败或停止启动，不隐式改取 latest |
| 已发布依赖失效 | 阻断不安全调用并诊断；必要时通过新清单修复/回滚 |

清单应固定 graph、skills、model、tools、policy、retriever/index、环境及报告引用的兼容组合。现有 Run 保留旧清单；新 Run 只解析一次有效清单，再按固定引用执行。暂存物回收不能删除被历史清单、Run、审计和保留策略引用的内容。

## 11. 回滚及差分隐私边界

回滚是对当前清单的另一次授权发布，引用经当前兼容校验的已知良好内容并生成新版本；不删除过去记录，不将版本号倒退，不把已运行任务假装成从未执行。图、技能、模型、配置或版本清单回滚都不撤销已发生的隐私消耗。若演化读写敏感证据或发布由私有数据导出的技能，应单独分析差分隐私机制、会计及授权边界；本组图不为这些资产提供 DP 定理。

## 12. 检查结果与尚未验证项

本组执行原生 XML 结构校验、官方 draw.io 引擎渲染、标签边界/重叠、连线穿无关节点检查，以及中英逐图视觉检查。导出检查包括 SVG 无栅格/外部资源、PDF 字体嵌入及文字可选择、字号、画幅比例与 PNG 尺寸。机器结果和文件哈希见 validation.json。几何检查不证明架构语义正确；本文件记录的是设计层审查。

未验证真实发布服务的崩溃与并发、模型随机性下的收益、长期退化、攻击抵抗、DP 保证及具体会议模板符合性。后续实施首先建立真实任务验收与可回放基线，再接通一个图算子、只读技能检索、受控技能补丁和联合清单发布，避免同时扩大搜索空间与发布权限。

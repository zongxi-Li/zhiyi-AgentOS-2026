# 图与 Skills 自进化图组设计

2026-11-19。承接已有三模块架构和联合实现计划，为两个演化方向绘制九张原创方法示意图。中英文各一套，风格与差分隐私图组一致。图不绘制未经测量的效果，不宣称所有候选均提升泛化能力。

| 图 | 单一解释任务 | 图中结构及角色 | 论文位置/对应方法主题 |
|---|---|---|---|
| G1 | 图演化以独立证据和正式发布约束候选 | 主锚点：离线候选闭环；边界：发布权威；反馈：新运行证据 | 主文：Evidence-governed graph evolution |
| G2 | 图补丁必须改变真实执行条件 | 前后两幅执行 DAG；插入验证器与失败分支 | 主文/方法：Typed graph patching |
| G3 | 三类图的节点和边不能混用 | 执行步骤、完整候选版本、技能版本关系三个平行定义面板 | 补充：Graph semantics |
| G4 | 回滚保留历史且仍需授权 | 提案状态、失败决策、新版本回滚三部分，状态机为锚点 | 补充：Proposal and release lifecycle |
| S1 | 抽象候选和正式可用技能之间存在验证链 | 成败证据、结构抽象、ADD/PATCH、校验、确认、注册 | 主文：Evidence-to-skill pipeline |

| S4 | 质量生命周期与召回策略是两个维度 | candidate/verified/deprecated/retired；独立 active/dormant 策略 | 补充：Skill lifecycle governance |
| J1 | 一个清单绑定兼容版本并原子切换 | 两类提案与报告、不可变暂存、CAS 清单、运行快照、回滚 | 主文/系统附录：Coherent graph–skill publication |

图注负责说明条件和术语；图内只保留识别节点、状态及边所必需的文本。统一蓝色执行/证据、青色候选/评测、紫色不可变版本/发布、灰色背景约束、橙色失败/回滚。保留文字和线型以支持灰度阅读。按约 180 mm 通栏导出，标签目标 ≥8 pt；最终投稿仍按具体会议模板核对。

先复用已有架构语义，再生成原生 draw.io；用官方 Graph/mxCodec 引擎渲染，逐图检查中英文，最后检查矢量文本、字体、几何边界与导出完整性。已有设计和用户“继续生成”的指令作为范围依据，不进行额外软件功能实施或 Git 提交。

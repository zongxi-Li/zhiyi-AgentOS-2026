Taxonomy Structure. Figure 3 presents the hierarchical
structure of our taxonomy for skill evolution. The taxon-
omy is organized into four top-level maintenance intents:
Corrective, Adaptive, Perfective, and Preventive Maintenance.
Each motivation is further decomposed into fine-grained why
categories, shown as colored nodes, which are associated with
concrete how operations, shown as white nodes. In this way,
the taxonomy connects the reason for a skill change with the                   Fig. 4: Distribution of Major Skill Components
specific operation through which the change is implemented.
   Corrective Maintenance refers to changes that resolve devia-
tions between a skill’s current behavior and its intended design
goal. Such changes address missing, incorrect, or unstable skill
content, including incomplete functionality, erroneous workflow
steps, inaccurate knowledge descriptions, and underspecified
execution conditions.
   Adaptive Maintenance captures changes motivated by exter-
nal shifts rather than defects in the skill itself. These changes are
needed when the surrounding toolchain, execution environment,
interface, data format, or target task evolves, requiring the skill
to be realigned with its updated usage context.
   Perfective Maintenance describes changes that improve a
skill that is already functional. These changes go beyond
basic correctness by enhancing skill capability, efficiency, and
usability, reflecting developers’ efforts to make skills more
effective in supporting future task execution.                             Fig. 5: Distribution of Fine-Grained Skill Components
